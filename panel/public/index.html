访问与屏幕锁

屏幕锁

首次进入和重新接管需解锁。锁定后已授权的双向映射全部保留，仍可建立新 TCP 连接并按原规则恢复；原任务继续运行。

临时账号

仅可配置“服务器访问本地设备”的映射，以及上传、下载共享中转文件；不能解锁桌面、使用终端或读取其他登录的映射。更新账号会撤销旧临时登录及其映射。

更新临时访问？

旧临时登录及其创建的设备映射会立即失效。管理员的登录、任务和映射保留。

连接时间线

仅本页最近 50 条，不保存 IP、凭据或终端内容；退出后清空。耗时包含网络和服务端处理。

    直连地址提示（可选）

    自动探测继续运行。可填写服务器 IP、浏览器端电脑 IP，或两者都填；留空使用自动发现。支持私有 IPv4、普通公网 IPv6，不含端口。

    地址仅保存到当前浏览器，并随直连协商发送给服务器。修改用于后续探测，已建立的连接继续运行；清空后保存可移除提示。

    TCP 端口映射

    运行 Mac 或 Windows 助手，在本机与服务器之间访问已授权的 TCP 服务。反向模式可让服务器上的 Codex 访问你本地的 SSH、Telnet 等设备；新连接优先直连，不可用时走 WSS 中转。

    请选择运行助手的电脑版本。

    Mac 首次运行：若提示“Apple 无法验证”，进入“系统设置 → 隐私与安全性”，对 codex-cloud-forward 点击“仍要打开”，确认后重新运行 Start.command。完整步骤见下方说明。

    Mac 首次运行 / Apple 无法验证时怎么办

    需要 macOS 12 或更新版本。解压 ZIP，双击 Start.command，在终端窗口粘贴配对码。本版尚未进行 Developer ID 签名及 Apple 公证，首次运行可能出现“Apple 无法验证 codex-cloud-forward”的提示。

    1. 确认下载来源并核对网页显示的 ZIP SHA256，然后尝试打开程序。出现验证提示时，点击“完成”或“取消”。
    2. 进入“系统设置 → 隐私与安全性”，向下滚动到“安全性”，找到刚被阻止的 codex-cloud-forward，点击“仍要打开”，并按系统提示确认。
    3. 重新双击 Start.command。如果提示阻止的是 Start.command，也需对该文件按上述步骤确认。

    没有看到“仍要打开”时，先在解压文件夹中双击 codex-cloud-forward，再返回设置查看。按Apple 官方说明确认此程序即可，无需关闭系统整体安全检查。也可在终端进入该文件夹运行 ./codex-cloud-forward。

    本地助手上的串口

    需要 0.7.0 助手，仅允许一个客户端，使用原始 TCP 接入，无硬件流控。打开串口时 DTR/RTS 可能短暂跳变并使设备复位。配置需由助手明确确认；运行助手 --list-serial 可列出名称。本版串口资料不加入设备目录。

    服务器 IP 默认继承当前浏览器的直连地址提示。浏览器与助手在不同电脑时，可单独填写助手端 IP；仅补充探测地址，不改变设备目标。

    目标从服务器所在网络访问。127.0.0.1 表示服务器自身，也可填写服务器可达的局域网或公网 IPv4 / IPv6。

    本地设备目录

    最多 16 个设备，只保存名称、地址和端口，不保存密码或授权。选择设备后生成配对码，本地助手确认目标后才启用。

    锁屏保留已授权映射。退出创建映射的登录、登录到期或被撤销、明确停止及面板重启会结束映射。20 条上限仅限制助手状态提示次数，不限制连接。

    监听端口仅绑定所在电脑或服务器的 127.0.0.1。刷新、关闭网页或切换模式保留映射。短暂断网后可于 30 秒内恢复授权，原 TCP 连接需由客户端重连，不重发设备命令。停止、退出原登录或授权过期后撤销；网页服务重启后需重新配对。
