# 代码审核记录

2026-11-05，基于 `e2a2730` 及本轮兼容性修改。审核范围包括认证和请求边界、桌面及终端控制、历史/复制、持续会话与换路、WebRTC/ICE/SCTP、端口映射及 Go 助手、原生桌面进程与安装恢复脚本。依赖检查覆盖现有锁定版本；这次审核不构成对任意部署环境的安全保证。

## 已修复

| 级别 | 问题与触发条件 | 修复和验证 |
| --- | --- | --- |
| P2 | 登录状态启动时整文件读取；本地损坏或超大的 JSON 可超出预期资源范围，原实现也会跟随文件符号链接。 | `panel/auth.mjs` 使用文件描述符读取，最多 16 KiB，拒绝符号链接、非普通文件、非当前用户文件；非阻塞打开避免 FIFO 挂住启动。只恢复最近八条格式有效的记录，舍弃未知字段。超大文件、符号链接、目录、FIFO 均有真实临时文件回归。 |
| P2 | 固定登录状态临时路径直接写入；该路径若预先是符号链接，会覆盖链接目标。已在隔离临时目录复现。 | 写入前只清理当前用户拥有的普通旧临时文件，使用 `O_EXCL` / `O_NOFOLLOW` 创建 0600 文件，sync 后原子替换。针对链接目标不变、并发创建/撤销、恢复及权限检查均通过。风险涉及能修改本地状态目录的主体，不是远程认证绕过。 |
| P2 | 桌面/网页终端直连只在完整 DataChannel 消息到达后检查长度，缺少端口映射已有的 SCTP 重组前防护。认证 peer 可以先让协议栈积累碎片或元数据。 | 提取 `panel/rtc-sctp.mjs`，三个直连用途共用接收窗口、最多 32 个流、1,024 个重组碎片、2,048 个乱序记录、1,024 个重复记录的检查；单碎片还受至多 1 MiB 窗口限制。超限或授权失效只关闭相应 peer。已有边界回归及真实 UDP/DTLS/SCTP 传输检查通过。依赖内部接口仍绑定固定 werift 0.26.0，升级时需要复核。 |
| P2 | Firefox 从 iframe 打开移到顶部的历史工具，以及在历史中按 Ctrl+F，焦点会留在 iframe。 | 在所属浏览上下文中设置焦点；首次打开的焦点处理复用单个有界布局回调，关闭/重连取消。三引擎检查普通打开、Ctrl+F、关闭返回及手动复制框焦点。 |

Shift+←、Shift+→ 同时加入原生固定白名单和网页终端编码，使用固定 argv / CSI，保留单次发送、独立粘贴和 Enter。真实隔离 Xvfb/xterm/tmux 捕获的字节与预期一致。

## 已核对的边界

- 浏览器面板的 HTTP 和 WebSocket 均保留登录、Host 和 Origin 检查，写请求保留 CSRF、当前 viewer、异步操作后的控制权复查；没有放宽局域网的授权。
- 面板与 helper 继续回环监听，VNC 仍通过 0600 私有 Unix socket。ICE 接收前保留地址范围、认证 STUN 和队列限制，公网 IPv6 不改变登录要求。
- 连接恢复保持一个上游、有限输出缓存和输入不重放；不通过恢复重新发送提示、确认、按键或旧 TCP 数据。
- 终端使用固定槽位、目标 token 和焦点验证，用户文本不插入 shell 命令。历史按需读取和选区复制各有 64 KiB 上限。
- 端口映射维持四个映射、每映射八条连接、单次配对及有期限的恢复；自定义目标只接受 IP 字面值及端口，不执行用户 shell。
- 应用版本继续精确锁定，未新增应用持久日志、凭据缓存或磁盘队列。会话持久化使用一个 writer 和一个 dirty 标记，避免每次请求新增一个待写 Promise 链。
- 安装与恢复不静默升级应用依赖，也不修改用户 Codex 配置。工作目录、运行文件、浏览器测试环境和产物均在 Git 忽略范围。

## 验证与实际部署

- 156 个脚本语法检查、169 项 Node 测试、10 项 Python 测试通过。
- 49 项三引擎兼容流程和完整 Chromium 浏览器回归 380 项均通过；后者手机、电脑各 190 项。完整记录见 `docs/verification.md`。
- `npm audit` 报告 0 项已知漏洞；Go `test -race`、`vet`、`mod verify` 通过。这些检查不排除尚未公开或未覆盖的问题。
- 隔离 `test:display` 验证真实 X11/PTY、26 种按键编码、中文粘贴和独立 Enter，未启动真实 Codex。
- 隔离 `test:pointer` 验证真实 Xvfb/x11vnc/noVNC 与 UDP/DTLS，换路前后保留同一 VNC、canvas 及按键/拖动释放。
- `test:forward` 使用真实 Linux 同源助手、TLS/WSS/TCP 和 UDP/DTLS/SCTP，覆盖 8 MiB 数据、半关闭、背压、恢复期限、IPv4/IPv6 目标和撤销；桌面管理仍为 fixture。
- 部署检查发现原面板进程已在 23:31:52 被 SIGKILL；恢复面板前后，桌面和 Tunnel 未重启。管理器加载新按键白名单前，将其已有的两个虚拟终端窗口、两个 tmux client 和一个 xclip 进程移入桌面服务控制组后再重启管理器，避免连带结束这些进程。两项持久任务 PID/启动时间、终端目录、登录状态文件和偏好摘要保持一致，实际分辨率保留 1600×2700。公网和回环健康、三项公开资源哈希及三项私有路径未登录 401 检查通过；未新建生产登录或发送测试输入。

## 仍需跟进

1. Android Chrome 真机结果待用户反馈，iOS/iPadOS 尚未真机验收；详见 `docs/compatibility.md`。
2. `test:viewport` 前两次在首次 1280×720 切换时未收到 DesktopSize，加入最多 8,192 字符的 VNC 诊断后完整通过。没有证据确认失败根因，也未因此修改原生分辨率实现；应继续检查 VNC 初始化与首个尺寸变化的竞争，不能把一次通过视为消除间歇失败。
3. 管理器新开的 X 窗口和剪贴板 owner 会继承管理器的 systemd 控制组。实际部署已保护现有进程；后续应将这些桌面子进程的生命周期在启动路径中统一交给桌面服务，避免运维每次迁移。tmux 任务属于桌面服务，本轮两项任务均保留。
4. 面板 SIGKILL 的来源未确认，现有可读日志未提供根因；不要将其归因于兼容性修复或内存不足。服务当前 `Restart=no`，可另行设计只恢复面板的有界重启策略。
5. 跨设备、跨运营商、真实 Windows/Mac 助手和真实 Cloudflare 波动，不能由同一主机的 fixture、协议检查或 Linux WebKit 替代。主机重启后恢复进程与恢复正在运行的内存任务也需要区分。
