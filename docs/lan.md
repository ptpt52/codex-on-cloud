# WebRTC 直连、TURN 与 HTTPS 中转

浏览器始终从配置好的网站入口登录。网络条件允许时，画面、终端及获授权的服务数据使用 WebRTC；直连失败仍可经 HTTPS / WSS 使用工作台。直连无需另外为节点申请本地 HTTPS 证书，也不会改变任务所在的机器。

```text
浏览器 ── HTTPS / WSS ── Cloudflare 入口或自建中心 ── 节点面板
   └──── WebRTC / DTLS：直接连接或经自建 TURN ──────────┘
```

## 当前支持

| 路径 | 条件与用途 |
| --- | --- |
| 私有 IPv4 直连 | 同机回环或局域网可达，双方允许 UDP |
| IPv4 NAT 打洞直连 | 双方可访问 IPv4 STUN，NAT 映射及 UDP 探测允许对端连通 |
| 公网 IPv4 直连 | 公网地址可达，双方 ICE / UDP 探测通过 |
| 公网 IPv6 直连 | 双方具有普通公网 IPv6，路由和防火墙允许 UDP |
| TURN 加密中继 | 已接入[自建中心](selfhost-server.md#turn)的浏览器连接，使用中心签发的短期凭据 |
| HTTPS / WebSocket 中转 | 通过当前网站入口回退；不要求直连成功 |

支持基于 STUN / ICE 的 IPv4 UDP 打洞，不提供 ICE-TCP。公网 IPv4 候选与双向探测成功后，数据可绕过网站中转；对称 NAT、复杂多层 NAT 或 UDP 封锁可能仍需中继。TURN 当前使用中心的固定公网 IPv4；控制连接可走 UDP、TCP 或 TLS，relay 数据仍使用 UDP。端口映射助手有独立的直连实现，目前使用直连或 WSS，不因浏览器获得 TURN 凭据就自动支持 TURN。

STUN 只帮助发现地址，不转发画面；TURN 转发 WebRTC 的 DTLS 密文；WSS 回退使用网站的 HTTPS 链路。三者用途不同。首次打开页面、登录及无现成连接时的协商仍需要网站入口可用，不能把 WebRTC 当作离线登录入口。

## 配置和端口

### 浏览器手动地址提示

打开“连接状态 → 直连地址提示（可选）”，填写服务器 IP、浏览器端 IP，或保持为空使用自动发现。不在同一台电脑运行端口映射助手时，可在映射表单单独设置“助手端 IP”。

地址接受私有 IPv4（含回环）或普通公网 IPv6，不填端口、域名或 URL。提示按当前浏览器的网站源（协议、主机、端口）保存；同源的多个节点共用这份提示。它不写 `.env`，也不替换自动候选或服务器监听地址。

保存后会安排后续探测，不主动断开已可用的连接；清空并保存则恢复自动发现。提示只补充已收集端口上的 ICE 候选，不会配置 NAT、修改防火墙或保证直连成功。

### 服务器部署参数

配置写在节点 `.env`，各项范围与生效服务见[配置参考](deployment-config.md)：

```dotenv
WEBRTC_ENABLED=1
WEBRTC_IPV6=1
# 多网卡时可固定已分配给本机的私有 IPv4；留空自动选择。
# WEBRTC_LAN_ADDRESS=192.168.1.10
# 可固定本机已分配的普通公网 IPv6。
# WEBRTC_IPV6_ADDRESS=你的公网IPv6
WEBRTC_STUN_URL=stun:stun.cloudflare.com:3478
```

`WEBRTC_STUN_URL` 同时用于浏览器、节点和助手发现 NAT 映射，只接受单个 UDP `stun:` 地址，设为空可关闭该配置提供的 STUN 发现。自建中心已经提供自己的 STUN / TURN；可统一设置为 `stun:desk.example.com:3478`，不需要 Cloudflare STUN。不要把 TURN 用户名、密码或 `turn:` URL 填进该项。

修改配置后只重启面板：

```sh
systemctl --user restart codex-cloud-panel.service
```

面板重启保留桌面和终端任务；助手使用原 key 重建已启用规则，旧 TCP 由客户端重连。关闭 WebRTC 时设 `WEBRTC_ENABLED=0`；日常更新使用[维护流程](operations.md)，不要为调网络在活动任务中重装依赖。

### UDP 与中继端口

| 位置 | 端口 | 用途 |
| --- | --- | --- |
| 节点 | UDP 40000–40015 | 桌面 / 网页终端 |
| 节点 | UDP 40016–40047 | 端口映射数据直连 |
| 助手电脑 | UDP 40048–40111 | Windows / Mac 助手直连 |
| 节点 | UDP 40112–40143 | 受限服务及文件直连 |
| 自建中心 | TCP/UDP 3478、TCP 5349、UDP 49160–49223 | STUN、TURN 控制及 relay |

节点只在协商时绑定需要的 ICE socket，不开放公共 TCP VNC。表中是本地绑定范围，NAT 公网映射端口可能不同；正常打洞不要求手工设置路由器端口转发。服务端和路由器必须允许实际需要的 UDP 通信，程序不自动修改防火墙。mDNS 发现可能使用 UDP 5353；STUN 还需访问配置的发现服务。

WSL 镜像网络另需核对 `hostAddressLoopback`，见[WSL 说明](wsl.md)。IPv6 无需 NAT 映射，但仍可能被主机、路由器或运营商阻止。

## 自动切换与恢复

中转连接可先提供画面，后台再探测直连。确认加密通道可用、当前输入与桌面操作空闲后切换；直连失效则恢复可用的中转。隐藏页面会暂停新探测，返回前台或网络变化后重新检查。

新建和切换网页终端尽量复用当前的已认证直连或 WSS；不会为每个后台终端常驻一个查看连接。已有任务、草稿和显示偏好保留，旧目标输出不能进入新终端。

**恢复连接不重发粘贴、Enter、提示词、审批或结果未知的写操作。** “结果未知”时先检查远端实际状态。检测、复核、握手和首屏准备各有期限，不能把某个心跳超时值当成端到端恢复保证。交接协议及精确预算见[连接恢复参考](network-protocol.md)。

端口映射区分管理通道与数据通道；助手整体管理连接断开时仍可保留健康映射；单条映射控制连接进入恢复窗口后暂停新客户端，按原授权恢复。已断开的 TCP 不迁移、不重放，见[映射恢复](forward.md#连接规格与恢复)。

## 查看实际路径

打开“连接状态”，按不同用途分别查看画面 / 终端、输入助手、受限服务、文件和端口映射的路径。某一项已直连不代表其他通道也已直连。

- **WebRTC 路径**：按实际选中的地址族与候选类型区分局域网、IPv6、NAT 打洞、公网 IPv4 直连和 TURN 中继；局域网的对端发现候选不会误标为 NAT；类型不完整时显示“路径待确认”。任一端使用 TURN 就属于中继，仍消耗中继服务器带宽。
- **WebRTC 网络 / 连接端点**：实际选中的 IPv4 / IPv6、协议和地址，并标注主机、NAT 映射或 TURN 中继地址；浏览器隐藏的地址不从其他候选推测。两端都是中心 IP、端口不同可以是正常的 TURN 分配，不能仅凭 IP 判断是否直连。
- **往返时间**：当前路径的应用心跳或 HTTPS 探测耗时，含排队与处理，不是 ICMP ping 或网络丢包率。
- **连接时间线**：当前页面最近 50 条、最多 16 KiB 的阶段摘要，可复制诊断；不包含 IP、SDP、账号、配对码或终端正文。
- **操作与通道提示**：区分连接失败和执行结果未知。收起提示不代表操作成功，也不会解除输入限制或重发操作。

## 常见问题

| 现象 | 检查顺序 |
| --- | --- |
| 网站登录本身失败 | 先检查所选入口、HTTPS、Tunnel / frpc 和工作台账号 |
| WebRTC 协商请求超时 | HTTPS 信令、外层登录或网络请求是否完成 |
| UDP 探测超时 | 双方地址、UDP 路由、防火墙与浏览器本地网络权限 |
| UDP 已接通但加密数据通道超时 | ICE 后的 DTLS / 通道握手；不能仅据此断言防火墙故障 |
| 自建 TURN 不可用 | 中心端口、安全组、节点在线与凭据签发，再做实际 relay 测试 |
| 直连失败但中转正常 | 可继续工作，再按所需网络排查；无需因此重装桌面 |

Mac 上 ping 成功不等于 Chrome 获得本地网络权限。系统授权位置见 [Apple 本地网络说明](https://support.apple.com/zh-hans/guide/mac-help/mchla4f49138/mac)。

## 验证与后续

先验证网站和中转，再分别使用局域网、蜂窝网络和公网 IPv6 检查实际路径、断线恢复及原任务保留。启用自建中心 TURN 时，还需验证其 UDP、TCP、TLS 控制和 relay 数据路径。

自动化中的真实 WebRTC / DTLS / UDP 与模拟 RFB、PTY 上游分开计入验证；它们不能代替另一台设备、运营商或真实手机验收。测试命令与范围见[验证方法](verification.md)，候选、安全边界与恢复协议见[开发参考](network-protocol.md)。
