# IPv4 局域网与公网 IPv6 加密直连

浏览器继续访问 `https://home-codex.x-wrt.dev`。无需另备本地 HTTPS 证书、修改路由器 DNS 或安装客户端 CA：网页和连接协商使用现有 HTTPS 入口，noVNC 的画面与原生键鼠字节通过 WebRTC DataChannel 直连主机。

```text
浏览器 ── HTTPS：登录、协商、管理 API ── Cloudflare / Tunnel ── 面板回环接口
   └──────── 双栈 UDP：ICE + DTLS + SCTP ───────────────┘
                                                       ↓
                                               私有 VNC Unix socket
```

## 当前支持

- 同一台主机、IPv4 局域网及具备公网 IPv6 的两端尝试加密直连；实际可达性取决于网络和防火墙。
- 连接状态窗口的“画面路径”显示实际使用的“WebRTC 加密直连”或“HTTPS / WebSocket 中转”。不是根据地址猜测结果。
- 直连协商最多等待 12 秒，浏览器收集候选最多 1.5 秒；失败或连接断开后回退到既有 WebSocket。中转画面继续显示时，后台持续探测局域网直连；确认可用且输入空闲后自动切换，无需刷新或再次接管。连接恢复只建立新画面，不补发提示词、粘贴、Enter、审批或其他输入。
- 手机从 Wi-Fi 切到蜂窝网络时，前台直连心跳主动检测失效并开始连接中转；切回局域网后持续探测会重新升级直连。实际画面恢复时间仍取决于公网连接。
- 画面、noVNC 原生键鼠，以及输入助手的粘贴、白名单按键和剪贴板读取支持加密直连。“输入助手路径”单独显示实际路径。统一会话直连后，状态轮询、终端目录和网页终端标签切换也使用直连；登录、创建终端、桌面管理及文件 API 仍使用 HTTPS，网页初次打开仍依赖公网入口可达。
- 浏览器默认使用 Cloudflare UDP STUN 发现地址，支持公网 IPv6 host/srflx 候选；双方进行完整 ICE 探测，尝试穿过允许出站流量回复的防火墙。首版不使用 TURN、ICE-TCP 或公网 IPv4 打洞，UDP 无法连通时继续使用现有 WebSocket。

WebRTC 使用标准 DTLS 加密，不另设计密码协议。临时证书不需要浏览器 CA 信任；双方通过已认证 HTTPS 协商证书指纹，再在 DTLS 握手中校验指纹。该安全性仍依赖 HTTPS 页面与协商入口可信。Cloudflare 参与页面、协商和管理 API；直连的画面字节不经过它。[WebRTC Data Channels 标准](https://www.rfc-editor.org/rfc/rfc8831.html)、[WebRTC 浏览器规范](https://www.w3.org/TR/webrtc/)

现有 WebSocket 回退使用原有 HTTPS/WSS 链路，不等同于 WebRTC 两端之间的 DTLS 加密。后续接入 TURN 后，TURN 可转发 DTLS 密文；当前未部署 TURN。

## 配置和端口

受限服务的浏览器直连独立使用服务端 UDP 40112–40143，不需要桌面控制权。它与桌面、终端及端口映射使用独立 peer；网络或防火墙未允许这些 UDP 通信时保留 HTTPS。程序不会自动修改防火墙。权限、并发和撤销规则见[临时访问](access.md#临时账号)。

### 浏览器手动地址提示

打开“连接状态 → 直连地址提示（可选）”，可填写服务器 IP、浏览器端电脑 IP，或同时填写。两项默认留空，自动发现与协商不依赖它们。保存会提前安排一次后续探测；自动候选全部保留，错误或不可达的提示不会替换原来的地址。清空并保存后恢复只使用自动发现。

每个地址限 45 字符，接受私有 IPv4（包括同机回环）和普通公网 IPv6，不接受端口、域名、URL、公网 IPv4 或特殊 IPv6。配置以当前节点 origin 隔离，保存到当前浏览器的 `codex-cloud.rtc-hints.v1`，单条最多 256 字符；存储失败时仅当前页面生效。它们随每次已认证 HTTPS 直连协商发给服务端，不写入 `.env`、日志或服务器持久化配置。

服务端用浏览器端 IP 为本轮 offer 补充目标候选，用服务器 IP 为 answer 补充目标候选。每侧最多新增 4 个去重 UDP 候选，沿用同地址族已经收集的端口和本次 ICE 凭据，优先级低于通常的 host 候选；原有最多 8 个自动候选保留。mDNS 隐藏地址族时，可用有效的 IPv4 / IPv6 提示尝试其已收集的 host 端口。IPv6 提示只在服务端已启用相应能力时使用；没有相应 host 端口时不猜测端口，不将明确的 IPv4 / IPv6 候选跨族拼接。服务端仍按原来的规则选择并绑定本机地址，不把提示用作监听地址，也不要求服务器提示属于本机网卡，因此有转发路径的别名也能尝试。

这些提示可帮助绕过跨网段 mDNS 不可达或补充已知地址；目标仍需将同一个 UDP 端口送到实际的 ICE socket。提示不会自动配置 NAT、改写端口映射、增加监听网卡或开放防火墙，不能保证仅靠 ping 可达就能直连。

每轮协商使用开始时的提示快照，保存新值不会修改进行中的 ICE 协商，也不会主动断开已经可用的直连。新值在后续探测、重连或刷新时使用。实际网络地址失效后仍沿用心跳检测、中转回退与后续探测，保留原终端、草稿和不重发输入的规则。

### 服务器部署参数

默认启用，可在 `.env` 中关闭或明确指定本机接口：

```dotenv
WEBRTC_ENABLED=1
# 可选；不填时优先选择默认路由网卡上的私有 IPv4，找不到则按网卡顺序选择。
WEBRTC_LAN_ADDRESS=192.168.16.224
WEBRTC_IPV6=1
# 可选：固定本机已分配的普通公网 IPv6。
# WEBRTC_IPV6_ADDRESS=你的公网IPv6
WEBRTC_STUN_URL=stun:stun.cloudflare.com:3478
# 可设为空字符串关闭 STUN；只支持单个 UDP stun: URL。
```

多网卡、VPN 或容器网桥环境可以明确指定 LAN 地址；必须是本机已分配的 RFC 1918 私有 IPv4 或回环地址。不指定时，每次协商重新选择当前接口，以适应 DHCP 地址变化。Linux 优先从有效默认路由中按 metric 选择有私有 IPv4 的网卡；默认路由不可读或无可用接口时，回退到网卡顺序，最后使用回环。明确指定后则需手动更新配置并重启面板，建议在路由器预留地址。主机本身的浏览器也可连接该 LAN 地址。

Windows 本机浏览器连接 WSL 镜像网络是一个例外：通过宿主机局域网 IPv4 访问 WSL 需要 `.wslconfig` 的 `[experimental] hostAddressLoopback=true`，否则可能回环 UDP 正常、局域网 IP 的 UDP 超时。部署会识别并自动补齐该项、保留备份，配置需重启 WSL 后生效；只读检查和排障步骤见 [WSL 部署说明](wsl.md)。

WebRTC 仅在协商时绑定所选 IPv4/IPv6 地址的 **UDP 40000–40015**，每个 peer 至多两个 host socket，不监听公共 TCP VNC 端口。公网 IPv6 需要主机和路由器允许相应 UDP 入站，或允许 ICE 双向出站探测建立回复状态；本项目不自动修改防火墙。IPv6 不需要 NAT 端口映射，但仍可能被运营商或防火墙阻止。浏览器 mDNS 解析可能使用 UDP 5353，STUN 发现需要访问所配置的 UDP 服务。面板和 helper 仍仅监听回环，VNC 仍为私有 Unix socket，Tunnel 的 IPv6 优先策略保持原状。

IPv6 默认优先选择与 LAN IPv4 同一网卡上的一个公网地址，没有可用地址时保留 IPv4；未固定地址时每次协商重新选择。`WEBRTC_IPV6=0` 关闭公网 IPv6。普通公网 IPv6 限于 2000::/3，并排除文档、6to4、2001::/23 等特殊范围；ULA、链路本地、scope ID、映射地址和组播不作为公网候选。固定地址必须已分配给本机，地址变化后需更新配置并重启面板。

STUN 只发现地址，不转发桌面数据；默认服务为 Cloudflare 的 `stun:stun.cloudflare.com:3478`，配置不接受 TURN、凭据或查询参数。服务端已知自身绑定地址，不使用外部 STUN；显式清除固定依赖在空 iceServers 时隐式选用的默认 STUN。浏览器地址发现超时后仍使用已收集的 host 候选，不阻塞现有 LAN 连接。[Cloudflare STUN 文档](https://developers.cloudflare.com/realtime/sfu/get-started/connection-patterns/)

运行 `npm ci` 安装锁定的 `werift@0.26.0`，再只重启面板：

```bash
systemctl --user restart codex-cloud-panel.service
```

关闭直连时设置 `WEBRTC_ENABLED=0` 并重启面板。桌面、tmux 和 Codex 会话独立运行。

## 认证与资源界限

协商接口要求有效登录、Host、Origin、CSRF 及当前页面控制权。延迟请求体、协商过程中发生接管或退出均不能获得旧控制权。WebRTC 与 WebSocket 共用单一画面连接、退出、登录到期、接管和桌面维护的关闭机制；数据转发前再次检查授权，不将 Cookie 或 CSRF 发给 VNC。

只接受一个 data m-section、有 SHA-256 指纹的 SDP；请求体最多 48 KiB，输入 SDP 最多 32 KiB，最多保留 8 个去重自动 UDP 候选，两族均存在时各预留 4 个；可选地址提示另补最多 4 个候选，浏览器目标合计最多 12 个。允许私有 IPv4/mDNS host，以及启用 IPv6 时的普通公网 IPv6 host/srflx；去除 remote-candidates。候选配对及实际探测来源再次过滤，拒绝公网 IPv4、特殊 IPv6 和 relay。桌面连接只允许各一个可靠、有序的 `codex-vnc`、`codex-control` 和 `codex-health` 数据通道；文字终端连接用独立的 `codex-terminal` 取代 VNC，不接受媒体或任意代理目标。兼容没有心跳通道的旧桌面客户端，主动心跳需刷新页面加载新版本。

公网 UDP 接收入口在固定版本 ICE agent 处理消息前验证会话、原始 STUN HMAC 与双方 ufrag，拒绝无凭据探测和未知端点的数据。每个 peer 的检查限制为每秒窗口 64 次、STUN 报文 2 KiB、最多 16 个已认证来源及 16 条 early checks；不写入日志或磁盘。

浏览器隐藏的 `.local` 候选通过所选 LAN IPv4 接口进行 mDNS 查询。每个桌面/网页终端 peer 最多一个按需创建的 UDP 5353 socket、8 个名称；每个名称最多查询两次，保留原有的 10 秒解析期限，允许 mDNS 不可达时浏览器主动发起已认证 ICE 探测。解析在回复的前 64 条 answer/additional 记录中查找匹配名称，优先取有效私有 IPv4，开启 IPv6 时也接受普通公网 IPv6；忽略无关名称、过期/goodbye 记录及不允许的地址。连接关闭立即取消等待并释放 socket，没有磁盘缓存。直接使用已锁定的 `multicast-dns@7.2.5`，不修改 werift 安装文件。

控制通道分派 `paste`、`key`、`clipboard` 三种固定业务动作，以及仅用于连接探测和启用的 `ping`、`activate`，每次处理前校验会话和页面认领对象，读取返回前再次校验。沿用私有管理 socket、输入互斥锁、文字 32 KiB 上限、固定快捷键及独立 Enter。请求 ID 单调递增，重复、并发或无权限的消息关闭控制通道，不重复执行。控制请求发出后，即使断线、超时或页面切换，也不会换成 HTTP 重发；后续新的明确操作才可使用 HTTP 回退。

控制 JSON 记录最多 256 KiB，按最多 16 KiB 二进制消息分块，单个长度前缀限定接收缓冲；每端仅一个待完成请求，发送缓冲上限 512 KiB，客户端等待最多 8 秒。取消读取会关闭控制通道并丢弃迟到结果；观看连接仍可继续，后续操作可走 HTTPS。iframe 消息同时验证来源、父窗口、页面代次及请求 ID；正文只暂存在请求和预览中，不写入浏览器存储或服务日志。

心跳使用 `codex-health-v1` 协议，只回显 4 字节大端单调 nonce（1–2147483647），不接受业务动作。每次验证原有会话、页面认领及连接对象；无权限、重复/无效 nonce、错误长度或每秒窗口超过 8 次均关闭连接。发送缓冲上限 4 KiB，每端最多一个待完成检查，无队列或历史。心跳与正在进行的粘贴/按键互不占用请求槽；取消旧检查后，迟到回复被忽略，不能满足下一次检查。

每次仅一项协商，最多一个活动 peer 与一个候选 peer。候选等待激活最多 26 秒；候选不连接 VNC，也不能执行输入或读取剪贴板。通过加密控制通道确认并启用时，先关闭旧观看连接，再允许新 VNC 连接；启用后连接 VNC 最多等待 5 秒。活动连接受登录有效期约束。消息最多 64 KiB，画面切为 16 KiB 消息，应用发送高水位 256 KiB，暂停读取上游形成背压；终端方向超过 256 KiB 就关闭连接，不排队重试。没有新增持久化证书、SDP、候选缓存、终端内容或连接日志。

新画面通道使用 `rfb-ready-v1`：noVNC 挂好事件处理器、通道打开后，客户端只发送一次固定的单字节 `0`。服务端消费该字节，且确认候选已启用、画面通道已打开后才连接 VNC；就绪字节不转发给桌面，格式错误则关闭连接。这样避免 VNC 首包早于浏览器 open 通知而造成初始化失败。它沿用原来的 5 秒启用期限，不增加缓冲或重试。旧 `rfb` 协议保持兼容，刷新后才使用新握手。

## 持续探测与自动切换

统一会话模式下，中转与直连并行建立，保留同一上游与渲染器。新客户端通过候选直连发送带连接代次、输出位置和已确认输入序号的 `prepare`，由服务器暂停旧通道输出，再经同一直连提交 `activate`；不等待慢中转的确认。暂停租约最多 2.5 秒、每会话仅一个，取消、超时、候选断开或撤权即释放。代次切换后，旧通道迟到的数据不能执行输入；新通道只补发未确认的输出，不重发输入。提交前失败保留可用旧连接，提交结果未知时重新核对流状态。旧服务器未声明支持时保留原交接方式。

中转建立后首次等待 15 秒探测；失败后按 30、60 秒退避，随后持续每 60 秒检查。一次只运行一个探测，没有队列。网络恢复、浏览器连接类型变化或页面重新可见时，会将下一次检查提前到约 1 秒；正在进行的探测仍保持单一。隐藏页面或离线时暂停新探测，恢复可见后继续。直连画面正常但控制通道已关闭时，也可用同一机制修复输入助手路径。

候选建立加密控制和只读心跳通道，尚不建立画面通道；完成两次控制 `ping`、间隔 500 毫秒，证明实际 DTLS 通道可用。探测失败不关闭旧 WebSocket，也不创建额外 x11vnc 观看进程。准备切换时，等待输入、剪贴板读取和桌面操作空闲，且没有按住键或指针；原生交互结束后至少空闲 800 毫秒。剪贴板预览窗口打开时也会延后。

父页面确认空闲后，短暂暂停新输入，再请求服务端启用候选。服务端重新检查会话、控制权与管理服务状态，确认空闲后才接替旧画面。新画面仍使用原分辨率、缩放、拖动与折叠设置，并恢复本地滚动位置；父页面和输入草稿保留。候选失败继续原路径；如果旧路径已经关闭，则重新连接画面。自动切换不发送登录、接管、粘贴、Enter 或审批，也不重发结果未知的操作。

切换确认最多等待 2 秒，父页面的输入暂停保护最多 15 秒。任何接管、退出、登录到期或桌面维护都会关闭候选；过期协商不能替换新页面的连接。这里只切换画面和控制通道，不重启 Xvfb、tmux、Codex 或 Tunnel。

## 直连失效后的快速回退

前台、在线且画面已连接时，独立心跳每 3 秒检查一次，每次最多等待 2 秒。即使浏览器仍将 WebRTC 标为 connected，静默断连也可在约 5 秒内被发现并开始建立 WSS。收到 `online`、网络类型变化或页面重新可见事件后，约 250 毫秒提前进行一次新检查，无回复约 2 秒后开始回退；浏览器主动报告直连断开则立即尝试中转。这是开始回退的时间预算，公网请求和 RFB 握手仍会影响最终画面恢复时间；后台定时器限制也可能延长检测。

隐藏或离线时暂停并取消在途心跳，不因该状态本身关闭现有直连流。恢复前台/在线后用新 nonce 检查，旧网络的迟到包不能通过新检查。多个事件只保留一个检查定时器；新的网络检查开始后，后续 RTT/带宽估计等事件不再取消或延后本次检查的期限。退出、接管、卸载或连接换代取消旧检查。中转连接也在可见且在线时恢复，不累计离线重试。

失效回退会明确将正在等待的输入标为结果未知，随后只重建观看流；不等待输入结束，也不再次提交已发送的业务操作。保留草稿、缩放与本地滚动位置，原桌面任务继续运行。中转建立后仍按上述策略检查并恢复 LAN，不增加新的中转服务。

## 已直连时的状态与终端切换

统一会话模式的已激活直连可查询面板状态和终端目录。它们使用现有 DTLS 数据流中的固定消息，不是任意 HTTP 代理；仍按最初通过 Host、Origin、CSRF 和登录验证的页面身份，在每次处理前后复核当前控制权。只允许活动直连查询，候选和备用中转不能借此读取信息；锁屏、退出、登录到期或接管使旧通道失效。

每条活动路径最多并行两项只读查询（状态、终端目录各一项），每秒最多八次，单响应最多 16 KiB。浏览器每项最多等待五秒，迟到结果按请求 ID 与连接代次丢弃，不占用粘贴/按键的请求槽。连接状态中的面板路径显示“可访问（加密直连）”；HTTPS 查询失败不会覆盖这条已验证的直连状态。文件、账号/锁配置、创建/重命名终端及端口映射管理仍使用 HTTPS。

网页终端标签切换优先复用当前 iframe、WebRTC peer 和统一会话，不重新下载界面或通过 CF 协商。服务器校验目标槽位和 pane token、确认输入已结束，再结束旧查看连接并附加新目标；原 tmux/Codex 任务继续运行。旧查看器的迟到输出不能进入新终端，旧的终端心跳和历史读取随切换释放，草稿继续按终端身份隔离。备用中转按新目标在后台重建。

切换每会话最多一项，确认最多八秒；输入未确认、目标身份变化或服务繁忙时保留旧目标，不排队稍后再切。结果未知时停止当前查看并要求重新选择，不自动重发切换或输入。旧服务端没有声明此能力时，仍使用原界面重连方式。

首次直连复用当前登录页取得的 WebRTC 配置与 CSRF，配置只在内存中保留，退出后清除；没有有效配置时才补取认证信息。地址收集最多等待 1.5 秒，创建/收集阶段另有三秒保护；HTTPS 信令和 ICE/DTLS 建连分别有十二秒期限，不再共用一个总期限。服务端候选等待激活最多 26 秒、激活后的画面就绪最多五秒；统一终端首次附加最多 45 秒，可用中转仍先显示。首次加载、登录及没有现成直连时的信令仍需要 HTTPS，未增加新的直达网站入口。

## 中转模式下的终端切换

统一会话的活动 WSS 连接也支持切换已有网页终端。页面保留同一个 iframe 和 WebSocket，经当前已认证连接发送一次固定目标切换消息；服务端沿用槽位、pane token、当前控制权和输入空闲检查，仅更换查看目标，不重启 tmux/Codex 任务。原 Host、Origin、Cookie 和 CSRF 认证不变，候选和备用路径不能切换目标。新能力单独声明，旧服务端未声明时沿用原页面重连方式。

切换沿用最多一项、确认八秒、结果未知需手动选择的限制；草稿按终端身份保留，旧输出、历史读取和终端心跳释放，输入不自动重发。已确认目标在当前会话内保留，WSS 短暂断线后附加同一目标；网页刷新后仍重新校验保存的目标身份。此功能不增加后台终端的常驻查看连接，也不缓存各终端最后画面。

切换前取消针对旧目标的直连探测，切换结束后继续按当前目标探测；主动取消不增加探测退避。服务端对尚未附加统一会话的 RTC 候选复核目标身份，拒绝旧探测的迟到启用。后续可升级直连，直连失效仍可回到保留的中转连接。中转下状态和终端目录查询继续使用 HTTPS；新画面到达时间仍取决于 CF 链路。

## 查看实际路径

统一桌面/网页终端在网络变化或返回前台后优先安排直连重探，不再让普通切换的 30 秒冷却阻挡本轮网络验证。网络触发的新探测每五秒至多开始一轮，进行中的协商不取消；事件风暴不会反复推迟已安排的探测。新候选仍需完成两次可用性确认、稳定等待和输入空闲检查，已有备用候选先取得新心跳回复后才获得提前切换资格。正常自动切换仍保留原冷却；隐藏、离线及终端目标变化清除尚未使用的提前探测意图，不重发输入。

“连接状态 → 连接时间线”记录中转建连/认证、直连地址收集、协商请求、加密通道建立、首屏准备、通道启用/失效、重试与排队情况。耗时包含网络、服务端及界面准备；桌面首屏准备包含原有 VNC 启动稳定等待。每页只保留最近 50 条且序列化不超过 16 KiB，只在内存保存，退出或重新登录清空；不包含终端正文、IP、SDP、Cookie、配对码或账号信息。待命侧与临时账号的独立服务连接单独标识。“复制诊断”仅复制这份有界摘要，剪贴板不可用时提供只读文字框；关闭界面不会创建日志文件。

Windows 端口映射助手也支持这套 IPv4/IPv6 直连策略，但具有独立的授权和 peer，页面接管不结束其连接。转发 peer 的服务端 UDP 范围为 40016–40047，助手为 40048–40111，不占用桌面/网页终端的 40000–40015。新 TCP 连接按可用通道选择，已有连接不迁移；管理与协商仍经 WSS，行为和资源上限见[端口映射助手](forward.md)。

连接状态中的“直连网络”显示实际选中 candidate pair 的 IPv4/IPv6 和 UDP，“直连两端”显示地址及端口。浏览器隐藏的地址明确标为隐藏，不从其他候选推测。路径在连接和成功心跳后更新，最多一个在途 stats 请求；换流、断线或接管丢弃旧详情。不记录 SDP、候选历史或地址日志。“直连检测”显示最近一次协商、心跳或连接失败，不将所有失败都断言为防火墙阻断。

“往返时间”同时适用于直连和中转：统一桌面/网页终端复用当前活动 WebRTC 或 WebSocket 的应用心跳；旧版网页终端复用终端心跳；临时账号、锁屏或被接管页面使用独立服务直连心跳，尚未直连时测量同源 HTTPS `/healthz` 请求。旧版桌面中转也使用该 HTTPS 探测，提示文字会说明测量方式。心跳在前台约每三秒更新；HTTPS 探测约每四秒、最多一项在途、六秒超时。每条网络路径只保留一个内存样本，十秒过期；切换后读取新路径自己的样本，断线、退出、隐藏时清除或停止显示旧值，初次测量显示“检测中…”。显示值是浏览器与面板之间的应用往返时间，包含通道排队与处理耗时，不是 ICMP ping，也不再混用 ICE RTT。测量不发送终端输入、不增加映射连接，也不触发桌面接管。

超时进一步区分为“直连协商请求超时”（HTTPS 请求未完成）、“直连 UDP 探测超时”（尚未建立 ICE 路径）和“直连 UDP 已接通，加密数据通道建立超时”。这些阶段提示不能单独证明是防火墙或 mDNS 故障。Mac 终端 ping 成功也不能验证 Chrome 的本地网络授权；可检查“系统设置 → 隐私与安全性 → 本地网络 → Google Chrome”的开关。[Apple：在 Mac 上控制对本地网络的访问](https://support.apple.com/zh-hans/guide/mac-help/mchla4f49138/mac)

## 验证与后续

网页终端也使用同一套 IPv4/IPv6 候选、HTTPS 指纹认证与 DTLS 加密。`/api/terminal/rtc` 必须携带当前终端槽和 pane ID / PID token，并在启用时重新校验；专用 `codex-terminal` / `terminal-v1` 通道传输原有终端 JSON，记录最多 256 KiB、按 16 KiB 分块，沿用 PTY 背压、固定按键、保护粘贴与独立 Enter。该连接的控制通道只接受 `ping` 和 `activate`，不执行桌面输入；探测及未启用通道不附加 PTY。浏览器安装收包器并发送固定单字节 `0`、服务端确认启用后，才连接原有 tmux 任务。

文字终端直连失败回退现有 WSS，中转期间按 15/30/60 秒持续探测，网络变化后约 1 秒提前探测。切换前还需结束中文组合输入、释放按键和指针、最近 800 毫秒没有交互，且父页面没有输入、确认框或其他阻塞操作；服务端也要求旧终端在途请求已清空。启用失败保留仍可用的旧流，失效输入标为未知且不补发。前台应用心跳继续按 3 秒间隔、2 秒期限检查；隐藏时暂停，离线主动释放附加客户端，上线后先恢复 WSS 再探测直连，原 tmux 任务保持运行。连接诊断同时显示文字终端实际路径、延迟与回退原因。

自动化测试使用真实 Chrome、noVNC、WebRTC、DTLS 和 UDP，桌面源为模拟 RFB；检查加密状态、无需 WebSocket 的画面、接管、草稿保留和故障回退。Node 测试覆盖协商认证、延迟请求、候选与大小限制。这些测试不能代替另一台 LAN 设备的验收。

实际验收时，手机与主机连接同一局域网，打开原来的 HTTPS 域名，查看“连接状态 → 画面路径”。再关闭 Wi-Fi，使用蜂窝网络查看是否出现 IPv6 / UDP 和实际选中地址；UDP 不可达时确认能回退至中转，恢复后再次切回直连。不要把 HTTPS 首次请求时间当作画面交互延迟。

后续可接入有独立凭据与配额的 TURN，提供跨网加密中转；若需要断网时完整访问网页和所有 API，仍需另行部署浏览器可信的 LAN HTTPS 入口及单域名 DNS 覆盖。后者可用 ACME DNS-01 签发，无需开放公网网站端口。[Let's Encrypt DNS-01](https://letsencrypt.org/docs/challenge-types/#dns-01-challenge)
