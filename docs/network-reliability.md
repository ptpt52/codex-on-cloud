# 网络可靠性审核与统一设计

本次审核覆盖网页终端与桌面的统一 RTC/WSS 流、旧版查看器、独立服务 RTC、HTTPS/RTC 文件传输、原生 TCP/串口助手、共享转发池、节点网关和自建中心。以操作能否确认、连接是否仍有有效进展、队列是否有界为依据；不把 `connected` 或 LAN 标签当作吞吐保证。

## 审核发现与修改

| 优先级 | 触发条件与原有问题 | 修改与回归证据 |
| --- | --- | --- |
| P1 | 中心响应持续少量回包，socket 空闲超时一直不触发 | `centerRequest` 增加覆盖连接、TLS、响应头和响应体的总期限；真实 HTTP 慢速回包测试 |
| P2 | 本机 helper 请求带调用方 signal 时，原有 6 秒限制被替换 | 合并取消信号和本地期限，两者任一触发即结束等待 |
| P1 | 网关重新构造 Request 时丢失取消信号，控制或路由等待缺少完整期限 | 逐跳传递 signal；路由总计 4 秒、控制转发总计 10 秒，覆盖响应体；已取消的请求不发往节点 |
| P1 | 服务 RTC 在后台或离线期间仍等心跳，旧异步结果可能影响恢复后的检查 | 暂停并取消心跳，按连接代次和检查代次丢弃旧结果；恢复后新 nonce；浏览器后台/离线故障注入 |
| P1 | 浏览器报告 offline 时，统一流和旧版终端主动销毁仍可用的 LAN peer | 暂停检查和输入准入，保留已就绪路径；真实关闭/ICE 失败仍回退；实际浏览器 RTC 测试 |
| P1 | Go 助手关闭时仍保留接收队列，ReadMessage 的 select 可选中旧数据 | 入队、关闭和出队复核使用同一互斥边界；关闭清空队列，迟到回调不得再次入队；并发竞态测试 |
| P2 | Go 写入先等窗口再等共享 credit，各阶段重新获得 15 秒；已过期 credit 偶尔仍被授予 | 一次写入共享绝对期限；过期准入失败且释放已授予额度；虚拟时钟验证 8 秒窗口等待后仍在总计 15 秒结束 |
| P1 | PTY 已短写部分输入后目标失效，却返回 rejected；终端桥也丢失 helper 的 outcome | 部分写入报告 unknown，桥只接受明确 rejected；隔离 tmux/PTY 强制短写和撤权验证 |
| P1 | 旧管理器或桌面执行 helper 返回缺少 outcome 的 5xx，已派发操作被上层误判为未执行 | 两层 Unix socket 客户端都将已发送的写请求按 unknown 处理；只读请求和明确拒绝保持 rejected；确认没有自动重发 |
| P1 | 中心或网关事务提交后异常，通用错误处理仍报告 rejected | 非预期写操作异常报告 unknown；提交后丢失确认的故障注入证明状态只修改一次 |

P1 表示可能误断有效连接、误报业务结果或越过关闭边界；P2 表示期限和资源释放不一致。这些等级不表示已发现外部攻击或生产数据损坏。

后续复核补齐以下边界：服务 RPC 取消后排空迟到回复，不因本地取消关闭共享文件连接；服务提升前允许取消，提升提交后由原有八秒 RPC 期限约束并完成接管，显式停止仍立即关闭候选；文件 HTTP 的明确结果逐层保留，通道可恢复性独立表达，繁忙拒绝不重放上传；助手只在已验证连接稳定三十秒后重置退避，并加入不超过十五秒的抖动。RTC writer 在原生通道离开 open 时丢弃待发队列、结束回调，保留原生缓冲计费直到 closed，避免空调度。

浏览器回归另覆盖实际 HTTP/DTLS 下的迟到查询与并行文件传输，以及服务端已关闭旧 peer、客户端尚未接收提升确认时隐藏页面；真实 DTLS 测试同时覆盖 HTTP 并发门限返回 503 后在原服务连接上手动重试。[文件传输性能基线](file-performance.md)提供独立可运行的测量，明确区分注入的应用层延迟与真实网络条件。

## 统一约束

### 活性与页面生命周期

浏览器的在线提示只控制是否发起探测和新操作，不能证明所有 LAN/VPN 路径已断开。隐藏或离线时取消在途心跳、停止累计重试；返回后重新探测。原生通道关闭、ICE 失败和有界健康检查失败仍可使路径退役。

手动直连重测也遵守同一生命周期：统一流、旧版终端和桌面在隐藏或离线时取消尚未接管的候选，立即结束等待并保留原有可用连接。已经提交的接管沿用自身有界确认与清理，不重发输入或重新创建桌面进程。

旧版终端和桌面的手动重测在派发 `activate` 前进入提交阶段，之后隐藏、离线及短暂的可见性变化都不丢弃候选，由原有八秒 RPC 期限约束确认与接管。明确的服务端拒绝保留原路径，丢失确认进入正常恢复；退出页面仍强制取消，迟到确认不能重新安装连接。回归覆盖真实 HTTP/DTLS 下旧连接已被关闭、应用尚未处理激活确认的交叉时序。

自动路径切换在父页面许可、排空和服务端准备确认期间使用同一个取消范围。隐藏或离线会取消尚未派发的切换，即使随后立即恢复可见，也不能继续旧切换；准备租约随清理释放。`activate` 发出后按既有 2.5 秒期限等待结果，后台期间到达的确认保留，但新输入等待前台的新心跳。

每个检查同时绑定登录/连接代次、peer 身份和检查代次。取消后的成功、失败和 finally 都不得修改新的检查状态。健康回复只接受当前 nonce；旧回复、出站缓冲量和静止队列不能证明活性。

独立文件服务沿用已有规则：最近 6 秒内有效文件数据或 ACK 可以证明共享 SCTP association 仍在工作；停滞后恢复普通心跳。统一流和助手沿用已有的一次有界拥塞宽限，不无限延长失联检测。RTC stats 已有 1 秒读取上限，继续保留，不为可选统计增加重连条件。

### 总期限、空闲期限与取消

同一个控制操作使用同一个绝对期限，连接、排队、共享额度、发送和读取响应不得重新计时。空闲期限可更短，但持续少量数据不能延长总期限。调用方取消必须向下游传递，不能替换内部资源上限。

| 边界 | 期限或资源边界 |
| --- | --- |
| 节点到中心的控制 HTTP | 默认总计 10 秒；保留调用方更早取消、16 KiB 响应上限、独立 CA 和域名校验 |
| 网关路由与就绪检查 | 每次总计 4 秒；路由响应最多 2 KiB，就绪响应最多 4 KiB |
| 网关管理 API | 入口请求体读取最多 5 秒、8 KiB；之后控制转发总计 10 秒、响应最多 16 KiB |
| 面板 TCP / 私有 Tunnel 监听 | 每个监听最多 256 个连接、64 项头部，头部期限 15 秒；两种入口使用同一配置函数，无新增连接等待队列 |
| 面板普通 JSON 请求体 | 从开始读取起总计 10 秒，每个面板最多 16 项，无等待队列；继续使用各路由的字节上限，登录 4 KiB、SDP 48 KiB |
| 自建中心 JSON 请求体与操作 | 公共、内部各自最多 16 项 JSON 读取、每项 10 秒；各自最多 32 项在途操作，无等待队列；插件继续使用 128 KiB 正文上限 |
| 自建中心 HTTP 连接 | 独立监听时公共最多 224 个、内部最多 32 个，未完成头部也独立计费；空闲 keep-alive 继续计费，头部期限 10 秒；旧共享配置总计最多 256 个 |
| 面板到本机文件/旧 helper | 最多 6 秒，同时接受调用方更早取消 |
| 管理 Unix socket | 默认总计 6 秒；保留动作专用期限和响应大小限制 |
| Go 助手一次默认写入 | 总计 15 秒，跨应用窗口、peer credit 和原生 writer；显式期限优先 |
| 文件传输 | 沿用 5 分钟总期限、分块/缓冲等待期限和单传输确认；不套用短控制期限 |

网关向实际节点的上传、下载和 WebSocket 保持流式转发，只传递调用方取消，不套用 4/10 秒控制期限。取消表示停止等待或发送，不表示已派发的操作已撤销。网关存储操作可能在取消后完成，客户端必须按 unknown 核对。

TURN 凭据端点与中心控制 HTTP 共用回环主机名校验，允许 `localhost`、`127.0.0.1`、`[::1]` 使用本机 HTTP；其他地址仍要求 HTTPS。提供节点的中心地址时，端点必须与其同源，禁止凭据重定向，继续保留独立 CA 校验、五秒总期限和 16 KiB 响应上限。IPv6 回归使用真实 `::1` HTTP 监听，并验证非回环 HTTP 在发送凭据前被拒绝。

面板 JSON 读取名额与密码验证名额分别计费，主监听与私有 Tunnel 入口共享同一面板的读取上限。缓慢或未完成的 JSON 请求不能续期；超时返回 408、读取名额已满返回 429，均在业务派发前明确拒绝。任何提前完成的响应在发送后关闭尚未读完的声明正文，不持续排空任意长度的正文，包括成功的无正文操作和跳转。成功、格式错误、超限、断线及面板关闭均释放读取名额；文件原始字节流仍沿用五分钟传输期限。

GET、HEAD 和 WebSocket 升级不接受 `Content-Length` 大于零或 `Transfer-Encoding` 声明的正文，在业务派发前拒绝。普通无正文请求（包括 `Content-Length: 0`）及已完整读取的 JSON、上传继续复用 keep-alive；TCP 与私有 Tunnel 的总连接准入测试同时验证达到上限时拒绝连接，释放容量后正常恢复。

自建中心复用同一 JSON 读取器，也在成功响应后关闭未读完的声明正文；GET/HEAD 在业务派发前拒绝声明正文。新安装将公共接口放在 `127.0.0.1:36180`，frps 插件、Caddy 路由授权及内部健康检查放在独立的 `127.0.0.1:36181`。公共端口拒绝内部路径，内部端口只接受固定内部路径；公共慢请求头占满 224 个连接时，内部 32 个连接仍有独立容量。Caddy 的内部授权空闲连接池最多保留 16 个连接，避免空闲授权连接占满 frps 回调容量。路由的回环来源、节点凭据、Host、Origin、CSRF 和频率检查继续执行，无新增等待队列。

未配置 `SELFHOST_INTERNAL_PORT` 的旧环境继续使用共享端口兼容模式：总计最多 256 个连接，解析请求后按公共 224 / 内部 32 分类计费，尚未解析的头部仍共享总上限。完整运行中心 `install` 才会同步迁移 `server.env`、Caddy 和 frps 配置；只替换应用目录不会自动迁移。内部端口先启动，任一监听失败时关闭全部监听；验收单独检查 `/internal/healthz` 的隔离状态。应用回滚在切换前检查旧包是否支持内部监听，避免回滚后公共健康页正常、节点回调却不可用。独立安装包验证脱离源码目录后两个监听均可启动。

同一节点的并发就绪检查只共享网络探测及其节点配置快照，不共享请求者的登录状态。每个请求在加入前及结果提交时独立验证会话和 CSRF；首个请求退出不会使其他有效请求失效。探测期间接入身份或后端地址变化时拒绝旧结果，最多四个并发网络探测和五秒结果缓存保持不变。

frps 管理探测根据 404 或其他错误状态结束时立即取消未读响应正文，不等待 1.5 秒请求期限；取消本身不阻塞结果返回。成功响应继续采用 16 KiB 有界读取与清理，真实 HTTP 回归覆盖未结束的错误正文。

网关管理事务在原事务内读取状态、核验会话并清理过期记录，仅当序列化状态发生变化时调用存储写入；稳定的节点/接入码查询跳过无变化写入。首次初始化、会话撤销、过期清理和业务修改仍按原事务提交，128 KiB 状态上限保持不变。模拟存储回归检查写入次数、并发修改与撤销；真实 workerd/SQLite 回归检查持久化与路由恢复，两者均不等同于 Cloudflare 生产吞吐测试。

### 结果确认与不重放

`rejected` 只用于明确未执行或明确的业务拒绝。`unknown` 用于派发后断线、超时、响应不完整、部分输入和提交后未得到确认。明确的 helper/管理器结果应逐层保留；兼容旧响应时，不能仅凭 5xx 声称写操作未执行。

文件上传只有完整确认后才成功；终端输入只有完整写入后才成功。未知的粘贴、Enter、审批、文件替换/删除、目标打开和中心修改不得通过其他路径自动重试。只读查询可以在恢复后重新获取。

HTTPS 上传和删除在预检通过后、唯一的助手写请求派发前标记操作阶段。派发前授权失效明确返回 `rejected`；派发后即使助手已完成操作，面板若因登录过期不能确认结果，仍保留 401 权限检查并报告 `unknown`，要求重新登录后核对，不将其表述为未执行。

### 背压、关闭与吞吐

关闭是准入边界：拒绝新写入，丢弃未交付接收数据和未发送队列，释放额度及等待项，迟到回调不得重新入队。已开始的底层系统调用不声称能够回滚，业务层仍需确认结果。

HTTP 上传遇到助手提前返回的容量、配额或繁忙拒绝时，先发送完整的结构化结果，再关闭尚未读完的入站连接；上传结束时解除请求体管道并销毁转换流。传输名额释放后不能留下任意长度的未完成请求体，正常完整上传仍可复用 keep-alive 连接。此规则也覆盖面板直接返回的其他 HTTP 错误，不只处理抛出的异常。

保留已协商的 4/8/16 分块窗口、512 KiB peer credit、小控制记录保留额度，以及原生 SCTP 的拥塞控制。文件源读取使用 16 个网络块组成的有界读取块，不为每个约 16 KiB 网络消息单独调用文件提供器。

Go 助手的共享 WSS 与 RTC 都允许接收 ACK 绕过同一流中等待发送准入的反向业务写入，避免双向流量相互阻塞。WSS ACK 进入既有的 128 项控制队列，保留 5 秒发送上限及连接代次检查；底层 WebSocket 仍由单一 writer 串行写入，不改变业务数据与 FIN 的顺序，也不重放记录。

浏览器文件读取每次最多 256 KiB、等待最多 15 秒，同一执行环境内最多两项尚未结算的原生读取，不设置等待队列。取消上传或关闭文件通道会结束应用等待；`Blob.arrayBuffer()` 尚未真正完成时继续占用名额，重建文件通道不能绕过上限。额度耗尽时，新上传在发送开始记录前明确拒绝，提示等待或刷新页面后重新选择文件；迟到读取不能发送旧文件内容，也不影响新上传。调试日志分别记录读取失败、读取超时和读取额度占满，不记录文件名或内容。

文件性能排查同时比较完成字节/总耗时、`fileReadMs`、ACK 延迟、窗口和缓冲等待。增大窗口必须通过延迟注入和交互公平性验证，不能只根据直连标签或一次测速决定。既有用户实测 LAN 超过 3 MB/s、VPN 约 2 MB/s 是测试结果，不是最低吞吐承诺。

## 验证与发布顺序

1. 先构造慢速回包、取消、迟到心跳、部分写入、关闭/接收竞争和丢失提交确认的回归，再按上述四组约束修改。
2. 运行语法检查、Node 全套、Python 桌面测试、Go 全套及 `-race`/`vet`；浏览器覆盖服务 RTC、统一流、旧版终端和两种文件通道。
3. 用实际 workerd/SQLite 验证网关控制、HTTP 文件流、WSS 和助手节点绑定。此测试的节点上游为隔离 fixture，不等同于 Cloudflare 生产验收。
4. 浏览器实际 RTC 测试仍使用隔离的终端、文件和管理上游；强制 PTY 短写测试使用私有 tmux。它们不代表真实 Android 文件提供器、跨运营商网络或物理串口已经验收。
5. 发布时分别更新面板/管理服务、网关、自建中心和四个平台助手；只更新网页不会更新 Go 助手或独立网关。保留既有 v2 密钥、规则和节点身份，混合版本继续按现有能力协商，不增加协议版本。
6. 按[部署检查清单](deployment-checklist.md)和[部署验证](deployment-verification.md)完成节点身份、登录、helper 构建归属和所选功能验收。生产文件上传/删除不用于自动故障注入；真实手机、VPN、重连与串口由人工验收。

本批不新增常驻探测服务、持久诊断文件或重放队列。既有网络调试开关和日志的事件数、字节数、保留时间与脱敏规则继续生效。
