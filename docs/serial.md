# 让节点主机访问助手电脑的串口

使用 0.9.0 助手和固定八槽管理页。网页不调用操作系统串口，只配置规则；助手仅在实际 TCP 客户端连接并通过认证后打开设备。

## 使用

1. 按[助手启动流程](forward.md#部署与启动)输入对应槽位的 key。每台电脑一个助手进程，可管理多条规则。
2. 在该助手页点“新增规则”，方向选“节点主机访问助手侧网络/串口”，协议选“串口”。从自动上报列表选择设备，也可手填 `COM3`、`/dev/cu.usbserial-xxx` 等有效路径。
3. 填写节点主机监听端口和通信参数，保存启用。默认 115200、8 数据位、无校验、1 停止位、DTR/RTS 不主动维持高电平。支持固定波特率、5–8 数据位、无/奇/偶校验及 1/2 停止位，无硬件流控或 Break。
4. 用“复制连接信息”取得 `nc 127.0.0.1 22002` 等命令，在节点主机的网页终端 / AI 中执行。节点主机只监听回环。不要用会改写字节的 Telnet 客户端访问原始串口。
5. 结束客户端会关闭设备；编辑、停用或删除只关闭这条规则的旧连接。修改参数后，下一条实际客户端连接才重新打开串口。

key 已授权控制节点动态管理本机网络及串口，不再逐条输入 YES。同一助手不能同时启用两条占用同一串口路径的规则；不同助手的清单和规则独立。可运行 `--list-serial` 手动列举，不打开设备。

不同驱动打开设备时可能短暂改变 DTR/RTS，即使设为低电平也不能保证无跳变，可能使设备复位。助手不自动发送换行、登录密码或设备命令，也不保证断线前已写入的命令被设备执行。

## 连续性与边界

每条串口规则只接受一个客户端；第二条立即拒绝，原连接继续。设备占用、无权限、拔除和写入阻塞给出固定错误，不把原始驱动错误或设备路径写入脱敏报告。

单条规则的控制连接短暂中断，可在原 30 秒窗口内保留健康数据连接和已打开的串口子进程，期间暂停新客户端；恢复不重新打开设备或重发字节。数据失败、规则停止或管理员重新生成 key 会关闭相应串口。临时账号的“刷新 key”仅重新读取，不关闭串口。

编辑、停用或删除规则即使在助手控制离线时也立即撤销旧映射；重新启用或修改后的规则等待助手接入再应用。节点重启后助手自动重建启用规则，原客户端重新连接，不恢复或重放旧操作。

- 常驻清单每 30 秒上报，最多 128 个串口；枚举使用一个固定子进程、三秒期限和 32 KiB 输出。手动刷新最多一项待处理请求。
- 每个活动串口连接最多一个驱动子进程；配置首行 JSON 最多 2 KiB，随后只收发字节，不生成 shell 命令或流量日志。
- 打开最多五秒，写阻塞最多十五秒。故障或取消关闭管道并回收子进程；主助手被强制结束时，独立父进程监测负责退出。硬件或内核不可中断故障仍依赖操作系统。
- 设备名仅接受限定的 `COM1–COM9999`、`/dev/cu.*`、`/dev/tty.*`、`/dev/ttyUSB*`、`/dev/ttyACM*`、`/dev/ttyS*` 或 `/dev/serial/by-id/*`。拒绝普通文件、路径穿越和控制字符；Unix 打开前确认最终目标为字符设备。
- 数据消息 16 KiB、缓冲 256 KiB，沿用有界连接尝试和背压。固定依赖 `go.bug.st/serial v1.6.4`，Windows / Mac 四平台可交叉构建。

`npm run test:serial` 使用真实 Linux 助手、驱动子进程及故意不存在的设备，验证延迟打开、失败隔离和撤销清理；Go race 测试覆盖模拟串口字节及阻塞。Windows、Mac 和 USB / 蓝牙串口仍需真机验收。
