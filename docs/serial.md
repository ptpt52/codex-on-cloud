# 让服务器 / Codex 访问本地串口

服务器只监听 127.0.0.1，服务器上的 Codex、Python socket 或 `nc` 经原始 TCP 入口收发助手电脑的串口字节。0.8.0 起可由常驻助手自动上报串口并接受动态规则；旧的一次性串口配对从 0.7.0 起支持。网页本身不访问操作系统串口，不保存设备密码，也不执行设备命令。

## 使用

### 常驻助手

先按[常驻助手流程](forward.md#常驻助手一个进程多条规则)创建独立长期 key 并启动助手。网页选择对应助手、方向“服务器 / Codex 访问本地设备”、协议“串口”，从自动上报的列表选择设备，或手填 COM3、`/dev/cu.usbserial-xxx` 等有效路径。填写服务器回环端口和通信参数，保存启用后自动下发，无需逐条输入 YES。

长期 key 已授权该控制节点管理本机串口；助手显示正在执行的规则。实际 TCP 客户端连接并完成认证前不打开串口。修改参数、停用或删除只结束该规则的旧连接；修改后下一条客户端连接才重新打开设备。不同助手各有独立清单和规则，同一助手不能启用两条占用同一设备路径的规则。

### 一次性配对

1. 在助手电脑连接串口设备并准备好驱动。终端运行 `codex-cloud-forward --list-serial`（Mac/Linux 通常需要 `./codex-cloud-forward --list-serial`）列出最多 128 个名称；列举不会打开设备。
2. 网页“端口映射”选“服务器 / Codex 访问本地设备”，设备协议选“串口”。填写设备名称、服务器回环端口（例如 22002）、助手电脑的设备名称（例如 COM3 或 /dev/cu.usbserial-xxx）。
3. 默认 115200、8 数据位、无校验、1 停止位、DTR/RTS 均不主动维持高电平。按设备说明修改。支持固定波特率选项、5–8 数据位、无/奇/偶校验及 1/2 停止位，无硬件流控，不提供 Break；一次性授权生效后参数固定。
4. 生成一次性配对码，在助手粘贴。核对串口名称、全部通信参数及服务器入口后，输入 YES 确认。串口授权要求交互确认，原 TCP 的 `--allow-reverse IP:port` 不能代替串口同意。
5. 网页显示助手在线时，还没有打开串口。“复制给 Codex”提供 `nc 127.0.0.1 22002` 等固定入口信息。只有实际 TCP 客户端连接并完成数据通道认证，助手才打开该串口。不要用 Telnet 客户端，以免其协议协商改写原始字节。
6. 结束客户端连接会关闭串口，结束助手或网页确认停止会撤销整个映射。串口配置固定在本次授权中；要修改参数需停止后重新配对。本版不将串口资料加入 TCP 设备目录。

不同驱动在打开串口时可能短暂拉高 DTR/RTS，即使选择低电平也不能保证完全没有跳变，可能导致连接的设备复位。界面与助手确认均提示这一行为。应在适合打开串口时确认并连接。连接关闭即关闭设备，不额外发送换行、命令或保证设备已执行之前写入的内容。

## 连续性与权限

每个串口映射只接受一个客户端。第二条连接立即拒绝，原客户端继续工作；多个助手访问同一物理串口仍受操作系统独占和权限限制。串口拒绝打开、设备拔除、写入阻塞分别给出固定错误，不把串口路径或原始驱动错误带入脱敏报告。

WSS 中转、可用时的新连接加密直连及授权恢复沿用 TCP 映射。0.7.2 助手与新版服务端双方确认保活后，管理通道短暂断开可在原 30 秒窗口内保留健康的数据连接及已打开的串口子进程，并暂停新连接；管理恢复不重新打开设备、不重发旧字节。数据通道失败、授权失效或恢复超时仍关闭串口，旧版任一端未支持保活时管理断线也会关闭旧 TCP 和串口子进程；再次连接服务器入口由原客户端决定。短暂数据通道故障不自动重试当前串口操作。旧助手缺少串口能力时在消费配对码之前拒绝，不能把串口误当作 TCP 地址。

锁屏保留已有授权、有效配对码和恢复能力。常驻 key 独立于网页登录，管理规则和查看清单需管理员解锁并接管；重启面板后助手可恢复启用规则，旧 TCP / 串口操作不重放。一次性授权绑定来源登录；临时账号可创建自己的串口反向授权，来源登录退出/到期/撤销、明确停止或面板重启结束对应映射。

串口设备不是 TCP 目标，`TCP_FORWARD_PORTS` 限制仍仅适用于 TCP 设备目标。服务器回环监听端口继续排除本项目管理端口；该监听没有额外设备认证，适用于项目原有的可信单用户服务器模型。

## 资源边界与检查

- 常驻模式每节点最多八个助手、每助手十六条规则，全节点最多三十二条活动映射；一次性模式仍最多四条。串口每映射一个客户端，消息 16 KiB、服务端缓冲 256 KiB，沿用有上限的连接尝试及背压。
- 常驻助手每 30 秒上报一次串口列表，最多 128 项；手动刷新合并为一项待处理请求。列举使用最多一个固定子进程、三秒超时和 32 KiB 输出，不打开设备。上报错误不妨碍手填有效路径。
- 本地助手每个活动串口连接最多一个子进程，配置通过最多 2 KiB 的首行 JSON 传入，之后仅收发字节，不生成 shell 命令、不写配置、内容或流量日志。
- 打开设备最多五秒，串口写入阻塞最多十五秒。驱动调用在子进程内进行，失败、数据通道关闭或主助手取消时关闭管道、结束并回收子进程；父助手被强制结束时由独立监测退出（Unix 最多约一秒，Windows 等待父进程句柄），清空连接状态，不保存待发送队列。硬件或内核不可中断故障仍依赖操作系统处理。
- 名称限制为 COM1–COM9999、/dev/cu.*、/dev/tty.*、/dev/ttyUSB*、/dev/ttyACM*、/dev/ttyS* 或 /dev/serial/by-id/*。不接受任意文件、/dev/zero、路径穿越或控制字符；Unix 打开前要求最终目标为字符设备。
- 固定依赖 [go.bug.st/serial v1.6.4](https://pkg.go.dev/go.bug.st/serial@v1.6.4)，CGO=0 可构建 Windows/Mac 两种架构；相关许可证包含在助手 --licenses 输出。

开发检查：`npm run test:serial` 使用真实 Linux 助手、子进程、TCP/WebSocket 与故意不存在的设备，验证 YES/拒绝、延迟打开、失败和回收；Go race 测试覆盖模拟设备双向字节、单独子进程的启动超时、写入阻塞及恢复参数固定。Linux 伪终端测试使用真实 serial 库验证原始字节，伪终端没有 DTR/RTS，不能代替实际控制线验收。

Windows/Mac 真机仍需使用 USB 串口检查：正常收发、第二客户端拒绝、拔线、明确停止、短暂断网后重新连接，以及实际 DTR/RTS 对设备复位的影响。上述自动化不代表这些硬件检查或公网 Cloudflare 部署检查已经完成。
