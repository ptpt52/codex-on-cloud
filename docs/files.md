# 文件中转

打开工作台的“文件中转”，上传或下载节点 `WORKSPACE_DIR` 下 `transfer` 目录中的文件。管理员和临时账号共用此目录；只放准备共享的内容，不提供整个工作区的任意路径访问。

## 上传、下载与同名文件

1. 选择本机文件，或拖入文件中转窗口上传。每次一个文件，最多 50 MiB；不支持文件夹，不排队上传。
2. 遇到同名文件，默认取消；可选择“自动改名上传”保留两份，或明确确认“替换文件”。Enter、Escape 均不会确认替换。
3. 替换会核对原文件版本。其他程序已修改或删除文件时，原内容保留；刷新列表后重新选择。
4. 下载从当前列表选择。50 MiB 以内由工作台显示进度；较大的已有文件交给浏览器下载列表管理。
5. 断线或提示“结果未知”时，先刷新列表核对实际文件，再手动重试；系统不自动重传。

仅收到 HTTP 200 不代表上传已确认：完成信息还必须包含有效的实际文件名。同名冲突、版本变化或配额拒绝只结束本次传输，不代表整个工作台或服务直连失效。

## 进度与取消

文件中转窗口每次处理一项文件传输，不排队。窗口显示已传大小、百分比与平均速度，可随时点击“取消传输”；关闭文件窗口后传输继续，重新打开可查看当前状态。

HTTPS 上传按节点实际收到的字节显示进度，WebRTC 上传按接收端确认的字节计算。达到 100% 后仍需等待保存确认；只有校验完成信息后才显示上传完成。取消或断线可能发生在文件已经保存之后，因此上传结果未知时先刷新列表核对，不自动重传，也不自动撤销服务器文件。

50 MiB 以内的下载显示接收进度，取消后不生成不完整下载文件。较大文件仍直接由浏览器保存，进度与取消操作在浏览器下载列表中完成；工作台不会把大文件整体读入网页内存。

手动取消 WebRTC 文件传输会结束该文件通道，并准备新文件通道；控制连接和桌面任务继续保留。是否重新上传／下载由用户决定。

## 把文件交给终端或 AI

列表中的“复制路径”复制节点主机上的完整文件路径，供 Codex 等服务器端程序使用；它不是浏览器设备的本地路径。浏览器拒绝自动复制时，会显示可选中的路径供手动复制。

“加入草稿”把路径追加到当前输入助手草稿，路径按 POSIX 单引号转义，包含空格、引号或 `$()` 的文件名仍按字面处理。先核对输入目标和文字，再点击粘贴，最后按 Enter；加入草稿本身不发送任何终端输入。加入后超过 32 KiB 时保留原草稿并提示精简。

桌面视图提供“在远程桌面打开目录”，首次打开部署配置中的固定目录，不接受任意路径。再次点击会激活已有窗口，保留浏览位置。锁屏、失去控制权或临时账号不能打开远程窗口或加入输入草稿，仍可按原权限上传、下载和复制共享路径。纯终端部署没有图形目录按钮。

## 权限与容量

| 项目 | 规则 |
| --- | --- |
| 管理员锁屏或被接管 | 仍可使用共享文件中转 |
| 临时账号 | 可上传、下载共享目录；不能读取其他工作区目录 |
| 临时上传配额 | 整个共享目录最多 1000 份文件 / 1 GiB，同时最多一个临时上传 |
| 全局传输 | 最多四项，每项最多五分钟 |
| 文件列表 | 最多返回 1000 份元数据；目录过大时明确提示未完整列出 |

配额无法完整核算或文件服务版本不支持校验时，拒绝临时上传，需管理员检查目录或升级服务。管理员上传不使用临时账号的目录配额。退出或授权失效会取消对应传输，未完成临时文件由文件服务清理。

## HTTPS 与文件直连

窗口显示当前内容传输路径。HTTPS 和独立 WebRTC 文件通道沿用相同身份、共享目录、配额与冲突规则；管理员打开窗口时也会按需准备服务直连。直连未就绪时可以使用 HTTPS；已经发出的直传请求不会换通道重传。

同一文件通道还可下载[已发布的端口映射助手](forward.md#下载与-mac-首次运行)，单项最多 32 MiB，不读取共享目录中的同名文件。

网络路径与端口见[直连与中转](lan.md)，账号与锁屏规则见[访问权限](access.md)。

## 旧部署升级

文件服务与 panel 需保持版本配套，单独刷新网页不能加载 Python 或后端代码。旧文件助手可能仍是任务宿主的关键子进程，直接结束它会触发宿主退出。

传输进度模块和取消协议需要更新 panel（含服务文件通道代码与 UI 资源白名单），不能只运行 `reload-ui`。旧后台不支持 HTTPS 上传进度时只显示等待状态，不伪造百分比。

共享目录窗口功能还需要更新 panel、manager 和桌面 actions 服务，并安装 Thunar。新部署使用 `--install-deps` 时会一并安装；旧部署先运行 `npm run native:doctor`，按提示安装缺失组件。按[界面与服务更新](ui-updates.md)选择对应更新方式；仅刷新静态资源不能启用新接口。重启 actions 会关闭它持有的图形窗口，tmux 任务继续运行，终端窗口可重新打开；不要为更新界面重启整个桌面。

保留任务时，按[独立文件服务迁移](ui-updates.md#文件服务与旧宿主迁移)先安装并验证新 files 服务，再选择空闲的 `FILE_AGENT_PORT`；不要直接结束旧助手。需要更新任务宿主时，另行安排维护窗口。

## 协议与资源边界（开发参考）

| 边界 | 约束 |
| --- | --- |
| 请求范围 | 仅共享目录中的单个普通文件，拒绝路径、URL、设备端口与命令 |
| 文件数据通道 | `codex-files` / `files-v1`，可靠有序；每 peer 一个文件通道，每通道同时一项传输 |
| 传输窗口 | 分块最多 16380 字节，协商 4 / 8 / 16 块；新客户端使用十六块，未确认或待处理分块各最多约 256 KiB，通道发送缓冲上限 512 KiB；写入或接收后确认 |
| 元数据 | 最多 4 KiB，序号单调递增；重复块、伪造确认或超出窗口会关闭通道 |
| 上传确认 | 最多保留一个待上传 File，确认最多两分钟，整个上传尝试最多五分钟 |
| 自动改名 | 最多尝试 100 个名称，名称最多 240 字节，尽量保留扩展名 |
| 目录扫描 | 最多扫描 4096 个目录项，返回最多 1000 份元数据，通过 `truncated` 标记完整性 |
| 浏览器下载 | 单项最多缓存 50 MiB 后生成 Blob，最多两个下载 URL，30 秒后、离页或退出时撤销 |
| 下载缓冲 | 最多 800 个 64 KiB 块，合并小分块，避免小包数量放大内存开销 |
| WebRTC 发送缓冲 | 512 KiB 上限，预留 4 KiB 控制消息空间；最多一个缓冲等待，15 秒未恢复则结束传输，不重发 |
| HTTPS 上传进度 | 仅附着于最多四项活跃传输，绑定原登录会话；结束即移除，无历史表。浏览器最多一个在途查询，间隔 500 毫秒，单次最多等待 2.5 秒 |

`GET /api/files` 声明 `uploadProtocol: 1` 并返回文件 `version`；panel 同时声明 `fileProgressProtocol: 1`。HTTPS 上传可携带随机 32 位十六进制 `X-Codex-Transfer-Id`，通过只读 `/api/file-progress/<id>` 查询节点已接收字节，仅原登录会话可读。两种通道使用相同模式：

| 上传模式 | HTTP 条件 | 结果 |
| --- | --- | --- |
| 新建 `create` | `X-Codex-Upload-Mode: create`、`If-None-Match: *` | 列表之后出现同名文件也不覆盖，返回 409 |
| 自动改名 `rename` | 上传模式为 `rename` | 新增文件，按临时账号完整配额核算 |
| 替换 `replace` | 上传模式为 `replace`、`If-Match: "<version>"` | 必须携带精确版本，变化或删除返回 412；仅抵扣原文件容量 |

直连在 start 元数据中携带相同 mode/version，完成回复返回实际文件名。未声明协议的旧文件服务返回 503；网页也在发送内容前检查能力，不回退静默覆盖。未完成或无效的成功回复仍视为结果未知，不根据原文件名猜测。

服务 `ping` 的 `filesWindow` 声明可用窗口，客户端在 `start.window` 提交，服务端在 `ready.window` 确认；未声明时保留四块，传输期间不能改变窗口。文件与服务控制通道在节点侧使用同一有界公平发送器，ACK、心跳和服务响应可优先发送，单个文件不会占满全部原生发送额度。桌面和终端继续使用原有独立 peer。

取消使用 `{type:"cancel", id}` / `{type:"cancelled", id}` 确认，仅接受当前或刚完成的传输 ID；浏览器立即结束等待，文件通道最多等待 1.5 秒后关闭。收到取消不代表已提交文件被回滚，也不重发原请求。

文件版本由 inode、设备号、大小和纳秒修改 / 变更时间生成，不读取整份内容、不持久化版本表。API 上传使用互斥锁并在提交前复核；新建和改名通过原子硬链接提交，替换在复核后原子替换。外部 shell 写入不共享此锁，不能视为对外部程序的完整事务隔离。

临时上传还要求 `quotaProtocol: 1`，由 panel 附加内部配额标记。文件服务在单上传锁内、接收内容前后核算整个目录，不以截断列表代替配额检查。无法完整核算时拒绝临时上传，不回退旧实现。没有新增历史文件或持久化上传队列。

助手下载只接受四个平台标识及可选固定版本号，访问已认证下载 API，拒绝任意路径和 URL；沿用全局最多两个助手下载、32 MiB 和五分钟期限，与普通下载共用浏览器 Blob URL 上限。

离线、退出或登录失效取消待确认上传和对应 HTTP / 文件服务请求；锁屏或画面接管不取消仍有权限的文件操作。上传逐块读取 File，不将整个文件转成内存字符串。协议错误、授权失效、网络故障或未知结果会关闭对应连接，不自动重传。明确业务拒绝可重建单个文件通道并保留服务控制 peer，服务端结束等待最多三秒。
