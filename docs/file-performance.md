# 文件传输性能基线

运行 `npm run test:files:bench`，在隔离面板上通过实际 ICE/DTLS 上传文件，校验后台接收内容的 SHA-256，同时每 50 毫秒串行执行一次只读服务探针。文件上游使用测试 fixture，不读写部署的共享目录，不使用生产入口或凭据。

并行服务请求的本机 HTTP 期限为 6 秒，浏览器 RPC 期限为 8 秒。RPC 超时后，已发送操作保持“结果未知”，不会重发；直连控制只保留一个待排空的请求 ID，晚到回复仅恢复通道，不改写原结果。正在进行的文件传输继续受原有五分钟总期限及进度、确认期限约束，新控制请求改用 HTTPS；回复一直缺失时，等文件结束再重建服务连接。实际连接或授权失效仍会终止传输。

本机文件提供器读取失败或返回截断内容时，通过同一 `cancel/cancelled` 流程清理当前上传，取消确认最多等待 1.5 秒。随后重新打开文件通道，保留健康的服务连接和在途控制请求；不会自动重新上传，需重新选择文件并明确重试。

默认上传 4 MiB、协商十六块窗口，每种条件重复三次，输出每次测量与中位数 JSON：

| 条件 | 注入的应用层 ACK 延迟 | 用途 |
| --- | --- | --- |
| `loopback` | 0 毫秒 | 本机协议栈与读取开销 |
| `ack-40ms` | 40 毫秒 | 观察较高确认延迟对窗口吞吐的影响 |
| `ack-150ms` | 150 毫秒 | 检查高确认延迟下的吞吐及并发服务响应 |

这是应用层故障注入，不是 IP/SCTP 网络整形，也不等于实际 LAN、VPN 或 Android 文件提供器的测试。服务探针本身没有注入网络延迟；其 P95 用于比较同一测试机上的资源争用。输出的 CPU 占用同时包含本进程内的面板与测试客户端，不能与独立生产进程的 CPU 数字直接比较。

可调整的环境变量：

| 变量 | 默认值与范围 |
| --- | --- |
| `FILE_BENCH_BYTES` | 4194304；64 KiB–16 MiB |
| `FILE_BENCH_REPEATS` | 3；1–5 |
| `FILE_BENCH_WINDOW` | 16；仅允许 4、8、16 |
| `FILE_BENCH_READ_MS` | 0；每个读取块额外等待 0–250 毫秒 |

例如比较较小窗口与有延迟的文件读取：

```sh
FILE_BENCH_WINDOW=8 FILE_BENCH_READ_MS=20 npm run test:files:bench
```

单次只运行一项上传，文件在每次确认并校验后从 fixture 清理；注入 ACK 队列不超过协商窗口，每次最多 1024 个探针样本，整轮最多十分钟。失败直接终止，不重放上传。基线不是默认 CI 的最低速度断言，避免把共享 runner 的负载波动误判为网络回归。

2026-11-18 的一次本机记录：Linux、Node v24.21.0、werift 0.26.0，4 MiB × 三次，窗口十六块，无额外读取延迟，测量时未并行运行仓库回归测试。

| 条件 | 吞吐中位数（MiB/s） | 三次中最高的探针 P95（毫秒） |
| --- | --- | --- |
| `loopback` | 2.94 | 212.53 |
| `ack-40ms` | 2.67 | 92.26 |
| `ack-150ms` | 1.46 | 19.42 |

所有上传均得到完成确认并通过哈希校验。探针延迟应结合吞吐和 CPU 一起看；减慢发送可能降低本机资源争用，该数字不能代替真实链路 RTT。另以八块窗口、每次读取额外等待 20 毫秒完成了三种条件的参数验证。

比较时保存相同文件大小、窗口、重复次数、Node/依赖版本和测试条件。先比较确认完成字节/耗时，再看 `fileReadMs`、`chunkAckMs`、`chunkMaxAckMs`、`bufferWaitMs`、探针 P95 和观测到的缓冲量；仅凭“直连”标签或单次测速不能判断瓶颈。实际 LAN/VPN 测试还应记录真实路径、操作系统与文件来源，并单独报告。

大文件下载另用 `test/browser/large-file-download.spec.mjs` 验证。2026-11-19 的一次隔离 Chromium 移动视口测试中，140 MiB 经真实本机 ICE/DTLS 下载、由浏览器流式保存，SHA256 一致，浏览器 HTTPS 文件内容请求为零，测得约 6.96 MiB/s。该记录使用测试文件服务和同机网络，不代表 Android 真机、无线局域网或 VPN 的吞吐，也不作为 CI 最低速度断言。

保存 Worker 的持续运行可显式运行下列验收，默认 CI 跳过此慢项：

```sh
FILE_LONG_DOWNLOAD_TEST=1 npm run test:browser -- test/browser/large-file-download.spec.mjs --project=mobile --grep 'sustained native'
```

本机已完成一次 311 秒的 8 MiB 慢速保存并通过哈希校验，覆盖五分钟以上的浏览器 Worker 生命周期；此项不测量 WebRTC 吞吐。
