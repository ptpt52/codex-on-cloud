# 屏幕锁与临时访问

在已接管的工作台打开“工具 → 访问与屏幕锁”。桌面和纯终端均支持，默认不启用屏幕锁或临时账号。

工作台登录密码、屏幕锁密码、中心 / 网关管理员密码和节点接入 key 分别管理。浏览器保存工作台密码时保留预填登录名：自建节点为 `admin@node-<slug>`，CF 网关节点为 `admin@nodeid-<NODE_ID>`，自定义管理员用户保留自己的前缀；原用户名也可登录。具体入口见[中心登录](selfhost-admin.md#登录与浏览器记住密码)和[CF 网关](gateway.md#4-增加与切换节点)。

## 屏幕锁

1. 开启屏幕锁，设置独立的 4–128 字符密码并保存；当前页面随即需要解锁。
2. 新页面登录、刷新或点击“在这里使用”接管时，重新输入屏幕锁密码。
3. 当前页面可从工具中“立即锁定”。修改密码撤销现有画面授权，关闭锁恢复普通接管流程。

另一端登录不会立即抢走控制权，需正确解锁后才能接管。错误、取消、断线或结果未知都不会自动重复提交密码；以前输入的密码不会用于自动抢回控制权。

屏幕锁使用你设置的固定密码。设置框与解锁框尽量抑制浏览器的账号密码填充 / 保存建议，正常账号登录仍支持保存和填充；网页无法保证所有浏览器或扩展都遵守提示。

## 权限对照

| 操作 | 已解锁并接管的管理员 | 锁定 / 被接管的管理员 | 临时账号 |
| --- | --- | --- | --- |
| 桌面、网页终端、历史、剪贴板和输入 | 允许 | 不允许 | 不允许 |
| 工作台设置、设备目录 | 允许 | 不允许 | 不允许 |
| 连接状态 | 允许 | 允许 | 允许 |
| 共享文件中转 | 允许 | 允许 | 允许 |
| 创建 / 查看 / 停止一次性正向映射 | 允许 | 不允许 | 不允许 |
| 创建 / 管理一次性反向设备映射 | 允许 | 允许 | 仅本次登录创建的映射 |
| 常驻助手 key、动态规则及网卡 / 串口清单 | 允许 | 不允许 | 不允许 |

临时账号即使知道屏幕锁密码也不能解锁桌面。文件中转是共同目录，不隔离各用户的共享文件，完整范围和配额见[文件中转](files.md)。

## 临时账号

管理员解锁并接管后，配置一个与管理员不同的临时用户名、8–128 字符密码和 1 小时至 7 天的有效期。用户名使用字母、数字、下划线或短横线。保存确认后可复制本次账号密码；服务器只保存加盐哈希，需要再次分享而没有原密码时，设置新密码。

有效期从每次保存开始计算。修改、续期或停用前有确认，完成后撤销旧临时登录及其映射；管理员登录、任务和映射不受该操作影响。管理员最多八个登录，临时账号最多四个，名额池分开。

受限页面会独立探测获授权的服务直连，不认领桌面、不附加 VNC / PTY，也不挤占管理员的画面连接。失败继续使用 HTTPS；退出、账号撤销或到期时关闭对应服务连接。锁屏与桌面接管不撤销这项受限服务授权。

### 文件内容直传

上传下载可使用 HTTPS 或独立 WebRTC 文件通道，两者沿用相同权限和冲突规则。已发出的请求不自动换通道重传，见[文件中转](files.md)。

## 映射方向与生命周期

正向是“本机访问服务器网络”，反向是“服务器 / Codex 访问本地设备”。反向映射的服务器监听仅绑定回环，例如助手授权后，服务器可经 `127.0.0.1:22001` 访问助手电脑可达的固定设备。

一次性映射绑定创建它的登录，独立于桌面控制权。锁屏、被接管、刷新和关闭网页保留原授权；退出来源登录、该登录到期 / 被淘汰、明确停止或临时账号撤销会结束对应映射。面板重启也需重新配对，桌面和终端任务继续运行。

常驻助手使用独立、可撤销的长期 key，退出网页登录或密码重置不撤销它；需在完整管理员页面重新生成 key 或移除助手来撤销。后台重启中断旧 TCP，运行中的助手以原 key 重连并重建已启用规则，业务字节和设备命令不重放。key、规则及设备清单仅解锁并接管的管理员可查看 / 管理，临时账号不能访问。各助手独立授权，修改规则只重建该规则。详见[常驻助手](forward.md#常驻助手一个进程多条规则)。

### 锁屏后全部保留

锁屏保护网页画面与输入，**不撤销锁定前已签发的双向映射授权**；通过原映射建立后续新 TCP 连接也继续允许。开启 / 修改锁密码和被另一端接管使用相同规则。

| 锁定时的状态或操作 | 规则 |
| --- | --- |
| 已启用的正向映射（本机 → 服务器） | 保留映射及正在传输的 TCP 连接；也允许通过该映射建立后续新 TCP 连接。 |
| 已启用的反向映射（服务器 → 本地设备） | 同样保留已有与后续新 TCP 连接。 |
| 已生成、尚未使用的配对码 | 在原来两分钟有效期内仍可配对原固定目标；锁屏不延长期限，也不会签发新码。 |
| 原授权处于断网恢复中 | 按原来 30 秒 / 最多八次握手的预算恢复同一映射，不要求先解锁。双方支持保活时，管理断线期间保留健康数据连接并暂停新连接；已失败 TCP 不迁移或重放字节/设备命令，旧版仍关闭旧 TCP 后恢复映射。 |
| 锁定页面新建正向映射、签发新码或管理正向映射 | 拒绝。解锁后才能查看/停止该方向的映射；运行助手的电脑仍可停止助手。 |
| 锁定页面配置反向映射、使用文件中转或查看连接状态 | 继续按原权限开放；临时账号仍只管理本次登录创建的反向映射。 |

上表的一次性授权仍要求来源登录有效、助手运行。常驻规则在锁屏后继续，规则管理及设备清单访问被禁止。后台重置密码会停止并恢复面板：一次性映射结束，常驻助手重连重建规则，旧 TCP 均不保留。助手的方向、配对、目标确认和恢复见[端口映射](forward.md)。

## 后台密码重置

以下只重置节点工作台密码或屏幕锁，不重置中心、网关或 Codex 账号。在节点本机或 SSH 中进入部署目录，使用部署项目的普通用户执行，不要 sudo：

```bash
npm run reset-password
```

菜单可选择重置管理员密码、重设屏幕锁密码或关闭屏幕锁。也可直接指定操作：

```bash
npm run reset-password -- --admin
npm run reset-password -- --screen
npm run reset-password -- --unlock
```

管理员密码输入两次且不回显，长度 16–512 个字符，首尾不能有空白。屏幕锁密码为 4–128 个字符；`--screen` 会立即设置新密码并开启锁，`--unlock` 只关闭锁。两次输入不一致、Ctrl+C 或输入超时都会在开始提交前取消。不要把密码放在命令行参数中。

没有交互终端或希望自动生成管理员密码时：

```bash
npm run reset-password -- --admin --generate
```

新管理员密码写入 `secrets/panel_password`，并同步更新 `secrets/credentials.txt`，均为 0600；密码不会打印到命令输出。原管理员密码只是忘记时，也可直接在服务器查看现有的 `secrets/panel_password`，无需执行重置。

命令先收集并校验输入，再停止运行中的 `codex-cloud-panel.service`、写入配置、恢复面板并检查回环健康。仅操作与当前项目目录匹配的面板服务；其他部署、特殊文件或仍在监听的手动面板会阻止写入。原本停止或失败的面板保持原状态，需要时手动启动。桌面、终端宿主、管理器、Tunnel 和 Codex 任务不重启；一次性映射需重新配对，常驻助手自动重连重建启用规则，旧 TCP 不恢复。

管理员密码重置会使旧登录失效，不改变屏幕锁或临时账号配置；忘记两种密码时需分别处理。屏幕锁重设/关闭保留管理员密码和临时账号配置。关闭锁后再次开启时，请填写新锁密码，留空会保留原来配置的密码。

重置命令以当前项目`.env`中的账号、入口和端口为准，不让旧Codex任务继承的部署变量覆盖配置；运行systemctl仍使用当前部署用户的正常进程环境。恢复检查不会因旧域名或旧端口误判。

## 实现与资源边界

屏幕锁和临时账号保存在私有 `data/panel/access.json`，最多 8 KiB、0600；损坏或权限异常时拒绝启动，不自动关闭锁。忘记密码使用上面的重置命令，不直接删除状态文件。回退到不识别临时角色的旧面板会要求重新登录。

受限服务只接受固定操作，沿用登录、Host、Origin、CSRF 和映射归属校验，不是任意 HTTP 或命令代理。最多八个 peer（含关闭中），管理员与临时账号各最多四个，每登录最多两个，每控制通道一项在途请求，超额仍可走 HTTPS；不自动重发结果未知的 POST。

维护锁固定为`data/panel/password-reset.lock`，0600、最多256字节。复用Python标准库flock，固定空inode是正常状态，不删除锁文件；活跃重置排斥并发，进程退出/被杀后自动释放，空锁和半截旧PID记录可恢复，完整活跃旧PID记录仍保守拒绝。不向其他重置进程发信号。写入前及改名提交前检查租约；租约丢失不继续改密码或与另一个维护进程争抢启动面板。管理员密码及摘要各使用一份固定`.reset.tmp`文件，内容上限分别为2 KiB / 4 KiB，0600，成功后原子替换并同步目录。写入失败时尽力恢复原来运行的面板，命令会报告可能已提交的修改；以`secrets/panel_password`为实际管理员密码来源，勿在结果未知时盲目重复操作。

## 验证边界

`access-control`、`access-policy`、`file-transfers` 和 `reverse-forward` 的 Node 测试覆盖持久化、权限隔离、撤销、并发边界及锁定/接管时真实 TCP/WebSocket 字节流继续传输。浏览器 `access.spec.mjs` 使用实际 Chrome、noVNC 和模拟 RFB/管理后端验证手机/电脑布局及完整登录流程；它不代替手机真机、真实 X11 桌面和公网网络验收。
