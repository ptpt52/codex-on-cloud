# 屏幕锁与临时访问

在已接管的工作台打开“工具 → 访问与屏幕锁”。桌面部署和纯网页终端部署都支持，默认不启用锁或临时账号。

## 屏幕锁

勾选开启，设置独立的 4–128 字符密码并保存。保存后当前页面也会锁定，需要重新输入。此后每次新页面登录、刷新页面或点击“在这里使用”接管时都需解锁；输入错误、取消或断线不会自动再次提交密码。当前页面可从工具中“立即锁定”。修改密码会撤销当前画面授权，关闭屏幕锁则恢复原有接管流程。

另一台电脑或手机登录时，原页面保持控制权，直到新页面正确输入屏幕锁密码。接管后旧页面的解锁授权立即作废，不能使用以前输入的密码自动抢回。锁同时保护桌面画面、网页终端、历史、剪贴板、输入及设置；任务仍由后台持有，不随锁定、接管或关闭浏览器结束。

屏幕锁的设置框和解锁框均单独设置自动填充提示，尽量抑制账号密码填充及保存建议；正常账号登录仍支持浏览器保存和填充密码。屏幕锁仍验证你设置的固定密码，不会因浏览器标记变成一次性密码。是否完全隐藏原生建议取决于浏览器或密码管理器扩展的策略。

锁定或被接管的管理员页面可以查看连接状态、使用文件中转，以及配置和管理“服务器 / Codex 访问本地设备”的反向映射。不能新建或停止“本机访问服务器网络”的正向映射，也不能读取或修改设备目录。

## 临时账号

管理员解锁并接管后，可启用一个临时用户名和 8–128 字符密码，选择 1 小时至 7 天的有效期，保存后复制本次账号密码给使用者。后端也接受五分钟起的有效期。只存加盐密码哈希，无法再次读出密码；需要重新复制时设置新密码。用户名使用字母、数字、下划线或短横线，并与管理员不同。

临时账号使用同一个登录界面，可进行：

- 查看连接状态。
- 创建、查看和停止本次登录创建的反向设备映射。
- 上传、下载共享文件中转目录中的文件。

临时账号登录、管理员锁屏或被接管后，浏览器会独立探测受限服务直连，使用当前浏览器保存的辅助 IP。该连接不认领桌面，不附加 VNC/PTY，也不会占用或关闭管理员的画面连接。可直连查询连接状态、诊断、文件列表和按原权限管理映射；失败继续使用 HTTPS，并按 15 / 30 / 60 秒重试，网络变化或保存辅助 IP 会提前探测。界面分别显示受限服务和助手映射的实际路径，两者独立协商。

受限服务只接受固定操作，不支持任意 URL、HTTP 头、命令或桌面输入。服务端通过固定回环请求复用原有 HTTP 权限检查，CSRF、Host、Origin、账号有效期与映射归属仍然生效；POST 结果不明时不经 HTTPS 重发。服务直连最多八个 peer（含关闭中），管理员与临时账号分别最多四个、每次登录最多两个，每个控制通道只有一项在途请求，无持久化队列；超额继续使用 HTTPS。账号退出、撤销或到期会关闭对应服务连接，屏幕锁及桌面接管不撤销这项受限授权。

### 文件内容直传

文件中转窗口显示文件内容使用 WebRTC 或 HTTPS。受限服务直连就绪时，50 MiB 内的上传和下载走独立的 `codex-files` / `files-v1` 可靠有序数据通道；管理员打开文件中转时也会按需启动服务直连。尚未直连时保留原 HTTPS，大于 50 MiB 的已有文件通过原 HTTPS 下载。

专用通道只允许共享目录中的单个普通文件，不接受路径、URL、设备端口或命令。每个 peer 只有一个文件通道，每通道同时一个文件；分块最多 16380 字节、最多四块未确认数据，接收方写入或接收后确认，发送与接收队列各最多约 64 KiB。元数据最多 4 KiB，序号单调递增，重复块、伪造确认或超出窗口会关闭通道。单次文件最多 50 MiB、五分钟；同一全局四项传输及临时上传串行、1 GiB / 1000 文件规则同时覆盖 HTTP 和直连。账号失效会取消本地 HTTP 请求和助手请求，Python 助手清理未完成临时文件。

上传前重新读取文件目录与版本。已有同名文件时弹出确认，默认焦点为“取消”，Enter、Escape 均不会替换文件；可选“自动改名上传”（例如 `资料 (2).txt`，保留原文件）或“替换文件”。替换携带确认时的原文件版本，收到内容后再次核对；已删除或发生变化则返回 412，原文件保留，需刷新列表后重新选择。列表之后才出现的同名文件也不会被默认上传覆盖，返回 409。

一次最多保留一个待上传 File，确认最多两分钟，包含确认的整个上传尝试最多五分钟。离线、退出或登录失效取消待确认操作；锁屏和画面接管不取消仍有权限的文件操作。自动改名最多尝试100个名称，名称不超过240字节，尽量保留扩展名；自动改名算新增文件，替换仅抵扣原文件的容量，不绕过临时账号配额。没有新增历史文件、上传队列或持久化版本表。

`GET /api/files` 返回 `uploadProtocol: 1` 和文件 `version`。上传默认仅新建（`X-Codex-Upload-Mode: create` / `If-None-Match: *`），自动改名用 `rename`，替换用 `replace` 与 `If-Match: "<version>"`；缺少精确版本的替换被拒绝。直连上传在 start 元数据中携带相同 mode/version，完成回复返回实际文件名。Python 助手必须同时更新，面板遇到未声明协议的旧助手会返回503，网页也在发送内容前检查能力，不回退到静默覆盖。

文件版本由 inode、设备号、大小和纳秒修改/变更时间生成，不读取整份内容、不持久化。API 上传之间使用既有互斥锁，提交前复核版本；服务器上的任意 shell 写入不共享此锁，不能把它视为对外部程序的完整事务隔离。新建与自动改名通过原子硬链接提交，名称被其他程序抢先创建时不会覆盖；确认替换在复核后原子替换。

目录最多返回1000份文件元数据、最多扫描4096个目录项，响应通过 `truncated` 明确表示是否完整。临时上传要求助手声明 `quotaProtocol:1`，由面板附加内部配额标记；助手在单上传锁内、接收内容前后检查1000份/1 GiB上限，不以截断列表代替整个目录。无法完整核算的目录拒绝临时上传，管理员整理后可恢复；普通管理员上传保持原权限。升级到支持配额核算的助手前，临时上传明确拒绝，不回退旧实现。

升级同时涉及文件助手及面板，单独重载网页不能加载 Python 代码。旧版助手属于桌面/终端宿主的关键子进程，直接结束它会触发宿主退出。保留任务时可按[独立文件助手迁移](ui-updates.md#文件服务与旧宿主迁移)部署新版助手并设置 `FILE_AGENT_PORT`，只更新文件接口；否则应在任务已保存的维护窗口按宿主更新流程加载新版，不要盲目结束原助手。重启面板仍按原规则需要重新配对映射。

浏览器单次下载最多缓存 50 MiB 后生成 Blob，最多保留两个下载 URL，三十秒后、页面离开或退出时撤销；单次上传逐块读取 File，不将整个文件转成内存字符串。尚未开始的操作可选择 HTTPS；一旦发出直传请求，失败或完成确认丢失都不会自动通过 HTTP 重传。请先刷新文件列表确认结果，再由用户手动重试。

HTTPS与直连都要求完成回复包含有效的实际文件名。HTTP 200但完成信息缺失或无效时仍提示结果未知，不根据原文件名猜测上传结果、不自动重传。

它不能接管桌面、使用网页终端或修改配置，即使知道屏幕锁密码也不能解锁。临时账号看不到其他登录的映射或管理员保存的设备目录。文件中转是共同目录，管理员应只放准备共享的文件。每个文件最多 50 MiB；临时上传受目录 1 GiB / 1000 文件限制，同时最多一个临时上传，全局最多四个进行中的文件传输，每次最多五分钟。

临时账号的到期时间从每次保存开始计算。修改、续期或停用都会撤销旧临时登录及其映射，保存前有确认提示；管理员登录、任务和映射保留。临时登录最多四个，管理员登录最多八个，两个名额池独立。

## 映射方向与生命周期

受限页面允许的是 **服务器 → 本地设备**。例如本地助手可达路由器 `192.168.16.1:22`，配置服务器回环端口 `22001`；助手确认目标后，服务器上的 Codex 可通过 `127.0.0.1:22001` 访问它。服务器只监听回环，不向公网开放 TCP 端口。目标端口继续受 `TCP_FORWARD_PORTS` 限制。

配置并配对的映射绑定创建它的登录，与桌面控制权分开。锁屏、另一端登录、接管或关闭网页都保留原授权及现有 TCP 连接，包括锁定前已创建的正向映射。退出创建映射的登录、该登录到期/被淘汰、明确停止或临时账号撤销才会结束对应映射。

### 锁屏后全部保留

屏幕锁保护浏览器中的桌面和网页终端，**不撤销锁定前已经签发的双向端口映射授权**。“全部保留”同时适用于“立即锁定”、网页开启/修改锁密码触发的锁定，以及本页被另一端接管。

| 锁定时的状态或操作 | 规则 |
| --- | --- |
| 已启用的正向映射（本机 → 服务器） | 保留映射及正在传输的 TCP 连接；也允许通过该映射建立后续新 TCP 连接。 |
| 已启用的反向映射（服务器 → 本地设备） | 同样保留已有与后续新 TCP 连接。 |
| 已生成、尚未使用的配对码 | 在原来两分钟有效期内仍可配对原固定目标；锁屏不延长期限，也不会签发新码。 |
| 原授权处于断网恢复中 | 按原来 30 秒 / 最多八次握手的预算恢复同一映射，不要求先解锁。双方支持保活时，管理断线期间保留健康数据连接并暂停新连接；已失败 TCP 不迁移或重放字节/设备命令，旧版仍关闭旧 TCP 后恢复映射。 |
| 锁定页面新建正向映射、签发新码或管理正向映射 | 拒绝。解锁后才能查看/停止该方向的映射；运行助手的电脑仍可停止助手。 |
| 锁定页面配置反向映射、使用文件中转或查看连接状态 | 继续按原权限开放；临时账号仍只管理本次登录创建的反向映射。 |

例如锁屏前已授权 `本机 127.0.0.1:2222 → 服务器 :22`：锁屏后原 SSH 连接继续工作，还可以经这个端口重新连接 SSH；SSH 自身的账号认证照常执行。屏幕锁不会使该端口授权自动失效。

保留授权的前提仍是来源登录有效、助手按原规则运行。退出来源登录、登录到期/被淘汰、明确停止、对应临时账号撤销或面板重启，仍会结束映射。**后台重置命令需要停止并恢复面板，因此仍需重新配对**；这与网页内单纯锁屏不同。

面板重启仍会清除内存中的映射，需重新配对；它不会重启桌面或提交任何 Codex 输入。屏幕锁与账号设置持久化在私有 `data/panel/access.json`，最多 8 KiB、权限 0600；登录恢复后仍需重新解锁画面。损坏或权限异常时拒绝启动，不自动关闭锁。忘记锁密码时需由服务器主机用户维护此文件；不要把它、会话文件或账号密码提交到 Git。

升级会迁移原管理员登录，并为包含角色的新会话文件使用独立的凭据版本。回退到不识别临时角色的旧面板时，旧面板将要求所有人重新登录，避免把临时登录当成管理员。

## 后台密码重置

在服务器本机或 SSH 中进入项目目录，使用部署项目的普通用户执行，不要 sudo：

```bash
npm run reset-password
```

菜单可选择重置管理员密码、重设屏幕锁密码或关闭屏幕锁。也可直接指定操作：

```bash
npm run reset-password -- --admin
npm run reset-password -- --screen
npm run reset-password -- --unlock
```

管理员密码输入两次且不回显，长度 16–512 个字符，首尾不能有空白。屏幕锁密码为 4–128 个字符；`--screen` 会立即设置新密码并开启锁，`--unlock` 只关闭锁。两次输入不一致、Ctrl+C 或输入超时都会在开始提交前取消。不要把密码放在命令行参数中。

没有交互终端或希望自动生成管理员密码时：

```bash
npm run reset-password -- --admin --generate
```

新管理员密码写入 `secrets/panel_password`，并同步更新 `secrets/credentials.txt`，均为 0600；密码不会打印到命令输出。原管理员密码只是忘记时，也可直接在服务器查看现有的 `secrets/panel_password`，无需执行重置。

命令先收集并校验输入，再停止运行中的 `codex-cloud-panel.service`、写入配置、恢复面板并检查回环健康。仅操作与当前项目目录匹配的面板服务；其他部署、特殊文件或仍在监听的手动面板会阻止写入。原本停止或失败的面板保持原状态，需要时手动启动。桌面、终端宿主、管理器、Tunnel 和 Codex 任务不重启；现有端口映射仍会因面板停止而结束，需重新配对。

管理员密码重置会使旧登录失效，不改变屏幕锁或临时账号配置；忘记两种密码时需分别处理。屏幕锁重设/关闭保留管理员密码和临时账号配置。关闭锁后再次开启时，请填写新锁密码，留空会保留原来配置的密码。

维护锁固定为`data/panel/password-reset.lock`，0600、最多256字节。复用Python标准库flock，固定空inode是正常状态，不删除锁文件；活跃重置排斥并发，进程退出/被杀后自动释放，空锁和半截旧PID记录可恢复，完整活跃旧PID记录仍保守拒绝。不向其他重置进程发信号。写入前及改名提交前检查租约；租约丢失不继续改密码或与另一个维护进程争抢启动面板。管理员密码及摘要各使用一份固定`.reset.tmp`文件，内容上限分别为2 KiB / 4 KiB，0600，成功后原子替换并同步目录。写入失败时尽力恢复原来运行的面板，命令会报告可能已提交的修改；以`secrets/panel_password`为实际管理员密码来源，勿在结果未知时盲目重复操作。

重置命令以当前项目`.env`中的账号、入口和端口为准，不让旧Codex任务继承的部署变量覆盖配置；运行systemctl仍使用当前部署用户的正常进程环境。恢复检查不会因旧域名或旧端口误判。

## 验证边界

`access-control`、`access-policy`、`file-transfers` 和 `reverse-forward` 的 Node 测试覆盖持久化、权限隔离、撤销、并发边界及锁定/接管时真实 TCP/WebSocket 字节流继续传输。浏览器 `access.spec.mjs` 使用实际 Chrome、noVNC 和模拟 RFB/管理后端验证手机/电脑布局及完整登录流程；它不代替手机真机、真实 X11 桌面和公网网络验收。

同名冲突、版本变化、配额不足等明确业务拒绝只结束本次文件传输。新协议允许重建单个文件通道并保留服务控制peer，状态和映射管理不因这类错误切回HTTPS；同一时间仍只有一个文件通道，服务端结束等待最多3秒。未知结果、协议错误、授权失效与网络故障继续关闭对应连接，不重传文件内容。
