# 屏幕锁与临时访问

在已接管的工作台打开“工具 → 访问与屏幕锁”。桌面部署和纯网页终端部署都支持，默认不启用锁或临时账号。

## 屏幕锁

勾选开启，设置独立的 4–128 字符密码并保存。保存后当前页面也会锁定，需要重新输入。此后每次新页面登录、刷新页面或点击“在这里使用”接管时都需解锁；输入错误、取消或断线不会自动再次提交密码。当前页面可从工具中“立即锁定”。修改密码会撤销当前画面授权，关闭屏幕锁则恢复原有接管流程。

另一台电脑或手机登录时，原页面保持控制权，直到新页面正确输入屏幕锁密码。接管后旧页面的解锁授权立即作废，不能使用以前输入的密码自动抢回。锁同时保护桌面画面、网页终端、历史、剪贴板、输入及设置；任务仍由后台持有，不随锁定、接管或关闭浏览器结束。

锁定或被接管的管理员页面可以查看连接状态、使用文件中转，以及配置和管理“服务器 / Codex 访问本地设备”的反向映射。不能新建或停止“本机访问服务器网络”的正向映射，也不能读取或修改设备目录。

## 临时账号

管理员解锁并接管后，可启用一个临时用户名和 8–128 字符密码，选择 1 小时至 7 天的有效期，保存后复制本次账号密码给使用者。后端也接受五分钟起的有效期。只存加盐密码哈希，无法再次读出密码；需要重新复制时设置新密码。用户名使用字母、数字、下划线或短横线，并与管理员不同。

临时账号使用同一个登录界面，可进行：

- 查看连接状态。
- 创建、查看和停止本次登录创建的反向设备映射。
- 上传、下载共享文件中转目录中的文件。

它不能接管桌面、使用网页终端或修改配置，即使知道屏幕锁密码也不能解锁。临时账号看不到其他登录的映射或管理员保存的设备目录。文件中转是共同目录，管理员应只放准备共享的文件。每个文件最多 50 MiB；临时上传受目录 1 GiB / 1000 文件限制，同时最多一个临时上传，全局最多四个进行中的文件传输，每次最多五分钟。

临时账号的到期时间从每次保存开始计算。修改、续期或停用都会撤销旧临时登录及其映射，保存前有确认提示；管理员登录、任务和映射保留。临时登录最多四个，管理员登录最多八个，两个名额池独立。

## 映射方向与生命周期

受限页面允许的是 **服务器 → 本地设备**。例如本地助手可达路由器 `192.168.16.1:22`，配置服务器回环端口 `22001`；助手确认目标后，服务器上的 Codex 可通过 `127.0.0.1:22001` 访问它。服务器只监听回环，不向公网开放 TCP 端口。目标端口继续受 `TCP_FORWARD_PORTS` 限制。

配置并配对的映射绑定创建它的登录，与桌面控制权分开。锁屏、另一端登录、接管或关闭网页都保留原授权及现有 TCP 连接，包括锁定前已创建的正向映射。退出创建映射的登录、该登录到期/被淘汰、明确停止或临时账号撤销才会结束对应映射。

面板重启仍会清除内存中的映射，需重新配对；它不会重启桌面或提交任何 Codex 输入。屏幕锁与账号设置持久化在私有 `data/panel/access.json`，最多 8 KiB、权限 0600；登录恢复后仍需重新解锁画面。损坏或权限异常时拒绝启动，不自动关闭锁。忘记锁密码时需由服务器主机用户维护此文件；不要把它、会话文件或账号密码提交到 Git。

升级会迁移原管理员登录，并为包含角色的新会话文件使用独立的凭据版本。回退到不识别临时角色的旧面板时，旧面板将要求所有人重新登录，避免把临时登录当成管理员。

## 验证边界

`access-control`、`access-policy`、`file-transfers` 和 `reverse-forward` 的 Node 测试覆盖持久化、权限隔离、撤销、并发边界及锁定/接管时真实 TCP/WebSocket 字节流继续传输。浏览器 `access.spec.mjs` 使用实际 Chrome、noVNC 和模拟 RFB/管理后端验证手机/电脑布局及完整登录流程；它不代替手机真机、真实 X11 桌面和公网网络验收。
