# WebRTC 协议与连接恢复

本页面向开发与深入排障，保留候选过滤、输入不重发、连接交接与资源上限。部署参数和日常排障见[直连与中转](lan.md)，端口映射的独立协议见[映射协议](forward-protocol.md)。

自动发现接受私有 IPv4、普通公网 IPv4 / IPv6 的 UDP host 和反射候选，允许通过 STUN / ICE 打洞；未显式指定时丢弃运营商共享段和 ULA；仍丢弃未指定地址、链路本地、文档、基准测试、多播及保留公网 IPv4 候选。自建中心模式额外允许中心签发的 TURN 公网 IPv4 与 relay 端口范围。TURN 凭据、配置与强制 relay 验证见[自建中心](selfhost-server.md#turn)。`WEBRTC_STUN_URL` 仍只配置 STUN，不能把 TURN 凭据直接填进该项。

## 地址提示与接口选择

浏览器按节点身份保存“节点主机直连 IP”和“浏览器端 IP”；无身份的独立入口按节点子路径隔离。每项限 45 字符，接受私有 / 普通公网 IPv4、普通公网 IPv6，以及明确指定的 `100.64/10` 和 `fc00::/7` VPN 端点；不接受端口、域名、URL、链路本地或其他保留地址。前后端共享地址验证，Go 助手保持相同过滤边界；VPN 候选与实际探测来源只对相应已认证会话的显式 IP 放行。

`codex-cloud.rtc-hints.v2` 为同源内最多 64 KiB 的缓存，记录按最后保存时间保留最多 90 天，空间不足时淘汰最旧项，不限制节点目录数量。旧全站 v1 提示不自动归属节点，用户可手动导入。存储失败时当前页面仍可使用；旧标签页保存只合并自身节点，不能覆盖其他节点。

服务端用浏览器提示为 offer 补充候选，用节点提示为 answer 补充候选；每侧最多新增 4 个。共享助手池的最多 4 个提示地址轮流取得候选名额，再轮流补充第二个端口，保留原有最多 8 个自动候选和 ICE 凭据。候选去重且 foundation 不冲突；仅使用本轮收集的 UDP host 端口，明确地址不跨族拼接。mDNS 隐藏地址族时可尝试对应族的有效提示。

本轮节点提示属于本机网卡时优先选中该接口，每个地址族仍最多一个 host socket；有多个本机提示时选择该族第一个匹配项。其他提示作为外部别名，沿用真实收集端口。显式 IPv6 本机配置也接受已分配的 ULA。提示不修改持久配置、路由、防火墙或 NAT 端口，地址到 socket 的实际路径仍须存在。

“保存”仅更新后续协商快照；“保存并重新探测”允许在健康 RTC / TURN 上验证新候选。每次最多一个候选、26 秒期限、无请求队列。候选先完成 ICE / DTLS、三次独立心跳和路径质量比较；等待输入与桌面操作空闲后，统一会话经健康 WSS 备用替换同类 RTC，再复用原上游与渲染器。备用不健康时延后，失败继续可用路径，输入与审批不重放。

受限服务同一 viewer 可有一个受限候选，与现有连接合计仍受每登录 2 个、每角色 4 个、总计 8 个 peer 上限约束。候选仅允许 ping 和固定 promote；提前打开文件通道关闭该候选。服务端候选最多保留 26 秒，客户端等文件与在途 RPC 完成后才 promote，再关闭旧 peer。实际端点来自选中 candidate pair；端点一致不声称一定由提示促成，浏览器隐藏时显示无法确认。

### 服务器部署参数

默认启用，可在 `.env` 中关闭或明确指定本机接口：

```dotenv
WEBRTC_ENABLED=1
# 可选；不填时优先选择默认路由网卡上的可用 IPv4，找不到则按网卡顺序选择。
WEBRTC_LAN_ADDRESS=192.168.16.224
WEBRTC_IPV6=1
# 可选：固定本机已分配的普通公网或 VPN IPv6。
# WEBRTC_IPV6_ADDRESS=你的公网IPv6
WEBRTC_STUN_URL=stun:stun.cloudflare.com:3478
# 可设为空字符串关闭 STUN；只支持单个 UDP stun: URL。
```

多网卡、VPN 或容器网桥环境可以明确指定 LAN 地址；必须是本机已分配的私有、普通公网或运营商共享 IPv4。不指定时，每次协商重新选择当前接口，以适应 DHCP 地址变化。Linux 优先从有效默认路由中按 metric 选择有私有或普通公网 IPv4 的网卡；默认路由不可读或无可用接口时，回退到网卡顺序，最后使用回环。明确指定后则需手动更新配置并重启面板，建议在路由器预留地址。主机本身的浏览器也可连接该 LAN 地址。

Windows 本机浏览器连接 WSL 镜像网络是一个例外：通过宿主机局域网 IPv4 访问 WSL 需要 `.wslconfig` 的 `[experimental] hostAddressLoopback=true`，否则可能回环 UDP 正常、局域网 IP 的 UDP 超时。部署会识别并自动补齐该项、保留备份，配置需重启 WSL 后生效；只读检查和排障步骤见 [WSL 部署说明](wsl.md)。

WebRTC 仅在协商时绑定所选 IPv4/IPv6 地址的 **UDP 40000–40015**，每个 peer 至多两个 host socket，不监听公共 TCP VNC 端口。公网 IPv6 需要主机和路由器允许相应 UDP 入站，或允许 ICE 双向出站探测建立回复状态；本项目不自动修改防火墙。IPv6 不需要 NAT 端口映射，但仍可能被运营商或防火墙阻止。浏览器 mDNS 解析可能使用 UDP 5353，STUN 发现需要访问所配置的 UDP 服务。面板和 helper 仍仅监听回环，VNC 仍为私有 Unix socket，Tunnel 的 IPv6 优先策略保持原状。

IPv6 默认优先选择与 LAN IPv4 同一网卡上的一个公网地址，没有可用地址时保留 IPv4；未固定地址时每次协商重新选择。`WEBRTC_IPV6=0` 关闭公网及 VPN IPv6。普通公网 IPv6 限于 2000::/3，并排除文档、6to4、2001::/23 等特殊范围；ULA、链路本地、scope ID、映射地址和组播不作为公网候选。固定地址必须已分配给本机，地址变化后需更新配置并重启面板。

STUN 只发现地址，不转发桌面数据；默认服务为 Cloudflare 的 `stun:stun.cloudflare.com:3478`，配置不接受 TURN、凭据或查询参数。浏览器、节点和端口映射助手都使用显式配置的 STUN 发现 NAT 映射，需要允许向该服务发送 UDP 并接收响应。本机绑定地址不能替代公网 NAT 映射的发现。空配置会清除固定依赖的隐式默认 STUN；发现超时后仍使用已收集的 host 候选，不阻塞现有 LAN 连接。[Cloudflare STUN 文档](https://developers.cloudflare.com/realtime/sfu/get-started/connection-patterns/)

TURN 凭据在节点内存中保留一份，每次至多一个刷新请求，失败后退避 15 秒。状态查询只读取尚有效的缓存并触发后台刷新，不等待中心接口；登录、配置读取与新协商可等待有界刷新。浏览器保留凭据有效期，新协商前在剩余不足 30 秒时重新读取配置，不将过期凭据交给新 peer。刷新配置不重建健康的连接，也不重发输入。

依赖由锁文件固定；在隔离开发目录安装依赖，活动部署按[维护指南](operations.md)更新。仅修改网络配置时重启面板：

```bash
systemctl --user restart codex-cloud-panel.service
```

关闭直连时设置 `WEBRTC_ENABLED=0` 并重启面板。桌面、tmux 和 Codex 会话独立运行。

## 认证与资源界限

协商接口要求有效登录、Host、Origin、CSRF 及当前页面控制权。延迟请求体、协商过程中发生接管或退出均不能获得旧控制权。WebRTC 与 WebSocket 共用单一画面连接、退出、登录到期、接管和桌面维护的关闭机制；数据转发前再次检查授权，不将 Cookie 或 CSRF 发给 VNC。

只接受一个 data m-section、有 SHA-256 指纹的 SDP；请求体最多 48 KiB，输入 SDP 最多 32 KiB，最多保留 8 个去重自动 UDP 候选，在局域网 IPv4、NAT IPv4、IPv6 和受信 TURN 之间轮流保留名额，避免多网卡挤掉反射或中继候选；可选地址提示另补最多 4 个候选，浏览器目标合计最多 12 个。允许私有 / 普通公网 IPv4、mDNS host、IPv4 srflx，以及启用 IPv6 时的普通公网 IPv6 host/srflx；去除 remote-candidates。候选配对及实际探测来源再次过滤，拒绝特殊 IPv4 / IPv6，公开地址也必须通过本轮 ICE 凭据和加密指纹验证；自建中心模式只额外接受已签发 TURN 响应允许的 relay 地址与端口。桌面连接只允许各一个可靠、有序的 `codex-vnc`、`codex-control` 和 `codex-health` 数据通道；文字终端连接用独立的 `codex-terminal` 取代 VNC，不接受媒体或任意代理目标。兼容没有心跳通道的旧桌面客户端，主动心跳需刷新页面加载新版本。

公网 UDP 接收入口在固定版本 ICE agent 处理消息前验证会话、原始 STUN HMAC 与双方 ufrag，拒绝无凭据探测和未知端点的数据。每个 peer 的检查限制为每秒窗口 64 次、STUN 报文 2 KiB、最多 16 个已认证来源及 16 条 early checks；不写入日志或磁盘。

浏览器隐藏的 `.local` 候选通过所选 LAN IPv4 接口进行 mDNS 查询。每个桌面/网页终端 peer 最多一个按需创建的 UDP 5353 socket、8 个名称；每个名称最多查询两次，保留原有的 10 秒解析期限，允许 mDNS 不可达时浏览器主动发起已认证 ICE 探测。解析在回复的前 64 条 answer/additional 记录中查找匹配名称，优先取有效私有 IPv4，开启 IPv6 时也接受普通公网 IPv6；忽略无关名称、过期/goodbye 记录及不允许的地址。连接关闭立即取消等待并释放 socket，没有磁盘缓存。直接使用已锁定的 `multicast-dns@7.2.5`，不修改 werift 安装文件。

控制通道分派 `paste`、`key`、`clipboard` 三种固定业务动作，以及仅用于连接探测和启用的 `ping`、`activate`，每次处理前校验会话和页面认领对象，读取返回前再次校验。沿用私有管理 socket、输入互斥锁、文字 32 KiB 上限、固定快捷键及独立 Enter。请求 ID 单调递增，重复、并发或无权限的消息关闭控制通道，不重复执行。控制请求发出后，即使断线、超时或页面切换，也不会换成 HTTP 重发；后续新的明确操作才可使用 HTTP 回退。

控制 JSON 记录最多 256 KiB，按最多 16 KiB 二进制消息分块，单个长度前缀限定接收缓冲；每端仅一个待完成请求，发送缓冲上限 512 KiB，客户端等待最多 8 秒。取消读取会关闭控制通道并丢弃迟到结果；观看连接仍可继续，后续操作可走 HTTPS。iframe 消息同时验证来源、父窗口、页面代次及请求 ID；正文只暂存在请求和预览中，不写入浏览器存储或服务日志。

心跳使用 `codex-health-v1` 协议，只回显 4 字节大端单调 nonce（1–2147483647），不接受业务动作。每次验证原有会话、页面认领及连接对象；无权限、重复/无效 nonce、错误长度或每秒窗口超过 8 次均关闭连接。发送缓冲上限 4 KiB，每端最多一个待完成检查，无队列或历史。心跳与正在进行的粘贴/按键互不占用请求槽；取消旧检查后，迟到回复被忽略，不能满足下一次检查。

每次仅一项协商，最多一个活动 peer 与一个候选 peer。候选等待激活最多 26 秒；候选不连接 VNC，也不能执行输入或读取剪贴板。通过加密控制通道确认并启用时，先关闭旧观看连接，再允许新 VNC 连接；启用后连接 VNC 最多等待 5 秒。活动连接受登录有效期约束。消息最多 64 KiB，画面切为 16 KiB 消息，应用发送高水位 256 KiB，暂停读取上游形成背压；终端方向超过 256 KiB 就关闭连接，不排队重试。没有新增持久化证书、SDP、候选缓存、终端内容或连接日志。

新画面通道使用 `rfb-ready-v1`：noVNC 挂好事件处理器、通道打开后，客户端只发送一次固定的单字节 `0`。服务端消费该字节，且确认候选已启用、画面通道已打开后才连接 VNC；就绪字节不转发给桌面，格式错误则关闭连接。这样避免 VNC 首包早于浏览器 open 通知而造成初始化失败。它沿用原来的 5 秒启用期限，不增加缓冲或重试。旧 `rfb` 协议保持兼容，刷新后才使用新握手。

## 持续探测与自动切换

统一会话模式下，中转与直连并行建立，保留同一上游与渲染器。新客户端通过候选直连发送带连接代次、输出位置和已确认输入序号的 `prepare`，由服务器暂停旧通道输出，再经同一直连提交 `activate`；不等待慢中转的确认。暂停租约最多 2.5 秒、每会话仅一个，取消、超时、候选断开或撤权即释放。代次切换后，旧通道迟到的数据不能执行输入；新通道只补发未确认的输出，不重发输入。提交前失败保留可用旧连接，提交结果未知时重新核对流状态。旧服务器未声明支持时保留原交接方式。

中转建立后首次等待 15 秒探测；失败后按 30、60 秒退避，随后持续每 60 秒检查。一次只运行一个探测，没有队列。网络恢复、浏览器连接类型变化或页面重新可见时，会将下一次检查提前到约 1 秒；正在进行的探测仍保持单一。隐藏页面或离线时暂停新探测，恢复可见后继续。直连画面正常但控制通道已关闭时，也可用同一机制修复输入助手路径。

候选建立加密控制和只读心跳通道，尚不建立画面通道；完成两次控制 `ping`、间隔 500 毫秒，证明实际 DTLS 通道可用。探测失败不关闭旧 WebSocket，也不创建额外 x11vnc 观看进程。准备切换时，等待输入、剪贴板读取和桌面操作空闲，且没有按住键或指针；原生交互结束后至少空闲 800 毫秒。剪贴板预览窗口打开时也会延后。

父页面确认空闲后，短暂暂停新输入，再请求服务端启用候选。服务端重新检查会话、控制权与管理服务状态，确认空闲后才接替旧画面。新画面仍使用原分辨率、缩放、拖动与折叠设置，并恢复本地滚动位置；父页面和输入草稿保留。候选失败继续原路径；如果旧路径已经关闭，则重新连接画面。自动切换不发送登录、接管、粘贴、Enter 或审批，也不重发结果未知的操作。

切换确认最多等待 2 秒，父页面的输入暂停保护最多 15 秒。任何接管、退出、登录到期或桌面维护都会关闭候选；过期协商不能替换新页面的连接。这里只切换画面和控制通道，不重启 Xvfb、tmux、Codex 或 Tunnel。

## 直连失效后的快速回退

前台心跳通常每三秒检查，新路径先做三次有界预热。统一流、网页终端及受限服务按近期 RTT 和波动计算 2–6 秒期限，近期较慢样本也会抬高预算；没有健康备用路径时，统一流和网页终端对第一次迟到再用新 nonce 复核一次，复核期限 1–2 秒，不重发旧探测或业务输入。统一流在复核期间暂停输入；收到新回复恢复，旧回复不能解除暂停。有近十秒内确认健康的备用路径时可直接回退，明确的连接关闭/ICE 失败也不等待复核。受限服务对首次心跳超时再检查一次。网络事件不会不断延后在途检查；返回前台后必须取得新回复才能解除既有心跳暂停。旧版桌面查看器仍按原路径恢复。

统一 RTC 会话通过独立 `codex-health` 通道探测；服务端将画面发送纳入有界公平队列，为心跳和控制保留准入空间。统一 RTC／WSS 和助手 RTC 在本次探测开始后仍收到有效数据进展时，只额外宽限一次四秒；静态队列、旧数据或网络事件不能触发续期。每次探测最多十秒，复核最多六秒，之后仍按故障回退；数据持续流动也不能无限推迟缺失心跳的检测。这些是检测预算，公网握手、画面准备与浏览器事件循环另计，集成测试按完整预算加传输余量验收。

隐藏或离线时暂停并取消在途心跳，不因该状态本身关闭现有直连流。恢复前台/在线后用新 nonce 检查，旧网络的迟到包不能通过新检查。多个事件只保留一个检查定时器；新的网络检查开始后，后续 RTT/带宽估计等事件不再取消或延后本次检查的期限。退出、接管、卸载或连接换代取消旧检查。中转连接也在可见且在线时恢复，不累计离线重试。

失效回退会明确将正在等待的输入标为结果未知，随后只重建观看流；不等待输入结束，也不再次提交已发送的业务操作。保留草稿、缩放与本地滚动位置，原桌面任务继续运行。中转建立后仍按上述策略检查并恢复 LAN，不增加新的中转服务。

## 已直连时的状态与终端切换

统一会话模式的已激活直连可查询面板状态和终端目录。它们使用现有 DTLS 数据流中的固定消息，不是任意 HTTP 代理；仍按最初通过 Host、Origin、CSRF 和登录验证的页面身份，在每次处理前后复核当前控制权。只允许活动直连查询，候选和备用中转不能借此读取信息；锁屏、退出、登录到期或接管使旧通道失效。

每条活动路径最多并行两项只读查询（状态、终端目录各一项），每秒最多八次，单响应最多 16 KiB。浏览器每项最多等待五秒，迟到结果按请求 ID 与连接代次丢弃，不占用粘贴/按键的请求槽。连接状态中的面板路径显示“可访问（加密直连）”；HTTPS 查询失败不会覆盖这条已验证的直连状态。文件、账号/锁配置、重命名终端及端口映射管理仍按各自原有路径处理。

统一终端流另以 `terminalCreate` 声明新建能力，活动直连和活动 WSS 均可执行固定的 `create-terminal` 请求。只接收名称和可选固定名额，请求最多 1 KiB，每流最多一项创建、不排队，共享每秒八次与响应 16 KiB 的限制；客户端最多等待 6.5 秒。创建中不提交路径或目标切换；响应丢失、超时、管理器结果未知或撤权均不通过 HTTPS 重发。确认创建后用返回的槽位和 pane token 复用现有连接切换，不能立即切换时保留原目标并明确提示已创建，用户可从列表选择。旧后台未声明创建能力时只发一次 HTTPS 创建，再按其已有切换能力附加。

网页终端标签切换优先复用当前 iframe、WebRTC peer 和统一会话，不重新下载界面或通过 CF 协商。服务器校验目标槽位和 pane token、确认输入已结束，再结束旧查看连接并附加新目标；原 tmux/Codex 任务继续运行。旧查看器的迟到输出不能进入新终端，旧的终端心跳和历史读取随切换释放，草稿继续按终端身份隔离。备用中转按新目标在后台重建。

切换每会话最多一项，确认最多八秒；输入未确认、目标身份变化或服务繁忙时保留旧目标，不排队稍后再切。结果未知时停止当前查看并要求重新选择，不自动重发切换或输入。旧服务端没有声明此能力时，仍使用原界面重连方式。

首次直连复用当前登录页取得的 WebRTC 配置与 CSRF，配置只在内存中保留，退出后清除；没有有效配置时才补取认证信息。地址收集最多等待 1.5 秒，创建/收集阶段另有三秒保护；HTTPS 信令和 ICE/DTLS 建连分别有十二秒期限，不再共用一个总期限。服务端候选等待激活最多 26 秒、激活后的画面就绪最多五秒；统一终端首次附加最多 45 秒，可用中转仍先显示。首次加载、登录及没有现成直连时的信令仍需要 HTTPS，未增加新的直达网站入口。

## 中转模式下的终端切换

统一会话的活动 WSS 连接也支持切换已有网页终端。页面保留同一个 iframe 和 WebSocket，经当前已认证连接发送一次固定目标切换消息；服务端沿用槽位、pane token、当前控制权和输入空闲检查，仅更换查看目标，不重启 tmux/Codex 任务。原 Host、Origin、Cookie 和 CSRF 认证不变，候选和备用路径不能切换目标。新能力单独声明，旧服务端未声明时沿用原页面重连方式。

切换沿用最多一项、确认八秒、结果未知需手动选择的限制；草稿按终端身份保留，旧输出、历史读取和终端心跳释放，输入不自动重发。已确认目标在当前会话内保留，WSS 短暂断线后附加同一目标；网页刷新后仍重新校验保存的目标身份。此功能不增加后台终端的常驻查看连接，也不缓存各终端最后画面。

切换前取消针对旧目标的直连探测，切换结束后继续按当前目标探测；主动取消不增加探测退避。服务端对尚未附加统一会话的 RTC 候选复核目标身份，拒绝旧探测的迟到启用。后续可升级直连，直连失效仍可回到保留的中转连接。中转下状态和终端目录查询继续使用 HTTPS；新画面到达时间仍取决于 CF 链路。

## 网页终端协议

统一会话为 WSS 和 WebRTC 分别保存平滑延迟与有界预热计数，至少两次观测后开始比较，十秒未更新则失效，连续两次比较支持同一选择后才计划切换。延迟相近时优先直连；TURN 升级需至少降低 20 ms 或 20%，从直连回到 WSS 需至少降低 40 ms 或 35%（各取较大门槛）。计划切换仍受输入空闲、确认边界和 30 秒冷却约束，健康备用连接继续保留；当前路径失效时立即按健康备用恢复，不等待质量比较。首次连接尚无可比较样本时先使用已就绪路径。

常驻助手的共享 peer 对下一条 TCP 使用同样的直连／WSS 延迟门槛、连续比较和冷却期。已有 TCP 保留原路径，健康但暂未被选中的 RTC 不重复协商；WSS 不可用时允许新连接使用健康 RTC。诊断会说明因中转延迟更低而选择 WSS，不将其当作直连故障。

网页终端也使用同一套 IPv4/IPv6 候选、HTTPS 指纹认证与 DTLS 加密。`/api/terminal/rtc` 必须携带当前终端槽和 pane ID / PID token，并在启用时重新校验；专用 `codex-terminal` / `terminal-v1` 通道传输原有终端 JSON，记录最多 256 KiB、按 16 KiB 分块，沿用 PTY 背压、固定按键、保护粘贴与独立 Enter。该连接的控制通道只接受 `ping` 和 `activate`，不执行桌面输入；探测及未启用通道不附加 PTY。浏览器安装收包器并发送固定单字节 `0`、服务端确认启用后，才连接原有 tmux 任务。

文字终端直连失败回退现有 WSS，中转期间按 15/30/60 秒持续探测，网络变化后约 1 秒提前探测。切换前还需结束中文组合输入、释放按键和指针、最近 800 毫秒没有交互，且父页面没有输入、确认框或其他阻塞操作；服务端也要求旧终端在途请求已清空。启用失败保留仍可用的旧流，失效输入标为未知且不补发。前台应用心跳使用上述自适应期限和一次复核；隐藏时暂停，离线主动释放附加客户端，上线后先恢复 WSS 再探测直连，原 tmux 任务保持运行。连接诊断同时显示文字终端实际路径、延迟与回退原因。

## 协商错误分类

协商重试按错误分类：429 繁忙从约 0.5 秒起退避，最多五秒；临时协商/网络失败按约 15/30/60 秒带少量抖动退避。401/403/423 权限、409 目标身份、400 参数协议或未启用等错误停止本查看作用域的自动探测，原可用中转继续工作；重新登录、接管或明确切换到新终端后重新初始化。外层登录跳转不自动跟随，不将认证页面当作 SDP。创建/关闭、粘贴、Enter 等写入不因错误分类而重试。

## 连接通知边界

手机终端仍可压缩正常连接标记；等待网络、服务中断、连接复核、恢复及结果未知时，在画面上方显示短文字提示，保持原画面和本地历史可读，不改变终端行数或工具栏高度。未知结果区分输入助手的具体操作、桌面或网页终端通道、后台待命视图及执行服务历史状态。通道记录可能包含心跳、尺寸调整等协议消息，不能仅凭通道异常判断提示词或 Enter 是否执行。右侧“×”可收起当前提示；同一事件在本页轮询、重连和切换视图后不会重弹，新事件仍会提醒。收起不代表执行成功，不会解除输入限制或补发输入；输入助手的新反馈也不会清除旧告警。连接状态中的“操作与通道提示”保留来源、原因、当时路径及收起状态，仅本页内存最近 32 条，退出后清空，不记录输入内容或异常原文。恢复正常后收回普通提示，未知结果不因恢复连接自动清除。仅关闭按钮接收指针，其余提示区域保持穿透；原有输入权限和暂停规则保持。
