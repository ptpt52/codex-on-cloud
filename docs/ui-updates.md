# 前端资源热更新

面板已经升级到支持热更新的版本后，文案、样式及与当前后台兼容的前端脚本可由部署用户执行：

```sh
npm run reload-ui
```

命令只访问 `data/panel/ui-reload.sock`，不重启任何服务、不改变登录或映射授权。此目录 0700、接口 0600，只接受固定维护动作；公网面板没有更新接口。旧版面板没有此接口，首次安装该能力需要正常重启一次面板，当次映射仍需重新配对。命令找不到接口时直接失败，不会给旧进程发送信号。

完整固定资源集经过文件类型、大小、JS 语法、模块路径及重复读取一致性检查后，原子发布一个版本。加载失败、文件缺失、资源仍在写入等情况保留上一版；新模块路径或后台 API 变化需要配套升级后台。此命令不构成后台代码热更新。

HTML 用带 CSP 哈希的 import map 锁定模块版本；CSS、普通 script 和后续打开的桌面/终端 frame 也携带原页面版本。已有页面与输入不会自动刷新，新开或手动刷新的页面取得新版本。页面每分钟前台检查一次版本，只显示更新提示。库资源使用当前安装的精确固定依赖，不在热更新中升级。

每文件最多 4 MiB，每版本原始资源最多 16 MiB，最多保留四个版本（含当前版），最多一个更新任务；固定集还会有转换和暂存内存。连续发布超过四版后，已淘汰页面再请求旧资源返回 410，需要保存草稿后刷新；正在运行的已加载画面不会因此被主动关闭。离线缓存只包含公开页面壳、最多四个资源缓存，认证、终端、桌面、文件与 API 不缓存。面板重启后内存旧版本清空。

超时可能是结果未知，命令不会自动重试。检查本机面板和 `/ui-version` 返回的资源版本后再操作。尚在使用的前端应保留后台协议兼容性；更新前运行项目测试。

## 手机画面宽度与矮窗口

电脑上的终端标签按顺序显示能放下的部分，右侧“更多终端”只列出溢出项；窗口变宽后自动恢复更多标签。如果当前终端位于下拉中，入口显示其名称和选中状态，长名称也保留下拉箭头。列表保留切换、新开和终端操作入口。手机继续使用完整终端列表和当前终端操作按钮；布局变化只改变显示方式，键盘焦点随入口移动。

终端标题单击切换，原关闭按钮的位置改为始终可见的“⋯”，菜单提供“重命名”和“结束终端”；电脑右键或键盘菜单键／Shift+F10 打开同一菜单。菜单及触控按钮至少 44px 高宽，结束操作保留二次确认。重命名使用保存／取消弹窗，名称为 1–24 个字符；回车保存、Esc 取消，中文输入法选词期间的回车不会保存。改名同步标签、下拉列表和终端管理，刷新后保留，当前选择和草稿继续保持；保存响应丢失时提示结果未知并禁止重复保存，可取消后手动刷新核对。

手机宽度（不超过700 CSS像素）移除工作区两侧固定留白、画面卡片侧边框和圆角，让桌面和网页终端用满可用屏宽；保留刘海安全区。门户节点按钮可随剩余宽度收缩，最小触控宽度44px，320px窗口也不把整页撑宽。电脑和平板宽屏保留原有水平边距。

各屏幕的底部说明栏压到约18px，移除额外底部外边距，保留设备安全区；矮横屏继续隐藏说明栏。网页终端不再强制最小240px高度，随浏览器剩余空间收缩，避免顶部控件和终端一起把页面撑高。显示区域变化可以调整终端行列，不创建任务或发送输入。浏览器双指缩放继续保持原生行为，不禁用缩放。

这些调整属于兼容的前端热更新，执行`npm run reload-ui`后手动刷新页面生效；不会重启面板、桌面或端口映射。

## 新建终端复用当前连接

统一终端流支持在当前已认证的 WebRTC 或 WSS 通道中创建 shell。新建成功后复用同一查看连接切换到新终端，保留原终端进程和草稿，不重新加载终端 frame，也不为当前直连重新交换 SDP。切换目标后，后台备用通道仍按原规则为新目标重建；这不重建当前使用的直连。

创建只接受终端名称和可选的固定名额，沿用当前登录与查看控制权、终端数量和名称限制。每流同时最多一项创建、请求最多 1 KiB、响应最多 16 KiB；创建进行中不提交路径或目标切换。创建回复丢失、超时或连接断开时提示结果未知，不改走 HTTPS 重试，也不重新配对或发送输入。确认已创建但查看切换暂不能完成时保留原查看，可从列表选择刚创建的终端，不重复新建。

此优化包含后台协议变化，需要升级面板后台；仅热更新前端不能启用通道内创建。新前端遇到未声明创建能力的旧后台时，仍只通过 HTTPS 创建一次；旧后台支持终端切换协议时，创建后也能复用原查看连接。现有传统终端通道继续沿用原创建流程。

## 文件服务与旧宿主迁移

新安装由 `codex-cloud-files.service` 独立运行 `native/file-agent.mjs`，仅监听回环 `FILE_AGENT_PORT`（默认跟随 `AGENT_PORT`，36902）。文件服务只处理文件，不查询 Codex 或访问 X11；桌面和纯终端宿主都不再启动 Python 助手。它退出、无法启动或重启，不会停止已有任务。管理服务通过独立显示/私有 tmux 探测宿主健康；`/readyz` 同时检查宿主与文件协议，不把缺少文件服务的部署报告为成功。

`native:install/start/status/stop` 已纳入独立文件服务。服务失败每60秒最多启动3次，间隔5秒；日志沿用 journald，包装进程每30秒最多输出32 KiB。助手继续使用12个并发线程、单上传互斥、50 MiB单文件和临时账号配额。Python 子进程观察私有父管道，包装进程异常退出后也会结束。

旧宿主仍把旧助手作为关键子进程，不能结束它来加载更新。保留任务升级时先选择独立空闲端口（例如36904），在 `.env` 写入 `FILE_AGENT_PORT=36904`，运行 `npm run deploy`。安装器发现活动旧宿主且未分离端口时会在写 unit 前拒绝升级；不会自动改端口、重启宿主或终止任务。部署会更新文件服务、manager、panel，面板重启后映射需重新配对。旧助手继续保留直到任务已保存、宿主自然进入维护窗口。

已部署的 `# Managed migration for codex-on-cloud file helper` 迁移 unit 和面板端口 drop-in 原样保留，不覆盖、不强制 enable。其旧 `PartOf=panel` 关系继续有效；新安装的正式服务独立启用。维护窗口后可以改用正式 unit，但独立文件服务本身继续保留。不得把真实 unit、路径配置、运行状态、密码或密钥提交到 Git。

部署就绪检查默认读取当前 `.env`，避免旧任务 shell 继承的 `PUBLIC_ORIGIN`、`PORT`、助手端口导致已成功部署却被误判失败。systemd drop-in 的端口仍应与持久配置保持一致。已有活动 Tunnel 改入口时，先确认私有 socket 的 `/readyz` 成功，再修改远端路由，最后核对公网版本；不要为了重跑检查反复重启面板。
