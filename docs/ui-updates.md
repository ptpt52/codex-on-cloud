# 前端更新与版本配套

日常升级使用[维护指南](operations.md)中的 `git pull --ff-only` 与 `npm run deploy`。只有静态界面变更时，可以只发布前端：

```sh
npm run reload-ui
```

命令通过本机私有接口校验完整资源，再切换前端版本。不重启任务宿主，也不要求立即重载用户正在操作的页面。网页显示更新提示后，先保存草稿再手动刷新。

## 如何选择更新范围

只有 HTML、CSS 和浏览器脚本变更时使用上述命令。后端、权限、协议、文件服务或助手代码变化时，按[更新范围表](operations.md#更新项目)部署相应服务，不能只刷新网页。

前端热更新不会让旧后端获得新能力。desktop / terminal 宿主的更新另行安排维护重启；保留锁定依赖，不通过自动升级浏览器库或修改 Codex 配置恢复服务。端口映射助手的 exe / ZIP 也需要重新构建、下载，网页更新不会替换客户端。

收到草稿保存失败提示时，先手动复制文字；当前版本不能保证存储失败时阻止刷新或节点导航，见[浏览器存储](browser-preferences.md#刷新多个页面与存储失败)。

## 文件服务与旧宿主迁移

新部署使用独立文件服务。旧宿主迁移时，先安装并验证新 files 服务，再让 panel 使用空闲的 `FILE_AGENT_PORT`；不通过重启任务宿主完成迁移。配置含义见[配置参考](deployment-config.md)，失败时按[服务恢复](reliability.md)处理。

Service Worker 只缓存公共界面资源，不缓存认证 API、桌面画面或文件。旧页面与资源版本有界保留；无法加载原版本时提示保存草稿后刷新，不自动重发输入。
