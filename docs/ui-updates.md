# 前端更新与版本配套

日常升级使用[维护指南](operations.md)中的 `git pull --ff-only` 与 `npm run deploy`。只有静态界面变更时，可以只发布前端：

```sh
npm run reload-ui
```

命令通过本机私有接口校验完整资源，再切换前端版本。不重启任务宿主，也不要求立即重载用户正在操作的页面。网页显示更新提示后，先保存草稿再手动刷新。

## 如何选择更新范围

只有既有 HTML、CSS 和浏览器脚本内容变更时使用上述命令。后端、权限、协议、文件服务或助手代码变化时，按[更新范围表](operations.md#更新项目)部署相应服务，不能只刷新网页。

开发者新增浏览器模块时，还需登记 [UI 资源白名单](../panel/ui-assets.mjs)和[离线 shell 清单](../panel/public/sw.js)，并检查模块依赖与离线加载。白名单属于后端代码，旧 panel 不会靠 `reload-ui` 自动获得新增项，应按正常部署更新 panel。资源缺失或模块校验失败时保留原版本，不以浏览器刷新代替修复。

前端热更新不会让旧后端获得新能力。desktop / terminal 宿主的更新另行安排维护重启；保留锁定依赖，不通过自动升级浏览器库或修改 Codex 配置恢复服务。端口映射助手的 exe / ZIP 也需要重新构建、下载，网页更新不会替换客户端。

前端资源版本、Git 提交和助手构建版本分别核对；仅文档更新不需要重新部署或重建助手。部署的完成标准见[共用检查清单](deployment-checklist.md)。

收到草稿保存失败提示时，先复制或导出文字，再确认离开；原生刷新／关闭提示受浏览器限制，见[浏览器存储](browser-preferences.md#刷新多个页面与存储失败)。

## 文件服务与旧宿主迁移

新部署使用独立文件服务。旧宿主迁移时，先安装并验证新 files 服务，再让 panel 使用空闲的 `FILE_AGENT_PORT`；不通过重启任务宿主完成迁移。配置含义见[配置参考](deployment-config.md)，失败时按[服务恢复](reliability.md)处理。

Service Worker 只缓存公共界面资源，不缓存认证 API、桌面画面或文件。旧页面与资源版本有界保留；无法加载原版本时提示保存草稿后刷新，不自动重发输入。

带 `ui` 版本的公共脚本、样式等静态资源允许浏览器私有缓存一天；noVNC 使用预生成的单个模块，减少桌面首次加载时的请求链，并随 UI 版本缓存。HTML、API、文件与 Service Worker 脚本仍禁止 HTTP 缓存。不带版本的资源不使用这一缓存策略；节点子路径与根路径的模块导入都绑定到该页面的同一 UI 版本。

修改 noVNC 版本或构建入口后，开发者先按锁文件安装依赖，再执行 `npm run build:novnc`，同时提交 `panel/public/vendor/` 中的包、输入哈希清单与上游许可记录。`npm test` 会重建并比较产物，检查固定依赖集与大小上限。部署直接使用已提交产物，不在运行时启动编译器或更新依赖。此包只含库代码；认证 API、画面和输入仍走原有受保护通道。首次加入资源白名单需要正常更新 panel。
