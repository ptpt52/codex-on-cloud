# Windows TCP 端口映射助手

助手提供通用 TCP 字节转发，适用于 SSH、数据库和其他 TCP 客户端。网页负责发放一次性授权，助手通过原有网站的 WSS 入口进行管理和加密协商，TCP 数据优先通过局域网或公网 IPv6 的 WebRTC / DTLS 加密直连传输，不可用时使用 WSS 中转。映射授权绑定创建它的登录，独立于桌面控制权；刷新、关闭网页、切换桌面/终端模式或其他页面接管均保留现有 TCP 连接。不支持已有 TCP 连接跨通道续传。

## 使用

1. 登录工作台，在标题栏打开“端口映射”，下载适合 Windows 电脑架构的助手。大多数电脑选择 x64；Windows ARM64 设备可选择 ARM64。
2. 填写 Windows 本机端口，例如 2222；从列表选择服务器目标端口，例如 22，点击“生成一次性配对码”。
3. 双击运行下载的 exe，将配对码粘贴到助手窗口，回车确认。配对码有效期两分钟，只能使用一次。
4. 显示“映射已开启”后，将原有软件连接到 Windows 的 127.0.0.1 和本机端口。例如 SSH：

       ssh -p 2222 用户名@127.0.0.1

两个回环地址分别指 Windows 和 Linux 服务器。服务器目标固定为服务器自身的 127.0.0.1；不接受网页指定任意主机。服务仍需在目标端口监听，SSH 或数据库登录由原客户端和目标服务处理。

保持助手进程运行。Ctrl+C、关闭助手窗口或网页中“确认停止”可结束映射。退出创建映射的登录、登录授权到期或被撤销、网关更新或连接断开也会结束映射；不会重新配对、重新连接目标或重放 TCP 数据。新连接可以在同一活动映射下正常建立。

这是单用户项目，所有有效登录均可查看和明确停止映射，无需先接管桌面；另一个设备登录或退出它自己的登录不会影响已有映射。退出原登录或登录数量上限淘汰了原登录时，其创建的映射仍会撤销。更新后请重新下载 0.2.0 版本助手。旧版助手仍可使用 WSS，但不会启用直连。

## 直连和中转

使用同一个 HTTPS 网站和配对过程，无需另配局域网证书。网页中“新连接”表示下次创建 TCP 连接时的首选通道，“现有连接”分别统计已经固定在直连和中转上的连接；不会将“新连接可直连”显示成所有连接均已直连。界面和助手显示实际选中的 IPv4/IPv6、UDP、往返延迟及回退原因。

后台探测不连接目标端口。ICE、DTLS 指纹和映射凭据验证通过后，再通过两次独立心跳确认可用；每条新连接还要打开可靠有序的数据通道并发送固定目标开启记录。通道预检失败、尚未请求目标端口时，可以选 WSS。目标开启记录一旦发出，失败结果可能不确定，此连接只会断开，不再经其他通道重复连接或重发字节，由原 SSH、数据库等客户端决定是否重连。

直连期间每三秒进行独立心跳，期限两秒。失效后新连接使用中转，已建立的连接保持原通道；连接不可用时正常断开。中转期间按失败后 15、30、60 秒退避探测；每五秒检查本机网络地址变化，变化后提前探测。存在旧直连 TCP 时优先探测原 peer 的恢复，避免为换 peer 结束可用的旧 TCP。停止、退出原登录和授权失效仍撤销全部通道。

沿用 WEBRTC_ENABLED、WEBRTC_IPV6、WEBRTC_LAN_ADDRESS、WEBRTC_IPV6_ADDRESS 和 WEBRTC_STUN_URL 设置。设置 WEBRTC_ENABLED=0 时仅使用中转。只接受私有 IPv4 和普通公网 IPv6 的 UDP 候选，公共 IPv4、TURN 和 ICE-TCP 未启用。双方主动 ICE 探测允许尝试打通可出站回复的防火墙，并不保证所有网络均能直连。

服务器转发 peer 的 UDP 端口限定为 40016–40047，独立于桌面/网页终端的 40000–40015；Windows 助手使用 40048–40111。若设备或网络有出站/入站限制，需要允许相应 UDP 通信，否则自动使用中转；程序不改防火墙。助手提供给 SSH 等软件的 TCP 端口始终只监听 Windows 的 127.0.0.1。

管理、授权与协商仍依赖原网站的 WSS 连接，直连减少的是 TCP 数据中转。该管理连接断开仍会撤销映射；不会因为直连绕过登录授权。详见[双栈直连](lan.md)。

## 故障提示

助手区分配对码无效、过期或已使用、本机端口占用、监听失败、证书验证失败、域名解析失败、连接超时、访问认证被拒绝和网站不可用。绑定本机端口失败会通知服务器并释放该映射，网页可看到同一原因。

目标端口无法连接、目标连接超时或异常断开只结束对应 TCP 连接，映射仍保持开启；检查目标服务后，用原客户端手动重试即可，成功建立目标连接后清除上次连接错误。不会主动重复连接或重发字节。助手每次运行最多输出二十条 TCP 连接错误及一条达到上限的说明，之后可在网页查看最新错误。

网页“最近结束的映射”最多显示八条、保留十分钟，刷新页面仍可查看。只在面板内存保存端口、时间、固定原因及凭据摘要，不写磁盘；面板重启清空。正常停止或重启、退出原登录、授权到期和心跳超时有明确原因；进程被强制结束或网络突然断开无法确定远端根因，提示助手关闭或网络中断。

本机端口只绑定 127.0.0.1，不能通过局域网地址使用。助手不安装服务、不设置自启动、不保存密码或配对信息，不写配置、数据或流量日志。程序当前未进行 Authenticode 签名，下载界面提供 SHA256，Windows 来源提示及兼容性需要在实际 Windows 设备上验证。

## 服务器允许的目标端口

默认允许 22。在 .env 中显式设置最多 16 个端口：

    TCP_FORWARD_PORTS=22,5432,8080

留空可禁用新映射：

    TCP_FORWARD_PORTS=

面板、内部 helper 和 Tunnel 诊断端口始终排除。修改后只需重启网页面板，桌面和 tmux 任务继续运行。管理员启用的端口代表工作台用户可向这些本机服务发起连接，应根据实际需求选择。

## 构建

构建使用 Go 1.26.4、Gorilla WebSocket 1.5.3 和 [Pion WebRTC 4.2.26](https://github.com/pion/webrtc/releases/tag/v4.2.26)，全部依赖在 go.mod 和 go.sum 锁定。Go 工具链不是运行依赖。Windows 用户只运行 exe，无需 Go、Node.js 或 Python。构建不自动安装或升级工具链。

    npm run build:forward

默认服务器地址读取 PUBLIC_ORIGIN 并嵌入程序，之后双击仅需输入配对码。也可显式指定构建地址：

    npm run build:forward -- https://example.com

或在运行时覆盖默认地址：

    codex-cloud-forward-windows-amd64.exe --server https://example.com

公网地址必须是 HTTPS 根地址，无跳过证书校验选项；仅回环测试允许 HTTP。配对码从标准输入读取，不通过 URL 或命令行参数传递。--version 显示版本，--licenses 显示随程序内嵌的依赖许可证。

产物只保存在被 Git 忽略的 data/forward-client：两个固定文件名的 Windows exe（每个最多 32 MiB）、一个最多 4 KiB 的 manifest.json。构建期间至多一个 helper.tmp（最多 32 MiB）、一个 manifest.tmp（最多 4 KiB）及一个空 .build.lock；单一构建互斥，正常退出清除临时文件。下载要求登录，每次只读取固定文件名的普通文件，拒绝符号链接，最多同时两项下载。产物和清单不提交 Git。

如果启用了额外的 Cloudflare Access 网页登录，助手还需要能通过该外层认证；首版不读取浏览器 Cookie、不自动代办 Access 登录。工作台自身账号密码登录与一次性授权不受影响。

## 协议与资源上限

- 网页创建、停止映射校验 Host、Origin、登录和 CSRF，不依赖桌面页面控制权；读取请求体后再次校验登录和 CSRF，延迟请求不能跨退出登录或授权失效执行。
- 最多四个待配对或活动映射。配对码和运行凭据都是 256 位随机值，只保存摘要和少量元数据于内存；每个授权仅允许一个明确目标端口和一个本机端口。
- 助手用一次性配对码认证 /forward/helper，获得仅用于该映射的流凭据；中转的每条本机 TCP 连接独立认证 /forward/data。使用 codex-forward-v1 子协议，凭据放在 Authorization 请求头，保持 Host 和 Origin 校验；不会把工作台登录 Cookie 交给助手或目标服务。
- 新助手显式声明直连能力，SDP 只在已认证管理通道传输，单项最多 32 KiB、控制消息最多 48 KiB、控制发送缓冲最多 64 KiB。每个映射最多一个 peer，全局最多四个（包含关闭中），全局协商不排队、最多一项同时进行，同一映射十秒内不重复协商；旧直连 TCP 未结束时不替换其 peer。
- 直连使用 DTLS 验证 WSS 协商的证书指纹，健康通道再次校验映射凭据，数据通道只允许固定目标开启记录。可靠有序 SCTP 通道采用四条已确认记录的窗口，每条最多 16 KiB；目标写入受背压时不再释放确认额度，避免在接收端无限排队。FIN 与普通数据保持发送顺序并参与确认。
- 每个 peer 接收窗口最多 1 MiB；服务端在分片重组前限制最多 32 项流元数据、1024 个未重组分片、2048 项乱序包标识及 1024 项重复标识。每个助手 peer 最多创建 128 条数据通道，达到上限后新连接暂用中转，等待旧直连 TCP 结束后再轮换 peer，避免依赖库保留的已关闭通道元数据长期累积。每次助手运行最多输出二十条通道变化提示及一条达到上限说明。
- 服务端确认助手已绑定本机端口后才允许连接目标。配对后启用期限五秒，目标连接期限五秒。
- 每个映射最多八条并发 TCP 连接，每十秒最多 32 次连接尝试。二进制消息最多 16 KiB，服务端应用发送缓冲和目标写缓冲分别最多 256 KiB；慢接收方施加背压，超限关闭对应连接。
- TCP EOF 使用独立 FIN 记录，保留半关闭后的响应。原始字节不进入 PTY、输入助手或 shell，不解析 SSH/数据库协议，不执行任意命令。
- WebSocket 每十五秒心跳，未响应则关闭；助手读期限四十五秒、写期限十五秒。授权到期或失效最多五秒内清理，显式停止、退出原登录立即撤销。TCP 立即关闭，控制通道最多等待一秒发送固定原因，最多八个关闭中的通道，超限终止最早通道。
- 状态最多四项活动映射及字节计数，另保留八条最近结束原因十分钟，不保存原始内容、连接明细或流量日志。保留的配对码摘要仅用于返回过期/已用提示，不能再次配对；不向网页暴露摘要、登录标识或运行凭据。网页仅在对话框打开且前台时每三秒查询，最多一项在途请求；配对码仅当前窗口暂存，关闭窗口、隐藏页面或失去登录授权会清空，复制只在点击时发生。

## 验证

    npm run check
    npm test
    npm run test:desktop
    npm run test:forward
    CHROME_PATH=/usr/bin/google-chrome npm run test:browser -- test/browser/forward.spec.mjs test/browser/web-terminal.spec.mjs

Node 单元测试使用真实 WebSocket 和隔离 TCP 服务，另有基于模拟通道的背压/重组资源上限测试；桌面与管理执行器为 fixture。浏览器测试使用真实 Chrome 和模拟 RFB，覆盖刷新和接管保留映射、不同页面管理、固定故障提示和丢失响应不重试；通道统计界面用例使用模拟诊断数据，不将其当成真实网络通道验证。

test:forward 使用带 race 检测的 Linux 同源助手、临时证书、真实 TLS/WSS 代理、真实 Pion/werift UDP/DTLS/SCTP 和 TCP 服务。覆盖 8 MiB 数据、双向半关闭、心跳、探测不连接目标、旧中转流保留、不同通道并存、直连失效/恢复、peer 实际关闭后的后台重建、目标就绪丢失不回退重连、明确停止撤销两种通道，以及原有端口占用、目标不可达、输出上限和证书拒绝。健康失效和就绪丢失使用受控故障注入，数据仍经真实协议栈；IPv6 在主机实际分配的公网 IPv6 上验证，无地址时明确跳过。所有检查均不连接工作中的 Codex 或真实 SSH 服务。

Windows x64/ARM64 交叉构建和 PE 检查不替代 Windows 真机验收。本机公网 IPv6 连接也不能替代跨运营商验收。实际 Windows 设备可依次测试 SSH 登录、SFTP 上传/下载同一大文件并核对 SHA256、同时保持一条 SSH 后切换直连状态确认旧连接保留，最后测试断网/休眠后的明确错误与手动重新配对；需使用实际目标服务的账号，项目不代为保存该密码。
