# 端口映射：固定八个助手

使用固定的“助手1”至“助手8”。每台电脑运行一个助手进程、输入对应 key，网页动态管理它的多条 TCP / 串口规则。支持 Windows x64 / ARM64、Mac Apple Silicon / Intel；不提供 UDP 端口映射。助手构建版本为 `0.9.0+<提交标识>`，更新时核对完整构建，不能只看 `0.9.0`。

## 部署与启动

1. 按所选[部署组合](deployment.md)部署节点。首次初始化自动生成八个独立 key；普通部署、服务重启不会更换。
2. 最终域名与节点路径确定后运行 `npm run build:forward`，需要固定 Go **1.26.4**、Python、Git 和仓库的 Git 元数据。普通 `npm run deploy` 不构建助手；需要同时更新服务和助手时使用 `npm run deploy -- --build-forward`。四平台验收见[共用检查清单](deployment-checklist.md#3-需要助手时完成构建与发布)。
3. 管理员登录工作台，打开“端口映射”，选择“助手1”至“助手8”中的一个。锁定或被接管的管理员页面不能查看 key 和管理规则；临时账号只可查看管理员逐个开放的 key，不能管理规则。
4. 下载对应电脑版本。Windows 双击 exe；Mac 解压 ZIP，双击 `Start.command`。在窗口粘贴该助手页的 key 并回车。
5. 助手打印控制节点及规则。保持窗口打开，Ctrl+C 结束该电脑的全部映射；下次启动输入同一 key。

key 包含服务器入口、完整 `/node/<slug>/` 路径及节点身份。助手不接受一次性配对码、`--server` 或 `--allow-reverse`。同一 key 同时只允许一个助手进程，后来连接被拒绝，不抢占当前助手。另一台电脑应使用另一个固定槽位。

## 网页管理

标签固定编号，不增删或改名。宽度足够时平铺全部标签；不足时保留能放下的前几个，其他助手进入末尾下拉菜单。手机、平板和电脑遵循同一规则，选中的折叠助手显示在下拉框中。

每页先展示助手选择、key、在线状态和映射规则。下载与安装说明按需展开，版本与 SHA256 可单独查看。每条规则显示直连 / 中转、已有连接数量及目标验证状态。

新增或编辑使用弹窗，实时预览入口和目标所在机器；直连地址提示收在“高级”中。可离线保存，上线后自动应用。修改、停用或删除立即撤销该条规则的旧授权及连接，助手管理离线时也生效；新配置待助手上线后下发。其他规则继续，不会自动执行设备命令或终端输入。

关闭未保存的表单需确认。暂时切换窗口保留填写内容并清空 key，返回后重新读取；关闭页面或失去管理权限清空表单。

管理员的“重新生成 key”有确认：旧 key 立即失效，该助手及其映射断开；保存的规则保留，用新 key 重新接入。其他七个助手不受影响。管理员可随时查看和复制当前 key；离开页面、隐藏标签或失去完整管理权限时清空浏览器内的 key，不写入浏览器存储。

各助手页分别提供“临时账号可查看此助手 key”，默认关闭。开启后，临时账号只看到已开放的助手，可查看、复制 key；仅临时账号提供“刷新 key”，仅读取当前 key，不生成新 key，不提供规则及设备信息。关闭可见或临时账号到期只撤销网页读取权限；已复制的长期 key 仍可接入，需要撤销时由管理员重新生成。

## 规则方向

新增规则默认“节点主机访问助手侧网络/串口”，节点监听端口默认 22001；另一方向的默认监听端口为 2222。切换方向时，22001 / 2222 随方向切换，其他端口保持原值。本次默认值调整不修改已保存规则。

| 方向 | 回环监听位置 | 访问目标的位置 | 示例 |
| --- | --- | --- | --- |
| 节点主机访问助手侧网络/串口，默认 | 节点主机 | 助手电脑可达的网络或其串口 | 节点主机 `127.0.0.1:22001` → 助手侧 `192.168.1.1:22` |
| 助手电脑访问节点侧网络 | 助手电脑 | 节点主机可达的网络 | 助手电脑 `127.0.0.1:2222` → 节点侧 `192.168.1.10:22` |

“节点主机”是运行网页终端 / AI 的主机；“助手电脑”是实际运行下载助手的电脑。节点主机可以部署在本机或远程服务器上；助手电脑不一定是打开网页的设备。

按选择的方向，在对应机器上连接 `127.0.0.1:监听端口`。目标 IP 由另一端访问：节点侧目标中的 `127.0.0.1` 指节点主机自身，助手侧目标中的 `127.0.0.1` 指助手电脑自身。网络目标也可以是另一端能连接到的局域网设备。

目标仅接受具体 IPv4 / IPv6，不解析域名；监听端口为 1024–65535，排除工作台管理端口。

两个网络映射方向均可在“目标端口预设”选择 Web（HTTP，80）或 HTTPS（443），也可手动填写 8080、8443 等端口。预设只填写目标端口，监听端口保持原值；HTTPS 由目标服务提供证书并处理 TLS，映射透传 TCP。

规则可选 SSH、Telnet、其他 TCP 或[串口](serial.md)。同一助手电脑的监听端口不能重复；节点主机监听端口在整个节点中不能重复。不同助手电脑可使用相同的监听端口。一个助手不能同时启用两条占用同一串口路径的规则。

### 复制给 AI 的提示词

仅“节点主机访问助手侧”规则提供“复制 AI 提示词”，可直接粘贴给 Codex 等 AI。内容包括机器身份、节点入口、访问方向、监听与目标地址、串口参数、复制时状态及在节点执行的连接示例；助手访问节点侧仍提供“复制连接信息”。

AI 应先确认命令运行位置和具体任务。提示词中的助手侧 `127.0.0.1` 不代表节点主机，状态快照也不保证目标服务已连通；HTTPS 示例保留域名、SNI 和证书校验。提示词不包含助手 key 或密码，不会自动执行复制的命令。

剪贴板不可用时显示可手动复制的文本；修改规则、隐藏页面或切换助手后清除旧文本，避免继续使用过期拓扑。

## 网卡和串口信息

展开设备信息，可查看网卡名称、启用 / 停用、所有 IPv4 地址、前缀、子网掩码及串口列表。每 30 秒上报一次，也可手动刷新；串口既可选择，也可手填有效路径。枚举不会打开串口，也不自动扫描其他局域网设备。

离线时显示带时间的最后一次信息，不能据此判断当前在线。最多 128 张网卡、128 个串口，每张网卡 32 个 IPv4、总共 1024 个；清单最多 32 KiB，超出时标记截断。

在线状态同时检查助手消息：连续 75 秒未收到设备上报等有效消息会释放管理连接，代理回应 WebSocket 心跳不会延长这个期限。正常退出在页面下一次刷新时显示离线；断网等异常情况需等待超时。状态读取失败时显示“助手状态未确认”，不会保留旧的在线标记。下载列表失败不影响助手状态刷新。

## 连接规格与恢复

同一助手的多条规则共享一个 WebRTC 直连和一条 WSS 中转备用连接，各规则仍独立授权、计数和撤销。新 TCP 优先使用健康的局域网 IPv4、公网 IPv6 或 IPv4 NAT 打洞 UDP / DTLS 直连，未就绪时复用已认证的 WSS，不再为每条 TCP 单独握手；当前助手不支持 TURN。全节点最多八个转发 peer（含关闭中），每助手同时最多 24 条直连数据流，超过后新 TCP 使用 WSS。管理与协商使用原网站，不另配局域网证书。

“新连接”显示下一条 TCP 的首选路径，并区分局域网、IPv6、NAT 打洞或公网 IPv4；“已有连接”显示实际固定在直连 / 中转上的数量，不迁移旧 TCP。探测不连接业务目标，目标开启结果未知时不换路重复访问或补发字节。地址提示可为每条规则单独填写、清空；修改规则会重建该规则的连接。UDP 端口和网络排查见[网络说明](lan.md)。

网页刷新、关闭、退出登录、锁屏和浏览器切换默认节点不撤销助手 key。断线后的影响取决于哪条连接中断：

| 中断位置 | 影响与恢复 |
| --- | --- |
| 助手整体管理连接 | 暂停配置及设备清单下发，按 1、2、4、8、15 秒退避重连；仍健康的单条映射可继续接收新 TCP |
| 共享 WSS 备用连接 | 该连接上的中转 TCP 中断并由业务客户端重连；健康直连保留，备用自动重建，不重建整个助手或其他直连 |
| 共享 WebRTC 直连 | 原直连 TCP 中断并由业务客户端重连；新 TCP 使用健康 WSS，后台继续探测直连 |
| 单条映射的控制连接 | 在原 30 秒 / 八次握手窗口内保留健康数据，暂停新客户端；恢复超时则关闭旧映射 |
| 节点面板进程 | 旧 TCP 中断，助手凭原 key 重建启用规则；业务客户端自行重连 |

以上恢复均不重放业务字节或串口操作。管理员修改、停用或删除规则仍立即撤销该条旧映射，不受助手整体管理连接在线与否影响。

## 下载与 Mac 首次运行

网页可通过独立 WebRTC 文件通道下载助手；未准备好时最多额外等待 1.5 秒，再使用 HTTPS。每项最多 32 MiB，直传保存前验证大小和 SHA256。已开始的传输失败不自动换路重复下载，手动重试即可。下载不附加 VNC / PTY。

更新节点和助手后，直连额度暂满的新 TCP 会在连接目标前改走共享 WSS。已有直连继续运行，小消息有保留额度；任何已经发出目标开启请求的连接都不会换路重试。

Mac 需要 macOS 12 或更新版本：Apple M 系列选 Apple Silicon，Intel 选 Intel。包内固定包含程序、`Start.command` 和 `README.txt`，程序和启动器有执行权限。也可在解压目录运行：

```sh
./codex-cloud-forward
./codex-cloud-forward --version
./codex-cloud-forward --licenses
```

当前无 Developer ID 分发签名和 Apple 公证。首次出现“Apple 无法验证”时，核对下载来源、版本及 SHA256，然后按 [Apple 官方说明](https://support.apple.com/zh-cn/102445)，在“系统设置 → 隐私与安全性”中对刚被阻止的程序选择“仍要打开”；启动器被阻止时也需单独确认。不提供关闭 Gatekeeper 或自动删除隔离属性的脚本。

## 构建与全新替换

### 日常构建与升级

```sh
npm run build:forward
# 或指定完整入口
npm run build:forward -- https://desk.example.com/node/node-a/
```

默认读取持久 `.env` 的 `PUBLIC_ORIGIN` 与 `ENTRY_BASE_PATH`。单独构建不重启工作台，客户端无需 Go、Node 或 Python。入口或助手代码变化后重新构建、下载；入口变化还需从目标节点页面复制当前 key。NAT 打洞及连接池需要使用本次更新后构建的助手；更新无需更换现有 v2 key 或规则。CF 网关也需更新，以支持 `/forward/transport` 的[助手固定节点路由](gateway.md#更新与恢复)，不能让浏览器切换改变助手归属。

已有固定槽位 v2 配置普通升级保留 key 和规则，直接按上述构建 / 部署流程操作，不执行清理。单独修改文档无需构建；助手代码或入口改变才重新构建、下载。

### 旧格式的显式重置

本节不用于普通 v2 升级。更早格式不迁移旧 key、旧规则或设备目录；全新目录直接初始化即可。只有明确废弃旧授权和规则时，才先结束旧映射，停面板后仅清理旧端口映射配置，再部署：

```sh
systemctl --user stop codex-cloud-panel.service
rm -f -- data/panel/forward-agents.json data/panel/devices.json
npm run deploy -- --build-forward
```

这会废弃旧助手授权和规则，不清理工作台账号、文件或终端任务。私有配置为 `data/panel/forward-agents.json`，128 KiB、0600，含八个 key 的 secret 和规则；按凭据保护，不加入 Git。助手本机不保存 key 或流量日志。

## 资源与排障

每助手最多 16 条保存规则，全节点最多 32 条活动映射；每条 TCP 最多八个客户端、每十秒 32 次连接尝试，串口每条一个客户端。

| 现象 | 核对 |
| --- | --- |
| 助手离线 | 进程、网络、节点入口、key 是否重新生成，以及助手是否为与当前节点匹配的构建；不要仅核对基础版本号 |
| 同一 key 已在线 | 使用另一个助手槽位；不强制抢占当前连接 |
| 规则未生效 | 查看该规则错误，检查端口占用、IP、串口路径及系统权限 |
| 保存结果未知 | 刷新规则列表核对，不连续重复提交 |
| 直连失败但中转可用 | 可继续使用，按网络说明检查 UDP、防火墙和本地网络权限 |
| 外层 Access 拒绝助手 | 助手不读取浏览器 Cookie 或自动完成 Access 登录 |

`TCP_FORWARD_PORTS=*` 默认允许所有非管理目标端口，也可设为最多 16 个端口或空值禁用 TCP 目标。规则重新应用时检查当前限制；串口不受 TCP 目标列表限制。修改环境后重启面板生效。

“复制诊断报告”只含枚举状态与计数，省略 key、地址、端口、规则名和串口路径。协议、发布边界及真实测试范围见[开发参考](forward-protocol.md)。
