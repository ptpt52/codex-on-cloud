# TCP 端口映射助手

网页配置映射，本地助手转发原始 TCP 字节，适用于 SSH、数据库及其他 TCP 客户端。0.8.0 起支持一个助手接受多条动态规则，也保留一次性配对。提供 Windows x64 / ARM64 和 Mac Apple Silicon / Intel 四个平台下载；不提供 UDP 端口映射。串口设备使用[串口模式](serial.md)。

## 先选择方向

| 页面方向 | 谁监听回环端口 | 谁访问目标 | 示例 |
| --- | --- | --- | --- |
| 本机访问服务器网络 | 助手电脑 | 服务器 | 电脑 `127.0.0.1:2222` → 服务器可达的 `192.168.1.10:22` |
| 服务器 / Codex 访问本地设备 | 服务器 | 助手电脑 | 服务器 `127.0.0.1:22001` → 电脑可达的 `192.168.1.1:22` |

“本机”指运行助手的电脑，不一定是打开网页的设备。目标 IP 按访问目标的一端解释；两侧的 `127.0.0.1` 分别指各自机器。这里只接受具体 IPv4 / IPv6 地址，不解析目标域名。

## 使用

### 常驻助手：一个进程、多条规则

1. 管理员登录、解锁并接管工作台，打开“端口映射”，下载当前助手。节点后台和助手均需支持 0.8.0 的常驻模式。
2. 在“常驻远程助手”填写电脑名称，创建助手，复制仅显示一次的长期授权 key，私密保存。每台电脑创建独立助手，不共用 key。
3. Windows 双击 exe；Mac 解压后双击 `Start.command`。在窗口粘贴 key 并回车。key 包含正确域名、节点路径及身份，不需要额外指定服务器。每次启动可重复输入，程序不保存 key 或安装自启动服务。
4. 在映射表单选择该助手，填写规则名称、方向、监听端口和目标；保持“启用”后保存。在线时自动生效，离线时保存并等待助手上线。
5. 继续给同一助手添加规则，或选择其他助手配置。一个助手进程承载它的全部规则，无需为每条规则再开窗口。

编辑并保存会重建这一条映射并关闭它的旧连接；停用保留配置，删除移除配置，均不影响其他规则。服务器监听端口不能重复；不同助手可使用相同的助手本机监听端口。同一助手不能同时启用两条占用同一串口的规则。保存到设备目录仍只保存资料，不自动创建常驻规则。

每个助手的卡片独立显示控制连接是否在线、各条规则是否生效、新连接走直连还是 WSS，以及已有直连 / 中转连接数。展开设备信息查看网卡名称、启用状态、全部 IPv4、前缀和子网掩码，以及串口列表；每 30 秒自动更新，也可手动刷新。离线保留带时间的最后一次信息，不能据此判断设备当前在线。超过资源上限会明确标记截断。

粘贴长期 key 即允许指定控制台节点在此助手运行期间增删 TCP 和串口规则，不再逐条输入 YES。仅将自己节点生成的 key 输入自己的助手。助手打印控制节点及当前规则，Ctrl+C 停止本机全部映射。重新生成 key 立即撤销旧 key 并断开该助手，规则保留；“撤销并移除助手”同时删除其规则。其他助手不受影响。

常驻授权独立于网页登录：刷新、退出登录、锁屏和浏览器切换默认节点不撤销它。后台重启会中断旧 TCP，仍运行的助手使用原 key 重连并重建已启用规则，不重放旧字节；原客户端需重新连接。不要把 key 放进 URL、命令行、聊天或 Git；服务器只保存摘要，遗失后重新生成。

### 一次性配对：兼容旧助手

1. 登录工作台，打开“端口映射”，下载助手。没有下载项时请部署者按[构建](#构建)发布。
2. 选择“本机访问服务器网络”，填写本机端口、服务器可达的目标 IP 和目标端口。
3. 点击“生成一次性配对码”。配对码有效两分钟，只能使用一次；不放进 URL 或命令行。
4. Windows 双击 exe；Mac 解压 ZIP，双击 `Start.command`，在助手窗口粘贴配对码并回车。
5. 助手显示“映射已开启”后，让原客户端连接助手电脑的回环端口，例如：

```sh
ssh -p 2222 USER@127.0.0.1
```

目标服务仍需监听，SSH、数据库等服务的认证由原客户端处理。每次配对固定方向、目标与端口；修改网页表单只影响下一次创建。

### 助手下载链路

画面 / 终端直连与助手下载分别判断。“端口映射”窗口会准备独立的 WebRTC 文件通道，显示下载链路、进度和校验结果。通道就绪后优先从节点传输助手；准备尚未完成时，点击最多额外等待 1.5 秒，再使用原 HTTPS 下载。

直连下载仍使用当前登录、节点路径和列表中的固定发布版本，最多 32 MiB，保存前校验大小与 SHA256。没有直连能力、旧后台或浏览器缺少校验能力时继续使用 HTTPS；已开始的直传失败不自动经 HTTPS 重复下载，手动重新点击即可。下载不附加终端或接管桌面，也不需要重新构建已有助手。

## 反向设备接入

常驻模式选择助手后直接保存反向规则即可，按该助手的串口列表选择或手填设备路径。下面是一次性配对模式的本机逐条确认流程：

1. 选择“服务器 / Codex 访问本地设备”，填写设备名称、协议标签、服务器回环端口和助手电脑可达的设备 IP / 端口。
2. 可先保存到设备目录；保存资料不会开放访问。生成配对码后在助手粘贴。
3. 在助手核对服务器入口、设备名称和固定目标，输入 **YES**。拒绝或确认超时不会开放监听或连接设备。
4. 启用后点击“复制给 Codex”，取得服务器上使用的连接说明，例如：

```sh
ssh -o HostKeyAlias=codex-cloud-DEVICE_ID -p 22001 USER@127.0.0.1
```

实际复制内容使用固定设备标识；`USER` 替换为设备用户名。不会自动执行命令、接受主机指纹或保存 SSH 密码。“助手已连接”只表示授权通道就绪，实际客户端连接后才访问设备。

脚本可显式使用 `--allow-reverse 192.168.1.1:22`，只允许完全匹配的目标；串口仍必须交互确认。编辑或删除设备目录记录不会修改现有授权。

## Mac 首次运行

支持 macOS 12 Monterey 或更新版本，来自固定 Go 1.26.4 的系统要求；[Go 官方版本说明](https://go.dev/doc/go1.26#darwin)。在“关于本机”中显示 Apple M 系列芯片时选 Apple Silicon，显示 Intel 时选 Intel。网页只在打开下载窗口时请求浏览器的架构提示，最多等待 500 毫秒；浏览器拒绝、未提供或超时则保留手选，不从所有 Mac 都可能返回的 `MacIntel` 标识推断实际芯片，不把设备信息写入存储或发送给服务端。[Chrome Client Hints 文档](https://developer.chrome.com/docs/privacy-security/user-agent-client-hints)

ZIP 中固定包含 `codex-cloud-forward`、`Start.command` 和 `README.txt`，前两项有可执行权限。也可在终端进入解压文件夹运行：

    ./codex-cloud-forward

检查版本或依赖许可证：

    ./codex-cloud-forward --version
    ./codex-cloud-forward --licenses

本版没有 Developer ID 分发签名和 Apple 公证，因此首次运行可能出现“Apple 无法验证 codex-cloud-forward 是否包含可能危害 Mac 安全或泄漏隐私的恶意软件”。Apple Silicon 文件带 Go 链接器生成的 ad-hoc 签名，这不等于开发者身份认证或 Apple 公证。Mac 浏览器打开下载窗口时会展开首次运行说明。

确认下载来自自己的工作台、网页版本及 ZIP SHA256 后，可按 [Apple 官方说明](https://support.apple.com/zh-cn/102445) 操作：

1. 先尝试打开解压后的程序；弹出验证提示时，点击“完成”或“取消”。
2. 打开“系统设置 → 隐私与安全性”，向下滚动到“安全性”，找到刚被阻止的 `codex-cloud-forward`，点击“仍要打开”，按系统提示确认。
3. 重新双击 `Start.command`。如果被阻止的名称是 `Start.command`，也需要对该文件完成上述确认。

没有“仍要打开”时，先在 Finder 的解压文件夹中双击 `codex-cloud-forward`，再返回设置查看。受组织管理的 Mac 可能无法由使用者更改此设置，需联系管理员。按文件确认后，macOS 会记住该程序的例外；将来更换下载文件可能需要再次确认。无需重新配对已有映射来做此设置；使用一次性模式时，准备启动助手后再生成两分钟配对码。

要让正式下载免去上述未验证软件的放行步骤，后续需使用 Developer ID 分发签名并完成 Apple 公证；当前 Linux 交叉编译和 Go ad-hoc 签名不能完成这一步。不提供关闭 Gatekeeper 或自动删除隔离属性的脚本。Mac 提示本地网络权限时，允许助手/终端访问可用于局域网探测。

保持启动的终端窗口打开，Ctrl+C 停止；出错时交互窗口显示原因并等待 Enter。启动脚本只执行同目录程序和明确传入的参数，不安装服务、自启动项或写入用户 Codex 配置。

## 直连和中转

两种模式使用相同连接规格：新连接优先使用可用的局域网 IPv4 / 公网 IPv6 UDP / DTLS 加密直连，否则使用 WSS。管理和配对始终经过原网站；不需要另配局域网证书。已有 TCP 固定在原通道，不会在直连与中转之间迁移。多个助手及各规则分别探测、统计，不借用浏览器画面或其他助手的“直连”结果。全节点同时最多四个转发直连 peer，其余规则可经 WSS 工作。

网页分别显示“新连接”的首选路径和“现有连接”的实际数量。直连探测不连接业务目标，通道开启结果未知时不换路重复访问目标或补发字节。

新映射继承浏览器的直连 IP 提示；助手在另一台电脑时，单独填写“助手端 IP”。一次性映射点击“应用当前直连提示”更新；常驻规则编辑保存后更新该规则，重建它的连接。端口与网络排查见[网络说明](lan.md)。

## 短暂断网恢复

保持助手进程运行。当前助手在原授权的 30 秒窗口内恢复管理连接；管理链路短暂中断时可保留已就绪的健康 TCP / 直连通道，并暂停新连接。数据通道本身已断开的 TCP 需要原客户端重新连接，不自动重放字节。

刷新或关闭网页、切换显示模式、锁屏和其他页面接管均保留已有授权。一次性模式在 Ctrl+C、关闭助手窗口、网页确认停止、退出来源登录、授权失效或面板重启后结束；需重新配对。常驻模式的控制连接按 1、2、4、8、15 秒退避持续重连，规则通道仍沿用原 30 秒恢复窗口；窗口耗尽后可自动建立新映射，但已断开的业务 TCP 必须由原客户端重连。Ctrl+C、停用 / 删除规则、撤销 key 均会结束相应映射。旧版助手可能在管理断线时关闭旧 TCP，建议从自己的节点下载当前版本。

常驻助手配置、key 和设备信息仅已解锁并接管的管理员可访问；锁定、被接管或临时账号不能操作。一次性模式中，锁定或被接管的管理员只能管理反向映射；临时账号只能管理本次登录创建的反向映射。详细规则见[访问权限](access.md#锁屏后全部保留)。

## 故障提示

| 现象 | 处理 |
| --- | --- |
| 常驻助手不在线 | 检查进程、网络及 key 所指的域名 / 节点；旧 key 撤销后需输入新 key |
| 同一 key 已有助手连接 | 每台电脑创建独立助手；同一 key 同时只接入一个进程 |
| 规则未生效 | 查看该规则错误；端口占用或系统不支持该串口路径仅影响此规则 |
| 没有助手下载项 | 最终域名 / 节点路径确定后重新构建，在当前节点核对四项下载 |
| 配对码无效、过期或已使用 | 从网页明确生成新码，勿重复使用旧码 |
| 本机或服务器监听端口占用 | 选择空闲端口后重新配对 |
| 配对按钮提示结果未知 | 先刷新映射状态核对，不连续点击创建 |
| 目标连接失败或超时 | 检查设备、地址和目标服务；映射仍在线时由原客户端重连，无需反复配对 |
| 直连失败但中转在线 | 可继续工作，按[网络说明](lan.md#常见问题)检查 UDP 与权限 |
| 网页可登录但助手被 Access 拒绝 | 助手不读取浏览器 Cookie，也不自动完成 Cloudflare Access 登录 |
| 控制台达到 20 条提示上限 | 只限制同类日志，不限制数据转发；在网页查看最新状态 |

网页“最近结束的映射”最多保留八项、十分钟，面板重启清空。“复制诊断报告”省略目标 IP、端口、设备名和凭据，不包含传输内容。Windows 尚无 Authenticode 签名；Mac 首次运行见上文。

## 服务器允许的目标端口

```dotenv
# 默认允许所有目标端口；本项目管理端口始终排除。
TCP_FORWARD_PORTS=*
# 也可限制为最多 16 个端口，例如：
# TCP_FORWARD_PORTS=22,5432,8080
```

设为空值禁用新的 TCP 目标映射，重启 panel 生效；常驻规则重新应用时也检查此限制，不符合的规则显示未生效。反向监听端口需为 1024–65535 且未占用，所有监听只绑定回环。串口不是 TCP 目标，不受目标端口列表限制。

## 构建

在节点部署目录准备固定 Go **1.26.4**、Python 和 Git，先完成最终入口接入，再构建：

```sh
npm run build:forward
```

构建读取持久 `.env` 的 `PUBLIC_ORIGIN` 与 `ENTRY_BASE_PATH`，支持 HTTPS 根地址和完整 `/node/<slug>/` 路径；仅回环测试允许 HTTP。也可显式指定：

```sh
npm run build:forward -- https://desk.example.com/node/node-a/
```

一次性模式可用 `--server` 覆盖默认地址；常驻模式使用 key 内地址，显式 `--server` 必须与它一致。`--version` 查看版本，`--licenses` 查看依赖许可证。没有跳过证书验证选项。

升级常驻功能需要更新节点后台并重新构建、下载 0.8.0 助手，单独热更新网页不足以启用。CF 网关还需[更新 Worker](gateway.md#更新与恢复)，使助手连接固定到授权节点；浏览器切换默认节点不会迁移助手。自建中心继续使用 key 内完整 `/node/<slug>/` 路径。

构建完成后，在网页核对并下载实际使用的平台版本。入口变更后需重新构建、重新下载；不匹配当前入口的产物不会提供。单独构建不重启工作台服务。客户端运行 exe / Mac 包无需安装 Go、Node 或 Python。

依赖、包体、原子发布、资源上限与真实协议测试见[开发参考](forward-protocol.md)。Mac / Windows 系统运行和 USB 硬件仍需真机验收。

## 协议与资源上限

每节点最多八个常驻助手、每助手十六条保存规则，全节点最多三十二条待配对或活动映射（包括一次性映射）；一次性模式仍最多四条。每个 TCP 映射最多八条并发、每十秒 32 次连接尝试；串口映射最多一个客户端。常驻 key 摘要和规则保存在私有、有界配置中，配对码、运行凭据、恢复状态及设备清单仅在有界内存；不保存流量内容。

完整协议见[映射协议](forward-protocol.md#协议与资源上限)；开发检查见[映射验证](forward-protocol.md#验证)。
