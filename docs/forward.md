# Mac 与 Windows TCP 端口映射助手

助手提供通用 TCP 字节转发，适用于 SSH、数据库和其他 TCP 客户端。网页负责发放一次性授权，助手通过原有网站的 WSS 入口进行管理和加密协商，TCP 数据优先通过局域网或公网 IPv6 的 WebRTC / DTLS 加密直连传输，不可用时使用 WSS 中转。映射授权绑定创建它的登录，独立于桌面控制权；刷新、关闭网页、切换桌面/终端模式或其他页面接管均保留现有 TCP 连接。不支持已有 TCP 连接跨通道续传。

锁屏后，锁定前授权的正反向映射全部保留：原 TCP 不因锁屏断开，后续新 TCP 也可继续接入；未使用的有效配对码和原授权的断网恢复继续按原期限处理。锁定页面不能新增或管理“本机访问服务器”的映射，来源登录失效、明确停止和面板重启仍会撤销授权。详见[锁屏保留规则](access.md#锁屏后全部保留)。

## 使用

1. 登录工作台，在标题栏打开“端口映射”，下载运行助手的电脑版本：Mac Apple Silicon（M 系列）、Mac Intel、Windows x64 或 Windows ARM64。浏览器确认架构后会标出推荐版本，四种下载始终可手动选择。
2. 填写本机端口，例如 2222；填写目标 IP 和目标端口，例如 192.168.1.10 和 22，点击“生成一次性配对码”。目标 IP 默认 127.0.0.1，表示服务器自身；也可填写服务器可访问的局域网或公网 IPv4 / IPv6。
3. Windows 双击 exe；Mac 解压 ZIP，双击文件夹中的 `Start.command`。将配对码粘贴到助手的终端窗口，回车确认。配对码有效期两分钟，只能使用一次。
4. 显示“映射已开启”后，将原有软件连接到运行助手那台电脑的 127.0.0.1 和本机端口。例如 SSH：

       ssh -p 2222 用户名@127.0.0.1

本机 127.0.0.1 指运行助手的 Mac/Windows；目标 IP 则从 Linux 服务器所在网络访问。例如本机 127.0.0.1:2222 → 加密通道 → 服务器 → 192.168.1.10:22。目标可以是另一个局域网设备或公网主机，不要求访问网页的电脑直接可达它。目标 IPv6 可写 ::1 或 [2001:db8::1]，界面以 [IPv6]:端口 显示；这里只接受具体的 IPv4 / IPv6 单播地址，不解析域名或带网卡标识的 IPv6。服务仍需在目标端口监听，SSH 或数据库登录由原客户端和目标服务处理。

每次配对绑定本机端口、目标 IP 与目标端口。编辑表单只影响下一次创建，不能修改已有映射；直连、中转及断网恢复使用原目标。目标 IP 的地址族与助手到服务器的直连地址族独立。配对和后台探测均不会主动连接目标。

保持助手进程运行。新版助手在检测到短暂断网后，可在 30 秒内自动恢复原映射及本地监听。原有 TCP 连接会关闭，由 SSH、数据库等原客户端重新发起连接；恢复过程不自动连接目标或重放字节。Ctrl+C、关闭助手窗口或网页中“确认停止”可结束映射；退出创建映射的登录、授权到期或撤销、网关更新会终止恢复。面板重启后需重新配对。

当前接管的管理员可管理全部映射；锁定或被接管的管理员仅可管理反向设备映射，临时账号仅可管理本次登录创建的反向映射。受限页面不能配置正向映射，但锁定前已建立的正反向连接均保留。另一个设备登录或退出它自己的登录不会影响已有映射；退出原登录、原登录到期/被名额上限淘汰或临时账号撤销时，其创建的映射会结束。详见[屏幕锁与临时访问](access.md)。Mac 支持从 0.4.0 开始，Windows 0.3.0 和新版都支持自动恢复；0.2.0 助手保留原有直连功能，但断开管理连接后需重新配对。0.5.0 助手正确显示自定义目标，并在恢复时核对目标 IP；旧助手仍可转发，但其控制台将目标显示为服务器回环地址，建议重新下载。新版助手连接未返回目标 IP 的旧服务器时继续按 127.0.0.1 处理。

## 反向设备接入

0.6.0 增加“服务器 / Codex 访问本地设备”。正向模式由电脑监听本机端口、服务器连接目标；反向模式由服务器监听 **127.0.0.1**，本地助手连接它能访问的固定设备 IP/端口。复用原网站的认证 WSS、WebRTC/DTLS、心跳和恢复路径，不额外部署穿透服务器，不开放公网 TCP 监听。

1. 打开“端口映射”，下载新版助手，选择反向方向。
2. 输入设备名称、SSH / Telnet / 其他 TCP 标签、服务器回环端口和设备目标 IP/端口。例如“家中路由器”、SSH、22001、192.168.1.1、22。目标的 127.0.0.1 指运行助手的电脑；其他 IP 由这台电脑所在网络访问。
3. 可先保存到设备目录；保存只记录资料，不创建或启用访问授权。点击“生成一次性配对码”，运行助手并粘贴配对码。
4. 助手显示设备名称、目标 IP/端口和服务器入口；确认后输入 **YES**。首次确认最多等待 60 秒，助手在 55 秒时取消未完成确认。拒绝、超时或停止均不开放监听或连接设备。
5. 映射启用后点击“复制给 Codex”，取得连接信息。例如服务器上执行：

       ssh -o HostKeyAlias=codex-cloud-DEVICE_ID -p 22001 USER@127.0.0.1

   实际复制内容使用固定十六进制设备标识代替 DEVICE_ID；USER 需替换为设备用户名。SSH 主机指纹和账号认证仍由原 SSH 客户端处理，不自动接受指纹、不保存密码或私钥。Telnet 示例为 `telnet 127.0.0.1 23001`，TCP 仅提供入口。协议标签只用于连接说明，不解析或执行应用命令。

脚本调用可明确传入 `--allow-reverse 192.168.1.1:22`，只有配对返回完全相同的规范化 IP:端口才允许，IPv6 使用 `[地址]:端口`。省略时必须交互确认。网页配对码本身不替代本地确认；旧版助手缺少反向能力声明时返回明确的升级提示，并保留尚未使用的配对码。

每个授权只对应一个设备目标。服务器端口须为 1024–65535，不能占用面板、helper 或 Tunnel 诊断端口；目标端口仍受 TCP_FORWARD_PORTS 控制。正反向合计最多四个映射，每映射最多八条连接、每十秒 32 次连接尝试。初次本地确认期间不启动数据监听或连接目标，ICE 探测也不访问目标。

服务器接收新 TCP 后只保留一个暂停的 socket 和四十秒期限，并通知助手使用一次性连接标识认领。0.6.1 助手为数据通道预留十五秒建立预算（含直连预检及 WSS 握手），就绪记录最多等待十秒；收到该连接的认证就绪记录后才访问固定目标，设备连接期限仍为五秒，发送确认最多五秒。服务端总期限覆盖这些阶段，避免旧版十秒期限提前关闭尚在握手的连接。原有 16 KiB 消息、256 KiB 缓冲与背压继续生效，监听 backlog 为八，待就绪连接仍计入八条并发上限。失败不换通道重连设备或补发旧字节；由原 SSH / Telnet 客户端明确重新连接。

管理断开立即关闭服务器监听、旧 TCP、旧连接标识和直连 peer。30 秒 / 八次握手的恢复预算及退避策略保持不变；恢复同时绑定原映射 ID、方向、名称、两端端口与规范化目标 IP。已确认目标在同一次助手运行中无需再次确认，恢复不访问设备、不重新配对、不重放命令。停止、退出原登录、授权到期或面板重启后不自动重建。

设备目录为服务器 `data/panel/devices.json`：最多 16 项、文件最多 16 KiB、0600，只有一份固定临时文件原子替换；拒绝符号链接、FIFO、非普通文件或非当前用户文件。仅保存名称、协议、目标和监听端口，无账号密码、配对/恢复凭据、设备输出或日志。新建、编辑、删除沿用登录、Host、Origin 和 CSRF 检查，无操作队列。修改或删除条目不改变现有授权中的固定目标；条目已改变时，旧表单需重新选择或保存后再配对。

“助手已连接”只说明通道已授权，不证明设备可达。首次实际 TCP 连接后才显示最近一次目标连接成功/失败，不进行后台探测。目录只记录当前映射的一项结果，无设备网络扫描或历史日志。“复制给 Codex”仅复制固定连接信息，剪贴板拒绝时显示可选择的只读文本和明确复制按钮。

本版支持 SSH、Telnet 等原始 TCP；Telnet 在助手到设备这一段仍按设备原协议通信。串口、设备命令执行器与密码管理不包含在此版本。Windows/Mac 真机需要重新下载 0.6.1 助手，再用实际设备验收认证、目标拒绝/超时、短暂断网及明确停止；Linux 同源助手和模拟设备检查不能代替这一步。

## Mac 首次运行

支持 macOS 12 Monterey 或更新版本，来自固定 Go 1.26.4 的系统要求；[Go 官方版本说明](https://go.dev/doc/go1.26#darwin)。在“关于本机”中显示 Apple M 系列芯片时选 Apple Silicon，显示 Intel 时选 Intel。网页只在打开下载窗口时请求浏览器的架构提示，最多等待 500 毫秒；浏览器拒绝、未提供或超时则保留手选，不从所有 Mac 都可能返回的 `MacIntel` 标识推断实际芯片，不把设备信息写入存储或发送给服务端。[Chrome Client Hints 文档](https://developer.chrome.com/docs/privacy-security/user-agent-client-hints)

ZIP 中固定包含 `codex-cloud-forward`、`Start.command` 和 `README.txt`，前两项有可执行权限。也可在终端进入解压文件夹运行：

    ./codex-cloud-forward

检查版本或依赖许可证：

    ./codex-cloud-forward --version
    ./codex-cloud-forward --licenses

本版没有 Developer ID 分发签名和 Apple 公证，因此首次运行可能出现“Apple 无法验证 codex-cloud-forward 是否包含可能危害 Mac 安全或泄漏隐私的恶意软件”。Apple Silicon 文件带 Go 链接器生成的 ad-hoc 签名，这不等于开发者身份认证或 Apple 公证。Mac 浏览器打开下载窗口时会展开首次运行说明。

确认下载来自自己的工作台、网页版本及 ZIP SHA256 后，可按 [Apple 官方说明](https://support.apple.com/zh-cn/102445) 操作：

1. 先尝试打开解压后的程序；弹出验证提示时，点击“完成”或“取消”。
2. 打开“系统设置 → 隐私与安全性”，向下滚动到“安全性”，找到刚被阻止的 `codex-cloud-forward`，点击“仍要打开”，按系统提示确认。
3. 重新双击 `Start.command`。如果被阻止的名称是 `Start.command`，也需要对该文件完成上述确认。

没有“仍要打开”时，先在 Finder 的解压文件夹中双击 `codex-cloud-forward`，再返回设置查看。受组织管理的 Mac 可能无法由使用者更改此设置，需联系管理员。按文件确认后，macOS 会记住该程序的例外；将来更换下载文件可能需要再次确认。无需重新配对已有映射来做此设置，准备启动助手后再生成两分钟配对码。

要让正式下载免去上述未验证软件的放行步骤，后续需使用 Developer ID 分发签名并完成 Apple 公证；当前 Linux 交叉编译和 Go ad-hoc 签名不能完成这一步。不提供关闭 Gatekeeper 或自动删除隔离属性的脚本。Mac 提示本地网络权限时，允许助手/终端访问可用于局域网探测。

保持启动的终端窗口打开，Ctrl+C 停止；出错时交互窗口显示原因并等待 Enter。启动脚本只执行同目录程序和明确传入的参数，不安装服务、自启动项或写入用户 Codex 配置。

## 直连和中转

使用同一个 HTTPS 网站和配对过程，无需另配局域网证书。网页中“新连接”表示下次创建 TCP 连接时的首选通道，“现有连接”分别统计已经固定在直连和中转上的连接；不会将“新连接可直连”显示成所有连接均已直连。界面和助手显示实际选中的 IPv4/IPv6、UDP、往返延迟及回退原因。

后台探测不连接目标端口。ICE、DTLS 指纹和映射凭据验证通过后，再通过两次独立心跳确认可用；每条新连接还要打开可靠有序的数据通道并发送固定目标开启记录。通道预检失败、尚未请求目标端口时，可以选 WSS。目标开启记录一旦发出，失败结果可能不确定，此连接只会断开，不再经其他通道重复连接或重发字节，由原 SSH、数据库等客户端决定是否重连。

直连期间每三秒进行独立心跳，期限两秒。失效后新连接使用中转，已建立的连接保持原通道；连接不可用时正常断开。中转期间按失败后 15、30、60 秒退避探测；每五秒检查本机网络地址变化，变化后提前探测。存在旧直连 TCP 时优先探测原 peer 的恢复，避免为换 peer 结束可用的旧 TCP。停止、退出原登录和授权失效仍撤销全部通道。

沿用 WEBRTC_ENABLED、WEBRTC_IPV6、WEBRTC_LAN_ADDRESS、WEBRTC_IPV6_ADDRESS 和 WEBRTC_STUN_URL 设置。设置 WEBRTC_ENABLED=0 时仅使用中转。只接受私有 IPv4 和普通公网 IPv6 的 UDP 候选，公共 IPv4、TURN 和 ICE-TCP 未启用。双方主动 ICE 探测允许尝试打通可出站回复的防火墙，并不保证所有网络均能直连。

服务器转发 peer 的 UDP 端口限定为 40016–40047，独立于桌面/网页终端的 40000–40015；Mac/Windows 助手使用 40048–40111。若设备或网络有出站/入站限制，需要允许相应 UDP 通信，否则自动使用中转；程序不改防火墙。助手提供给 SSH 等软件的 TCP 端口始终只监听本机的 127.0.0.1。

管理、授权与协商仍依赖原网站的 WSS 连接，直连减少的是 TCP 数据中转。管理连接断开立即关闭该映射的全部 TCP 和直连 peer，使用恢复凭据在同一服务进程内重新校验登录后再建立新通道，不绕过授权。详见[双栈直连](lan.md)。

## 短暂断网恢复

助手声明恢复能力后，首次配对返回独立的 256 位恢复凭据，仅绑定原映射、原登录、目标 IP 和两端端口，不能用于打开数据连接。服务端只保留其摘要，助手只放在内存，不写文件、URL、命令行或日志。原一次性配对码不会再次提交。恢复通过同源 `/forward/resume` WSS 接口认证，沿用 Host、Origin 和固定子协议检查。

服务端检测到控制断开后，将映射保留在最多 30 秒的恢复窗口中，仍占原有四个名额之一。助手按 1、2、4、8 秒退避，在自身 30 秒预算内重试；每个服务端恢复窗口最多接受八次握手。未完成握手不延长原期限；恢复请求也可替换仍半开的旧控制连接。每次恢复换发数据通道凭据，旧凭据、旧 peer 和旧异步回调失效。只有重新绑定本地端口并确认监听后才接受新 TCP，直连随后重新探测，探测本身不连接目标。

网页显示“正在自动恢复”、剩余时间或恢复握手状态，仍可通过原确认框停止。明确停止、退出原登录、授权过期或撤销、协议或证书错误、本机端口被其他程序占用，以及恢复预算耗尽均终止恢复。握手和网络故障的检测本身仍受既有五秒启动、十五秒 ping 和四十五秒读取期限影响；30 秒从检测到故障后计时，不保证实际断网后立即恢复。服务端授权窗口可能比助手先到期，服务端拒绝为准。

Ctrl+C 会立即停止本地恢复；通道仍可达时通知服务端关闭映射。断网期间退出或强制关闭助手无法通知服务器时，服务端在恢复窗口到期后清理。服务端不持久化恢复状态，重启后旧凭据失效，需要在网页重新配对；不会通过保存旧凭据在面板重启后重建授权。

## 故障提示

助手区分配对码无效、过期或已使用、本机端口占用、监听失败、证书验证失败、域名解析失败、连接超时、访问认证被拒绝和网站不可用。绑定本机端口失败会通知服务器并释放该映射，网页可看到同一原因。

目标端口无法连接、目标连接超时或异常断开只结束对应 TCP 连接，映射仍保持开启；检查目标服务后，用原客户端手动重试即可，成功建立目标连接后清除上次连接错误。不会主动重复连接或重发字节。助手每次运行的 TCP 错误、直连状态和恢复状态提示各最多二十条及一条达到上限的说明，跨恢复累计，不因重新连接清零；之后可在网页查看最新状态。

“20 条上限”仅限制控制台同类日志数量，不限制连接、重连或直连探测，不影响数据转发。反复探测产生的状态变化也消耗日志次数，即使只有一条 TCP 连接也可能达到。实际连接限制是每映射八条并发及每十秒三十二次新连接尝试；对应提示分别为 `connection_limit` 和 `rate_limit`。

0.6.1 将单条连接的故障区分为建立通道超时、等待通道就绪超时、数据通道收发超时、助手侧 TCP 对端断开或接收端阻塞。单条数据连接失败不代表映射授权失效，网页仍显示在线时可由 SSH/Telnet 客户端重新连接，无需重新配对；管理授权失效、停止或恢复预算耗尽时才重新配对。直连超时进一步区分 UDP 路径未打通、DTLS 加密握手未完成及通道认证未就绪，不能从这些日志计算网络丢包率。

网页“最近结束的映射”最多显示八条、保留十分钟，刷新页面仍可查看。只在面板内存保存目标 IP、端口、时间、固定原因及凭据摘要，不写磁盘；面板重启清空。正常停止或重启、退出原登录、授权到期和心跳超时有明确原因；进程被强制结束或网络突然断开无法确定远端根因，提示助手关闭或网络中断。

本机端口只绑定 127.0.0.1，不能通过局域网地址使用。助手不安装服务、不设置自启动、不保存密码或配对信息，不写配置、数据或流量日志。Windows 程序当前未进行 Authenticode 签名，Mac 首次打开说明见上文；下载界面提供 SHA256，各平台的系统提示及兼容性需要在真实设备上验证。

## 服务器允许的目标端口

默认 `TCP_FORWARD_PORTS=*`，允许在网页填写 1–65535 的目标端口。已有 .env 中显式配置的列表仍生效，可继续限制为最多 16 个端口：

    TCP_FORWARD_PORTS=22,5432,8080

留空可禁用新映射：

    TCP_FORWARD_PORTS=

面板、内部 helper 和 Tunnel 诊断端口始终排除，对所有目标 IP 生效。修改后只需重启网页面板，桌面和 tmux 任务继续运行。管理员启用的端口代表工作台用户可经服务器连接到可达 IP 上的这些 TCP 服务。

## 构建

构建使用 Go 1.26.4、Gorilla WebSocket 1.5.3 和 [Pion WebRTC 4.2.26](https://github.com/pion/webrtc/releases/tag/v4.2.26)，全部依赖在 go.mod 和 go.sum 锁定。服务端用既有 Python 标准库生成 Mac ZIP；Windows 用户只运行 exe，Mac 用户运行解压后的程序，均无需安装 Go、Node.js 或 Python。构建不自动安装或升级工具链。

    npm run build:forward

默认服务器地址读取 PUBLIC_ORIGIN 并嵌入程序，之后双击仅需输入配对码。也可显式指定构建地址：

    npm run build:forward -- https://example.com

或在运行时覆盖默认地址：

    codex-cloud-forward-windows-amd64.exe --server https://example.com

公网地址必须是 HTTPS 根地址，无跳过证书校验选项；仅回环测试允许 HTTP。配对码从标准输入读取，不通过 URL 或命令行参数传递。--version 显示版本，--licenses 显示随程序内嵌的依赖许可证。

产物只保存在被 Git 忽略的 data/forward-client：两个 Windows exe 和两个 Mac ZIP，均为固定文件名、每个最多 32 MiB；一个最多 4 KiB 的 manifest.json，最多四项且不接受重复架构。构建期间至多一个 helper.tmp（32 MiB）、一个 package.tmp（32 MiB）、一个 manifest.tmp（4 KiB）及一个空 .build.lock；单一构建互斥，正常退出清除临时文件。Mac 包检查 Mach-O 架构、可执行类型、macOS 12 目标及 ARM64 签名结构范围，固定三项 ZIP 内容和权限；这不代替 macOS 的实际签名验证。下载要求登录，每次只读取固定文件名的普通文件，拒绝符号链接，最多同时两项下载。产物和清单不提交 Git。

如果启用了额外的 Cloudflare Access 网页登录，助手还需要能通过该外层认证；首版不读取浏览器 Cookie、不自动代办 Access 登录。工作台自身账号密码登录与一次性授权不受影响。

## 协议与资源上限

- 网页创建、停止映射校验 Host、Origin、登录和 CSRF，不依赖桌面页面控制权；读取请求体后再次校验登录和 CSRF，延迟请求不能跨退出登录或授权失效执行。
- 最多四个待配对或活动映射。配对码和运行凭据都是 256 位随机值，只保存摘要和少量元数据于内存；每个授权仅允许一个明确目标 IP、目标端口和本机端口。IP 输入最多 64 字符，经字面地址验证并规范化后保存；IPv4 映射的 IPv6 转为 IPv4，不进行 DNS 或 shell 调用。旧网页省略目标 IP 时仍使用 127.0.0.1。
- 助手用一次性配对码认证 /forward/helper，获得仅用于该映射的流凭据；中转的每条本机 TCP 连接独立认证 /forward/data。使用 codex-forward-v1 子协议，凭据放在 Authorization 请求头，保持 Host 和 Origin 校验；不会把工作台登录 Cookie 交给助手或目标服务。
- 新助手用 `X-Codex-Forward-Resume: 1` 声明恢复协议，独立凭据仅能认证 /forward/resume；旧助手保持原有断线撤销行为。恢复中最多四个映射、每个一项控制握手、每窗口最多八次尝试和 30 秒期限；每次握手最多五秒，并受剩余恢复期限约束。最近结束记录额外保留恢复凭据摘要，用于返回明确的停止、撤销或超时原因，仍最多八条、十分钟，不向网页暴露。
- 新助手显式声明直连能力，SDP 只在已认证管理通道传输，单项最多 32 KiB、控制消息最多 48 KiB、控制发送缓冲最多 64 KiB。每个映射最多一个 peer，全局最多四个（包含关闭中），全局协商不排队、最多一项同时进行，同一映射十秒内不重复协商；旧直连 TCP 未结束时不替换其 peer。
- 直连使用 DTLS 验证 WSS 协商的证书指纹，健康通道再次校验映射凭据，数据通道只允许固定目标开启记录。可靠有序 SCTP 通道采用四条已确认记录的窗口，每条最多 16 KiB；目标写入受背压时不再释放确认额度，避免在接收端无限排队。FIN 与普通数据保持发送顺序并参与确认。
- 每个 peer 接收窗口最多 1 MiB；服务端在分片重组前限制最多 32 项流元数据、1024 个未重组分片、2048 项乱序包标识及 1024 项重复标识。每个助手 peer 最多创建 128 条数据通道，达到上限后新连接暂用中转，等待旧直连 TCP 结束后再轮换 peer，避免依赖库保留的已关闭通道元数据长期累积。每次助手运行最多输出二十条通道变化提示及一条达到上限说明。
- 正向模式由服务端确认助手已绑定本机端口后才允许连接目标，配对后启用期限五秒；反向模式首次本地确认最多六十秒。数据通道建立最多十五秒，就绪最多十秒，目标连接最多五秒；反向服务器 socket 从接受到目标确认总共最多四十秒。
- 每个映射最多八条并发 TCP 连接，每十秒最多 32 次连接尝试。二进制消息最多 16 KiB，服务端应用发送缓冲和目标写缓冲分别最多 256 KiB；慢接收方施加背压，超限关闭对应连接。
- TCP EOF 使用独立 FIN 记录，保留半关闭后的响应。原始字节不进入 PTY、输入助手或 shell，不解析 SSH/数据库协议，不执行任意命令。
- WebSocket 每十五秒检查心跳，探测最多等待三十秒匹配的 Pong；旧 Pong 不确认新探测。服务端主动暂停 WebSocket 读取时，Pong 读取也会暂停，期间不误判为网络失联，但继续发送 Ping 维持助手读期限；连续暂停最多六十秒，按 TCP 接收端阻塞清理，恢复读取后重新探测。助手数据阶段读期限四十五秒、写期限十五秒；写入助手侧 TCP 对端超时单独报告。授权到期或失效最多五秒内清理，显式停止、退出原登录立即撤销。TCP 立即关闭，控制通道最多等待一秒发送固定原因，最多八个关闭中的通道，超限终止最早通道。
- 状态最多四项活动映射及字节计数，另保留八条最近结束原因十分钟，不保存原始内容、连接明细或流量日志。保留的配对码摘要仅用于返回过期/已用提示，不能再次配对；不向网页暴露摘要、登录标识或运行凭据。网页仅在对话框打开且前台时每三秒查询，最多一项在途请求；配对码仅当前窗口暂存，关闭窗口、隐藏页面或失去登录授权会清空，复制只在点击时发生。

    npm run check

    npm run test:desktop
    npm run test:forward
    npm run test:forward:package
    CHROME_PATH=/usr/bin/google-chrome npm run test:browser -- test/browser/forward.spec.mjs test/browser/web-terminal.spec.mjs

Node 单元测试使用真实 WebSocket 和隔离 TCP 服务，另有基于模拟通道的背压/重组资源上限测试；桌面与管理执行器为 fixture。浏览器测试使用真实 Chrome 和模拟 RFB，覆盖刷新和接管保留映射、不同页面管理、固定故障提示和丢失响应不重试；通道统计界面用例使用模拟诊断数据，不将其当成真实网络通道验证。

test:forward 使用带 race 检测的 Linux 同源助手、临时证书、真实 TLS/WSS 代理、真实 Pion/werift UDP/DTLS/SCTP 和 TCP 服务。覆盖 8 MiB 数据、双向半关闭、心跳、探测不连接目标、旧中转流保留、不同通道并存、直连失效/恢复、peer 实际关闭后的后台重建、目标就绪丢失不回退重连、明确停止撤销两种通道，以及原有端口占用、目标不可达、输出上限和证书拒绝。新增实际关闭管理连接、暂时返回 503 后恢复同一映射和监听、原 TCP 关闭且配对码/字节不重放、恢复中明确停止、持续故障的真实 30 秒预算耗尽，以及管理恢复后重建直连 peer。健康失效、就绪丢失和故障代理使用受控故障注入，数据仍经真实协议栈；IPv6 在主机实际分配的公网 IPv6 上验证，无地址时明确跳过。所有检查均不连接工作中的 Codex 或真实 SSH 服务。

`test:forward:package` 交叉编译两种真实 Mach-O 并核对 ZIP CRC、程序字节、固定内容、执行权限、最低系统目标、ARM64 签名结构和 Go 构建元数据；另用隔离的脚本替身验证启动器对空格、中文和字面参数的保留，不声称在 Linux 上执行了 Mac 程序。Windows PE/Mac Mach-O 结构检查不代替各平台真机验收，本机公网 IPv6 也不能代替跨运营商验收。

Mac/Windows 真机可依次检查：初次打开和版本正确、配对后 SSH 登录、SFTP 上传/下载同一文件并核对 SHA256、保持一条 SSH 后切换直连状态确认旧连接保留，再短暂断网测试映射恢复及旧 SSH 由原客户端重连，最后明确停止并确认不再恢复。面板重启后重新配对；需要实际目标服务的账号，项目不代为保存该密码。

## 授权期限与脱敏诊断

映射行显示创建时间对应的授权来源（本次或其他登录）、管理员/临时账号和实际来源登录到期时间。配对码两分钟与登录授权期限分别计算；锁屏不续期。拥有管理权限的页面可查看现有映射，锁定及临时页面继续按原规则仅显示允许查看的反向映射，不提供原始登录标识。

“复制诊断报告”仅在打开的映射窗口里使用当前可见状态，包含路径选择、并发/流量、目标最近成功或失败、恢复期限及最近结束的固定错误码。报告省略目标 IP、端口、设备名、映射标识、配对码、恢复凭据和登录信息；不会采集传输内容或写磁盘。剪贴板拒绝时显示可选择文本和明确的复制按钮；关闭窗口、隐藏页面或权限变化时清空。助手控制通道故障、目标设备故障与直连协商失败分别说明；中转可用时直连失败不代表映射离线。

兼容的前端发布可使用 `npm run reload-ui` 保持活动连接，操作范围与限制见 [前端热更新](ui-updates.md)。后台重启仍会结束映射。
