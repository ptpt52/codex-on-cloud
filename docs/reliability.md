# 服务生命周期与恢复

2026-11-06。面板、管理器、虚拟桌面和桌面执行服务各自运行；浏览器关闭或连接切换不结束桌面任务。

## 窗口与剪贴板

`codex-cloud-actions.service` 持有管理器后来打开的 xterm 窗口及前台 xclip。该服务通过 `PartOf`、`Requisite` 和 `After` 关联桌面，只有现有桌面运行时才能启动；它的启动请求不会自动创建桌面。管理器使用认证的 `actions.sock`，该 Unix socket 为 0600，父目录为 0700。

接口仅接受两个固定动作：打开八个固定槽位中已有的 tmux 会话，以及设置最多 32 KiB 的剪贴板文字。终端只附加已有会话，不创建任务。粘贴先等待前台 xclip 的固定就绪消息，再由原管理器发送 Ctrl+Shift+V；Enter 仍需单独操作。确认丢失或超时不改走其他路径重发。

最多八个窗口子进程、一个稳定的剪贴板 owner；替换期间最多两个 owner。服务最多四个连接，只接受一个正在进行的动作，无等待队列，请求最多 200 KiB，响应最多 2 KiB。xclip 就绪信息只保留 256 字符，不保存或输出文字。管理器重启不会结束这些进程；明确重启桌面执行服务会关闭它持有的窗口和选区，tmux 任务仍独立存在。

## 面板异常恢复

只有面板增加有限自动恢复：异常退出后等待五秒，60 秒内最多启动三次。桌面、管理器、执行服务保留显式启动策略；Tunnel 沿用已有策略。手动停止面板不会触发自动恢复。上限耗尽后先检查：

```sh
npm run native:status
journalctl --user -u codex-cloud-panel.service -n 50 --no-pager
```

处理故障后可明确解除失败状态并启动：

```sh
systemctl --user reset-failed codex-cloud-panel.service
npm run native:start
```

面板恢复后沿用有效登录。原页面只有在服务端仍无人占用时才能恢复认领；请求处理时若另一页面已占用，则要求用户明确接管。恢复不会重新发送提示、按键、粘贴或审批，尚未确认的输入仍显示结果未知。端口映射的内存授权随面板重启失效，仍需重新配对。

连接状态增加面板自动恢复次数及管理器/桌面执行服务状态。诊断只读取三个固定 systemd unit 的指定字段，不读取日志、进程命令或环境。一次命令最多 4 KiB、1.5 秒，共用一个在途请求及三秒缓存。旧 systemd 可能在启动次数耗尽后仍报告 `Result=signal`，界面结合固定策略及失败状态显示自动恢复已停止。

## 验证与更新

`npm run test:lifecycle` 使用真实隔离 Xvfb/xterm/tmux/clipboard 和实际管理器、执行服务入口。杀掉整个管理器进程组后，窗口 PID、任务 PID 和剪贴板保留；重建管理器、字号替换及重复设置选区均通过。该检查使用进程组模拟停止后代，不声称是 systemd cgroup 验收。

`npm run test:recovery` 要求可用的 systemd 用户管理器。仅对唯一命名的临时测试服务注入 SIGKILL，用真实 Chrome 和面板验证有效登录、草稿、不抢占、不重放、启动次数限制和手动停止。VNC 和管理上游是 fixture；没有结束生产服务或向 Codex 输入。

升级已有实例时，安装新 unit 并启动桌面执行服务，再在管理器空闲时更新管理器和面板。已有窗口和选区的进程归属需在重启旧管理器前检查；旧版本创建且仍属于管理器的进程需要保护。本次更新保留正在运行的虚拟桌面，不为加载新的桌面监督器脚本自动重启桌面。

前台 xclip 的选择所有权及就绪消息依据 [xclip 源码](https://github.com/astrand/xclip/blob/master/xclip.c)核对，并由隔离真实 X11 检查验证；systemd 恢复行为由本机 237 的真实临时服务验证。

## 首帧与分辨率同步

本机 x11vnc 0.9.13 在初始画面仍传输时缩小尺寸，可以复现 `MIT-SHM / X_ShmGetImage / BadMatch`；另能复现 X 已变为 1280×720，RFB 仍显示 1600×1600、未收到 DesktopSize。上游 [watch_loop](https://github.com/LibVNC/x11vnc/blob/e2b726a8c0464051afda01648072af6835aaa5f7/src/screen.c#L4574) 在新客户端接入的前半秒跳过部分 X 事件处理，与这个启动窗口一致。

客户端现在分别管理键鼠空闲和尺寸准备状态。固定 noVNC 1.7.0 完成首个含像素的完整更新后，再等待 650 毫秒，才允许窗口适配和手动立即应用分辨率。后台连接探测和换路继续使用原来的空闲状态及期限。只保留一个启动定时器，断开、替换实例或离开页面时取消；解码器的两个临时挂钩在首帧后恢复原方法。升级 noVNC 时需要复核这两个固定版本接口。

原生 VNC 启动参数统一到 `native/vnc.mjs`，从启动起明确使用 `-xrandr resize` 的 X 错误保护，并用 `-norc` 保持虚拟桌面的固定参数。保留 inetd、私有 Unix socket 和原有禁止远程控制等选项。新参数在下一次明确重启桌面监督器时加载；本次先更新面板中的尺寸准备逻辑，当前桌面和任务继续运行。使用当前旧 VNC 参数的隔离测试也验证了相同的首帧等待流程。

最终原生检查在静默模式连续六轮通过，每轮七次尺寸变化、同一 RFB 连接和原 tmux 任务；旧启动参数另外通过两轮。浏览器通过延迟首帧的真实 noVNC 流程验证：等待期间零尺寸请求，像素到达并就绪后只调整一次，观看连接和任务保持不变。

## 终端结束与保活

主终端和七个辅助位置共享最多八个名额。管理界面的“结束终端”要求二次确认；HTTP/Unix 管理接口仍检查登录、控制权、CSRF 和明确的 `confirm: true`。结束时使用固定会话名、有效的窗格 ID/PID 和单窗口/单窗格布局，在 tmux 的 `if-shell -F` 格式分支内核对后执行固定 `kill-session` 动作，不启动 shell 解释用户输入。过期身份或布局改变会拒绝；命令超时或结果丢失显示未知，不自动重试。

纯终端后台已有一个不接收网页输入的 `codex-host` 保活会话。旧桌面第一次明确结束终端前，在现有私有 tmux 服务内补建同名固定 `sleep infinity` 会话，最多一项；不创建由面板或管理器持有的新 tmux 服务。最后一个用户终端结束后，后台服务和原 tmux 服务身份保留，可在空闲位置明确新开。固定保活会话不计入八个名额；仅此固定布局/命令可从原单终端桌面恢复检查中排除，异常保活布局仍禁止恢复。

结束会话会关闭其 PTY，结束正常的 shell 和前台任务；自行脱离会话或忽略关闭信号的进程不保证结束，不遍历或杀死同用户的其他进程。已有其他终端、桌面进程和映射保持原有生命周期。浏览器关闭或断线始终只结束观看连接。“打开终端”及窗口恢复仅附加已有会话；创建新 shell 必须使用明确的新开动作。未新增持久文件、输入记录或操作队列，空闲位置元数据最多八项。

终端标签仅展示运行中的会话和末尾一个共用的新开占位，满额时占位禁用。显示最多九个条目（八个实际终端加一个占位），后台仍使用原八个固定名额。前端占位标识 `new` 仅供界面选择，实际创建仍发送经过验证的固定空闲名额；它不成为输入目标或持久草稿身份。关闭确认前不激活所点标签；仅当前目标关闭成功后选中末尾占位，原终端身份用于保留旧草稿和刷新后的身份校验。关闭其他目标只移除对应标签，不修改当前选择、草稿和观看连接。其他终端任务继续运行，点击新开时才创建新 shell。快捷关闭使用独立的相邻按钮，避免嵌套按钮导致事件误触切换或新建；控制权、中文组合输入及原身份保护继续适用。
