# 端口映射协议与发布边界

用户流程见[固定八个助手](forward.md)，设备参数见[串口接入](serial.md)。使用固定槽位 v2 配置，普通升级保留已有 v2 key 和规则；更早格式需显式全新部署，不提供旧配对入口。

## 固定槽位与 key

`/api/forward` 声明 `managedHelpersProtocol: 2`，只返回端口策略、并发上限和已认证下载列表。`/api/forward/agents` 返回固定八个槽位：稳定 ID、编号、名称、key 版本、在线状态、最新清单及规则；列表不含 key 或 secret。

管理员通过 `GET /api/forward/agents/key?id=<id>` 读取选中助手的 key，`POST /api/forward/agents/rekey` 携带 ID 和原 key 版本单独重新生成。`POST /api/forward/agents/visibility` 携带 `{id, revision, visible}`，单独控制临时账号能否查看此助手 key，具有独立版本号，默认关闭，不重建 key 或规则。规则接口为 `rule`、`rule/remove`，手动清单请求为 `inventory`。写入体最多 4 KiB，沿用 Host、Origin、登录、CSRF、规则归属及读取请求体后的再次鉴权。锁定、临时账号和被接管页面不能操作这些写接口；key 响应不缓存。版本冲突返回 409，结果未知不自动重试。

临时账号的 `GET /api/forward/agents` 只返回已开放助手的 ID、槽位、名称和 key 版本，并标记 `readOnly: true`，不返回规则或设备信息；无开放助手时返回 403。读取或“刷新 key”使用同一个只读 key GET，未开放助手返回 403。每次读取都校验当前登录及可见设置；临时账号到期、撤销或设置关闭后拒绝读取。已复制的长期 key 生命周期保持独立。

首次初始化将八个随机 ID、独立 256 位 secret、key 版本和规则写入 `data/panel/forward-agents.json` v2。文件最多 128 KiB、0600，仅一份固定临时文件；原子改名并同步目录，拒绝符号链接、特殊文件、错误归属、宽松权限和超限文件。名称由固定编号生成。既有 v2 普通重启不变；旧格式明确拒绝，替换流程由部署者显式执行。

key 是 `COCA2.` 加 base64url JSON，包含版本 2、完整服务器入口、节点 ID、助手 ID 和 secret。服务器按 `SHA256(agentId.secret)` 验证运行授权，原始 secret 保留在上述私有文件，以便管理员再次复制。浏览器只暂存当前助手的 key，切换助手、关闭、隐藏或失去管理权限清空，不写本地存储、URL、日志或诊断报告。

## 助手管理与规则运行

助手通过 `/forward/agent` WSS、`codex-agent-v2`、`Authorization: Bearer agentId.secret` 和 32 位随机 `X-Codex-Agent-Instance` 接入。一个槽位同时只接受一个进程；另一进程的新连接返回 409，不终止旧连接；同一实例在旧连接尚未释放时收到可重试的 `resume_busy`，等待后再连接。`agent-ready` 和 `rules` 使用版本 2，管理链路只传配置、清单及结果，不传业务字节。

每条启用规则获独立、短时的运行授权，绑定规则版本、映射 ID、方向、监听端口和固定目标。助手在 `/forward/helper` 认证，原映射恢复经 `/forward/resume`；协商 `poolProtocol: 1` 后业务数据使用下述共享传输，未协商时保留 `/forward/data` 和独立 peer。凭据仅在控制台与助手内存，不发给网页。握手必须匹配下发配置，不能改变目标、重复消费授权或重发旧数据。单进程用有界协程管理多规则，修改只取消并重建这一条；失败规则最多每十五秒重试，其余规则继续。

规则编辑、停用或删除后，先撤销该规则的旧运行授权、控制及数据连接，再判断助手管理链路是否在线。每次运行鉴权同时检查 key、规则仍存在且启用、规则版本一致；离线助手也不能凭旧授权继续传输或建立新连接。未变更的其他规则保留，新的规则版本待管理链路恢复后下发。

目标只接受具体单播 IPv4 / IPv6，不 DNS 解析或调用 shell。服务器回环监听端口跨助手唯一，助手本机端口仅在本槽位内唯一。相同助手不能启用两条占用同一串口路径的规则。端口策略重新应用时校验，不符合时显示规则错误，不阻止读取保存的配置。

key 重新生成立即撤销该助手控制和数据通道，保留规则；网页退出 / 锁屏不撤销。助手按 1、2、4、8、15 秒退避持续连接原节点。同一进程重连保留健康映射，新实例重新建立。节点重启后凭 key 和期望规则重新签发运行授权，旧运行凭据及 TCP 不复用；业务客户端自行重连，不重放字节或设备命令。

## 助手共享传输

`agent-ready.transportProtocol: 1` 声明连接池。助手使用独立 `/forward/transport` WSS、`codex-forward-pool-v1`、相同 key、节点身份和实例 ID 接入；必须先由管理连接注册实例。节点重启后数据恢复早于管理注册时返回可重试的 `helper_reconnecting`，不同实例仍拒绝。一个助手实例只保留一条共享 WSS 和一个 RTC peer，不跨节点、key 版本或助手复用；管理链路不承载业务字节。

池握手返回内存中的独立随机 token，RTC 健康通道验证该 token。每条直连或中转流另提交 `{type:"open", mapping, token, id?}`，验证当前规则的映射 ID、独立 stream token、助手实例与授权；反向 id 必须是服务器尚未消费的接受项。探测和通道预检不连接目标。首次提交 open 后任何失败都不换路重试；规则停用、删除或编辑只结束该规则的流，重新生成 key 或新实例接管则撤销整个旧池。

新节点在 `rtc_config` 声明 `preflight: 1`，助手在健康通道 `auth` 请求，节点在 `ready` 确认。协商后，每条数据通道先收到唯一的 `{type:"preflight", ready:<bool>}`，不计入业务序号。两端均在打开目标前检查是否还可容纳一块业务数据；额度不足时，新连接使用原有 WSS，健康 peer 与既有 TCP 保留。通道打开与准入合计最多 1.5 秒；未协商时保持旧握手。准入仅反映检查当时的容量，已接纳的流仍按其原路径施加背压。

WSS 二进制帧为 1 字节操作、4 字节大端流 ID 和最多 16 KiB 正文：1 为文字记录，2 为二进制，3 为关闭，4 为预检打开，5 为预检确认。每条物理连接的 ID 从 1 单调增加、不重用，预检及等待 open 最多十秒；关闭后交错到达的旧记录丢弃，未知未来 ID、重复打开或超限帧关闭该 WSS。各流独立使用四项确认窗口、256 KiB 发送缓冲及逻辑暂停，不暂停物理 WSS；慢流不占用其他规则的确认额度。

WSS 每三秒发送应用 nonce 心跳，等待最多六秒无应用进展；有效业务记录也证明进展，代理自身的 Pong 不替代应用检查。RTC 通过自身健康通道返回路径状态，不依赖共享 WSS 在线。中转断开仅关闭该 WSS 上的流，健康直连及规则控制连接保留；备用按 1/2/4/8/15 秒恢复。既有 TCP 不跨连接迁移，字节不重放。

每助手池最多 128 条中转逻辑流、每十秒 256 次预检，物理 WSS 发送缓冲 1 MiB。中转按流轮转发送，每次一个记录，预检与确认优先但不打乱业务数据 / FIN；最多一个在途写入、十五秒期限。每流待发最多 32 项 / 256 KiB，共享待发总量最多 16 MiB / 256 个含关闭中的流组。文字信令最多 48 KiB、每十秒 40 条。每助手直连同时最多 24 条流（含正在打开），超额新 TCP 走 WSS。空闲且没有启用运行规则时释放 RTC，保留有界的 WSS 备用；不增加持久队列或流量日志。地址提示仍按规则保存，池内去重合并最多四个地址，每轮另补最多四个候选。

Go 助手同样使用单一 WSS 写入者，控制与数据待发队列各最多 128 项。预检、确认和 FIN 优先；每流前一次写入完成后才允许下一次写入，保留业务顺序。控制排队与写入合计最多五秒，数据最多十五秒；过期或属于旧物理连接的项目不会在新连接上发送，旧池的信令也不能越过 token 换代。

## 直连、恢复与资源上限

新业务 TCP 独立选择可用的局域网 IPv4 / 公网 IPv6 / IPv4 NAT 打洞 UDP / DTLS 直连，否则使用 WSS；当前助手不使用 TURN 或 ICE-TCP。SDP 经已认证 WSS 协商并检查证书指纹，通道再次验证映射凭据；探测不连接目标。目标开启请求已发出而结果不明时，不换路重连或补发字节。

网页分别显示每助手控制连接、新 TCP 的首选路径及现有 TCP 的直连 / 中转数量。旧 TCP 固定原通道，不因新连接可直连而改变统计。地址提示按规则保存，修改规则重建该规则；不会把枚举出的网卡 IP 自动当作目标或额外候选。

助手收到当前协商的明确拒绝后立即结束等待并释放该次 ICE 资源；资源忙使用现有五秒检查节奏短退避重试，不消耗网络故障的 15 / 30 / 60 秒退避。已关闭直连时等待新配置启用。只读探测不连接业务目标，已有 TCP 不迁移、不重放。

- 固定八个助手，每助手十六条期望规则，全节点最多三十二条活动映射。转发 peer 全局最多八个（含关闭中），协商同时最多一项；共享池中的多规则不重复占用 peer 名额，超额新 TCP 可经 WSS。
- TCP 每规则最多八个客户端、每十秒 32 次连接尝试；串口一个客户端。二进制块 16 KiB，服务端应用发送与目标写缓冲各 256 KiB，慢端施加背压；FIN 按原顺序传递，保留半关闭。
- 直连采用可靠有序 SCTP，在已认证健康通道协商 4 / 8 / 16 项确认窗口；新节点默认选择八项，即每流最多约 128 KiB 未确认业务数据。未声明能力时仍使用四项；窗口固定到该 peer，不在传输中变更。每侧共享发送额度仍为 512 KiB，其中 128 KiB 留给不超过 256 字节的建链和交互记录，大块数据最多占用 384 KiB。同类等待者按序获得额度，小记录可绕过等待大块额度的流；关闭流立即归还两类额度。
- RTC 发送在当前可发送的流中轮转，每次一个记录；ACK 与健康检查优先，放不下的大控制记录不会挡住其他流中仍可发送的小消息，业务数据和 FIN 保持原顺序。两端交给 SCTP 的待发数据总量最多 128 KiB，控制消息另留 64 KiB；应用队列每 peer 最多 1 MiB / 32 个含关闭中流组。节点每组最多 64 项 / 512 KiB，控制队列最多 512 KiB，以容纳原有 256 KiB 服务响应；助手每组最多 32 项 / 512 KiB、控制队列最多 64 KiB。原生缓冲未腾出时不恢复 TCP 读取，正常收尾先交付最后 ACK，最多等一秒；撤权直接清空队列。
- 每 peer SCTP 接收窗口仍为 1 MiB；分片前限制 32 项流元数据、1024 个未重组片、2048 项乱序标识及 1024 项重复标识。乱序记录满额时丢弃新的后续 DATA 并继续 SACK，保留补齐缺口的机会，由 SCTP 自身恢复；不扩大记录表，也不重放业务。每助手 peer 最多创建 128 个数据通道，超限后新连接先中转，旧通道结束后再轮换。
- 服务端 UDP 40016–40047，助手 UDP 40048–40111。程序不改防火墙。每侧最多四个额外去重提示候选，保留自动候选，不添加监听端口。
- 助手整体 `/forward/agent` 断开只影响配置和清单，不等同于每条映射断开。单条 `/forward/helper` 控制连接恢复窗口为原 30 秒、最多八次握手，每次最多五秒且受剩余期限约束；保留健康数据与 peer，期间暂停新客户端。窗口耗尽关闭原映射，长期管理恢复后可新建，不能恢复旧 TCP。
- WebSocket 每十五秒检查心跳，最多三十秒等待匹配 Pong；主动背压暂停读取时不误判断网，但连续暂停最多六十秒。助手读取四十五秒、写入十五秒；数据就绪十秒、目标连接五秒，反向接入总期限四十秒。
- 管理消息 48 KiB、发送缓冲 128 KiB、每分钟 120 项。策略通知每助手最多一个待处理定时器，规则结果队列 32 项、清单请求一项、管理读取队列一项。stdout 每分钟 120 次、每次 8 KiB，不写日志文件。
- 清单每三十秒及手动请求上报：128 个串口、128 张网卡、每卡 32 个 IPv4、总计 1024 个，序列化最多 32 KiB。只保留每助手最后一份和时间，超出标记截断；包含回环、停用及无 IPv4 网卡。串口枚举子进程最多三秒、32 KiB 输出，不打开设备。
- 最近结束运行信息仅保留八项、十分钟，用于固定错误及恢复诊断；不保存业务内容、连接明细或流量日志。

## 多节点与下载

自建中心保留完整 `/node/<slug>/`。CF 网关只对固定 `/forward/agent|helper|resume|data|transport` 和 Bearer 凭据接受 `X-Codex-Forward-Node`，只读查询对应节点并再次核对返回 ID，不改变浏览器默认路由；未知节点或新旧 DO 不一致返回 503，不回退其他节点。拒绝握手保留节点身份及固定错误码，避免鉴权错误经网关变成可重试的 502。

助手下载可经独立 WebRTC 文件通道或 HTTPS，沿用同一登录、节点路径、发布版本、尺寸和 SHA256；单项 32 MiB、五分钟期限、同时最多两项服务器下载。直传失败不自动经 HTTPS 重复下载，不认领桌面或 PTY。受限服务只保留助手下载元数据读取，不再提供旧映射创建 / 停止 RPC。

## 构建与原子发布

构建命令先检查固定 Go 1.26.4；版本与依赖见[构建器](../scripts/build-forward.mjs)、[go.mod](../client/forward/go.mod)和 [go.sum](../client/forward/go.sum)。公网地址支持 HTTPS 根地址与 `/node/<slug>/`，产物绑定最终入口。

产物只保存在被Git忽略的`data/forward-client`。新构建在`releases/<32位随机版本号>`中生成完整的两个Windows exe、两个Mac ZIP和至多4 KiB的v2清单，全部成功后才原子更新至多256字节的`current.json`入口；中途失败保留正在提供的版本。即使入口改名后目录同步报错，也不会删掉已经生效的版本。下载链接固定版本号，下一次构建清理更早版本后旧链接返回410，需刷新列表；已打开文件描述符的下载继续完成。

发布入口还会在文件租约内及提交前比较构建开始时保存的原始内容；构建期间入口被修改时拒绝覆盖，旧版本和人工修改保留。首次发布要求入口仍不存在，不会替换并发创建的入口。

最多保留两个版本目录，含当前版本与前一版本或正在构建的版本；下一次构建开始回收非当前目录。每版本四个产物各至多32 MiB，构建时至多一份helper.tmp、一份package.tmp及有界清单/入口暂存，产物生成后验证大小。现有根目录v1清单和四个旧产物原样保留，旧面板继续使用它们；更新面板后才识别新入口，部署应先升级后台再运行新构建。新格式最多约320 MiB已校验产物/临时数据，保留旧产物时另加至多128 MiB，不保存构建日志或任务队列。遇到非工具生成的目录、链接或额外文件时拒绝清理，不删除其他内容。

Mac包检查Mach-O架构、可执行类型、macOS 12目标及ARM64签名结构范围，固定三项ZIP内容和权限；这不代替macOS实际签名验证。下载仍要求登录，文件名和版本号固定校验，拒绝链接及特殊文件，最多同时两项下载；所有产物、清单和运行锁都不提交Git。

构建复用系统flock，`.build.lock`保留为0600的空锁inode，不再把文件存在当作永久占用。默认执行器由持锁Python助手直接管理固定的go/git/python3子进程，不经过shell，不排队；父Node被杀或取消时，先结束并回收独立编译进程组和被收养后代，再释放租约。子命令还继承锁描述符，避免监督器异常退出时编译器立即失去互斥。构建只在原生Linux运行；每租约最多32条顺序命令，每条请求128 KiB、输出16 KiB、最长180秒，Go包编译并行数2。未发布的唯一版本目录由下一次持锁构建安全回收。升级时应先结束旧版构建，不混跑旧版“仅检查文件存在”和新版内核锁协议。

## 验证

```sh
npm run check
npm test
npm run test:desktop
npm run test:forward
npm run test:forward:agents
npm run test:forward:entry
npm run test:forward:bench
npm run test:serial
npm run test:forward:publication
CHROME_PATH=/usr/bin/google-chrome npm run test:browser -- test/browser/forward-agents.spec.mjs test/browser/forward.spec.mjs test/browser/serial-forward.spec.mjs
npm run test:compat
```

Node 的运行通道测试直接驱动独立映射引擎，不暴露旧 HTTP 授权接口；应用权限、固定槽位和 key 测试使用真实面板 HTTP / WebSocket。浏览器使用真实引擎与模拟 RFB / 助手，涵盖标签溢出、弹窗、并发编辑、未知结果、隐私清理、网卡与串口；模拟的直连诊断不算实际网络证明。

`test:forward` 运行两个带 race 检测的真实 Linux 助手、临时 CA 和 TLS/WSS，覆盖 8 MiB、证书拒绝、独立规则及重启恢复。`test:forward:agents` 运行真实 Pion / werift IPv4，并在本机实际分配的公网 IPv6 上验证 IPv6 UDP / DTLS 和 IPv6 TCP 目标，无地址时明确跳过。`test:forward:entry` 复用相同真实流程验证节点前缀。`test:serial` 使用真实子进程和不存在的设备，验证延迟打开与故障回收，不操作物理串口。桌面管理仍为 fixture。

`test:gateway:worker` 使用真实 workerd / SQLite，验证固定节点路由与拒绝握手；不连接生产 CF。`test:forward:publication` 在临时部署运行固定编译器、租约监督器和打包器，验证四个平台、包结构与发布下载摘要，不覆盖正式产物。Windows / Mac 运行、USB / 蓝牙串口及跨运营商网络仍需真机验收。

IPv4 NAT 发现复用节点下发的 STUN 地址，与 IPv6 开关独立。Go 助手与节点同时保留公网反射候选，仍拒绝特殊地址；每次协商最多八个自动候选和四个提示，收集期限 1.5 秒。
