# 端口映射协议与发布边界

本页面向开发与深入排障。配对、方向选择、平台启动和构建命令见[端口映射使用说明](forward.md)，串口见[串口接入](serial.md)。浏览器的 TURN 能力不等同于助手支持 TURN；当前助手采用局域网 / 公网 IPv6 直连或 WSS 中转。

## 常驻助手协议

0.8.0 的 `/api/forward` 以 `managedHelpersProtocol: 1` 声明能力。完整管理员在解锁并接管后通过 `/api/forward/agents` 读取助手、期望规则、运行状态及设备清单；POST 子路径为 `create`、`rekey`、`remove`、`rule`、`rule/remove`、`inventory`。请求体最多 4 KiB，保持登录、Host、Origin、CSRF 和读取请求体后的再次鉴权；临时账号、锁定或被接管页面不能访问这些接口。规则修改携带原 revision，冲突返回 409，不覆盖他人的更新或自动重试结果未知的写入。

每个助手 key 为 `COCA1.` 加 base64url JSON，包含版本、完整服务器入口、可选节点 ID、助手 ID 和 256 位随机 secret。服务器只在创建 / 换 key 时返回原文，私有 `data/panel/forward-agents.json` 保存 `SHA256(agentId.secret)`、名称和期望规则。文件最多 128 KiB、0600，只有一份固定临时文件，原子替换并同步目录；拒绝符号链接、特殊文件、错误归属及不安全权限。文件不保存运行凭据、设备清单或流量；配置及 key 均不得提交 Git。

助手用 `/forward/agent` WSS、`codex-agent-v1` 子协议、`Authorization: Bearer agentId.secret`、32 位随机 `X-Codex-Agent-Instance` 认证。一个 key 同时只接入一个进程；不同助手独立 key。管理消息限 48 KiB、发送缓冲 128 KiB、每分钟 120 项，保活沿用映射心跳。该连接只传规则和清单，不承载业务字节。

控制台下发每条规则的 revision、映射 ID、固定目标配置和一次性运行配对码。助手用原 `/forward/helper`、`/forward/data`、`/forward/resume` 完成逐规则授权、TCP / 串口转发及直连协商；握手必须与下发目标完全匹配，不能改变目标或重复消费原码。规则各占一个 Go 工作协程，删除或修改只取消对应协程；串口驱动仍使用原来的固定子进程隔离。一条路径无效或端口冲突只报告该规则失败，其他规则继续；服务端最多每十五秒重试失败规则。

每节点最多八个助手、每助手十六条期望规则，运行映射全节点最多三十二条（包含一次性模式的最多四条）。直连 peer 仍全局最多四个，其他规则可经 WSS；单规则八条 TCP、串口一个客户端、16 KiB 消息和 256 KiB 缓冲不变。策略通知最多每助手一个待处理定时器；助手规则结果队列最多 32 项、清单请求队列一项、管理读取队列一项。stdout 不写文件或历史，最多每分钟 120 次、每次 8 KiB 输出，逐规则诊断仍有原来的分类上限。

清单每 30 秒及手动请求时上报：最多 128 个串口、128 张网卡、每网卡 32 个 IPv4、总共 1024 个地址，包含接口名称、序号、启用状态和前缀。包括回环、停用及无 IPv4 网卡；不把枚举地址自动作为直连候选或目标。序列化清单最多 32 KiB，超出后截断并标记；只保留每助手最新一份及更新时间，离线显示最后一次信息。串口枚举子进程最多三秒、32 KiB 输出，不打开设备。

长期 key 独立于网页会话，退出 / 锁屏不撤销；换 key 或移除立即关闭该助手映射。管理重连按 1、2、4、8、15 秒退避持续尝试，规则管理连接仍用原 30 秒恢复预算。同一进程重连保留尚健康的映射，新的进程实例重建规则；面板重启使用持久期望配置重新签发映射，旧运行凭据不复用，旧 TCP 由客户端重连。不自动重放字节、设备命令或网页输入。

多节点使用 key 的完整入口和身份。自建中心保留 `/node/<slug>/`；CF 网关仅对 `/forward/agent|helper|resume|data` 接受携带 Bearer 凭据的 `X-Codex-Forward-Node` 固定路由，经只读 DO 节点查询转发，不改变浏览器默认节点。节点不存在或身份改变时明确拒绝，不回退到其他节点。后台继续检查代理凭据、Host、Origin 和节点身份，pin 头不替代认证。升级时需同步部署新 Worker。

## 助手下载传输

受限服务的 `ping` 以 `helperDownloadsProtocol: 1` 声明能力。浏览器只在已声明能力且文件通道就绪时，发送固定 `helper` 来源（平台标识及可选 32 位十六进制发布版本）；其余使用原 HTTPS 链接。后台经回环复用节点前缀下的认证助手下载 API，保留 Host、Origin、登录、节点身份、入口匹配、版本与并发校验，不提供通用 URL 代理。

一次最多传输一个不超过 32 MiB 的助手，原下载接口全局最多两项，文件通道期限五分钟；字节流沿用分块确认和背压。客户端核对列表大小及 SHA256 后才提供文件，失败不自动重试。旧版本 410 等明确拒绝仅回收文件通道，服务控制连接继续可用。下载不认领桌面、不创建 PTY，也不影响已有画面连接；无需重编译助手本身。

## 协议与资源上限

- 映射授权与桌面控制权的生命周期分开；一次性模式按方向、角色与映射归属检查权限，常驻管理要求完整管理员权限。请求校验 Host、Origin、登录和 CSRF，读取请求体后再次校验登录和 CSRF，延迟请求不能跨退出登录或授权失效执行。
- 一次性模式最多四个待配对或活动映射；常驻与一次性合计最多三十二个。配对码和运行凭据都是 256 位随机值，只保存摘要和少量元数据于内存；每个运行授权仅允许一个明确目标 IP、目标端口和本机端口。IP 输入最多 64 字符，经字面地址验证并规范化后保存；IPv4 映射的 IPv6 转为 IPv4，不进行 DNS 或 shell 调用。旧网页省略目标 IP 时仍使用 127.0.0.1。
- 助手用一次性配对码认证 /forward/helper，获得仅用于该映射的流凭据；中转的每条本机 TCP 连接独立认证 /forward/data。使用 codex-forward-v1 子协议，凭据放在 Authorization 请求头，保持 Host 和 Origin 校验；不会把工作台登录 Cookie 交给助手或目标服务。
- 新助手用 `X-Codex-Forward-Resume: 1` 声明恢复协议，独立凭据仅能认证 /forward/resume；旧助手保持原有断线撤销行为。恢复占原有映射名额，每个一项控制握手、每窗口最多八次尝试和 30 秒期限；每次握手最多五秒，并受剩余恢复期限约束。最近结束记录额外保留恢复凭据摘要，用于返回明确的停止、撤销或超时原因，仍最多八条、十分钟，不向网页暴露。
- 新助手显式声明直连能力，SDP 只在已认证管理通道传输，单项最多 32 KiB、控制消息最多 48 KiB、控制发送缓冲最多 64 KiB。每个映射最多一个 peer，全局最多四个（包含关闭中），全局协商不排队、最多一项同时进行，同一映射十秒内不重复协商；旧直连 TCP 未结束时不替换其 peer。
- 直连使用 DTLS 验证 WSS 协商的证书指纹，健康通道再次校验映射凭据，数据通道只允许固定目标开启记录。可靠有序 SCTP 通道采用四条已确认记录的窗口，每条最多 16 KiB；目标写入受背压时不再释放确认额度，避免在接收端无限排队。FIN 与普通数据保持发送顺序并参与确认。
- 每个 peer 接收窗口最多 1 MiB；服务端在分片重组前限制最多 32 项流元数据、1024 个未重组分片、2048 项乱序包标识及 1024 项重复标识。每个助手 peer 最多创建 128 条数据通道，达到上限后新连接暂用中转，等待旧直连 TCP 结束后再轮换 peer，避免依赖库保留的已关闭通道元数据长期累积。每次助手运行最多输出二十条通道变化提示及一条达到上限说明。
- 正向模式由服务端确认助手已绑定本机端口后才允许连接目标，配对后启用期限五秒；一次性反向模式首次本地确认最多六十秒，常驻模式由 key 授权自动确认。数据通道建立最多十五秒，就绪最多十秒，目标连接最多五秒；反向服务器 socket 从接受到目标确认总共最多四十秒。
- 每个映射最多八条并发 TCP 连接，每十秒最多 32 次连接尝试。二进制消息最多 16 KiB，服务端应用发送缓冲和目标写缓冲分别最多 256 KiB；慢接收方施加背压，超限关闭对应连接。
- TCP EOF 使用独立 FIN 记录，保留半关闭后的响应。原始字节不进入 PTY、输入助手或 shell，不解析 SSH/数据库协议，不执行任意命令。
- WebSocket 每十五秒检查心跳，探测最多等待三十秒匹配的 Pong；旧 Pong 不确认新探测。服务端主动暂停 WebSocket 读取时，Pong 读取也会暂停，期间不误判为网络失联，但继续发送 Ping 维持助手读期限；连续暂停最多六十秒，按 TCP 接收端阻塞清理，恢复读取后重新探测。助手数据阶段读期限四十五秒、写期限十五秒；写入助手侧 TCP 对端超时单独报告。授权到期或失效最多五秒内清理，显式停止、退出原登录立即撤销。TCP 立即关闭，控制通道最多等待一秒发送固定原因，最多八个关闭中的通道，超限终止最早通道。
- 一次性列表最多四项活动映射及字节计数，常驻状态由独立助手列表返回；另保留八条最近结束原因十分钟，不保存原始内容、连接明细或流量日志。保留的配对码摘要仅用于返回过期/已用提示，不能再次配对；不向网页暴露摘要、登录标识或运行凭据。网页仅在对话框打开且前台时每三秒查询，最多一项在途请求；配对码与刚签发的 key 仅当前窗口暂存，关闭窗口、隐藏页面或失去完整管理权限会清空，复制只在点击时发生。

## 直连探测与管理保活

新映射默认继承当前浏览器“连接状态 → 直连地址提示”的服务器 IP 和浏览器端 IP。浏览器与助手通常在同一电脑；不在同一电脑时，可在映射表单单独填写“助手端 IP”覆盖浏览器端地址。留空继承，清空连接状态中的提示则使用自动发现；提示不改变映射的目标设备 IP 或端口，仅补充实际收集端口上的 ICE 候选。

每个运行映射保存创建时的地址快照，每侧地址最多 45 字符。一次性映射只在内存，点击“应用当前直连提示”后更新；常驻规则的提示随配置持久化，修改保存重建该规则。临时账号只能更新自己登录创建的一次性反向映射。0.7.1 助手会在没有正在运行的直连 TCP 时重新协商；已有 TCP 保持原路径。旧助手可继续中转和自动探测，但不保证主动应用新提示，请更新助手。每侧最多额外四个去重候选，自动候选保留，不添加端口、监听地址或防火墙规则。

使用同一个 HTTPS 网站和配对过程，无需另配局域网证书。网页中“新连接”表示下次创建 TCP 连接时的首选通道，“现有连接”分别统计已经固定在直连和中转上的连接；不会将“新连接可直连”显示成所有连接均已直连。界面和助手显示实际选中的 IPv4/IPv6、UDP、往返延迟及回退原因。

后台探测不连接目标端口。ICE、DTLS 指纹和映射凭据验证通过后，再通过两次独立心跳确认可用；每条新连接还要打开可靠有序的数据通道并发送固定目标开启记录。通道预检失败、尚未请求目标端口时，可以选 WSS。目标开启记录一旦发出，失败结果可能不确定，此连接只会断开，不再经其他通道重复连接或重发字节，由原 SSH、数据库等客户端决定是否重连。

直连期间每三秒进行独立心跳，期限两秒。失效后新连接使用中转，已建立的连接保持原通道；连接不可用时正常断开。中转期间按失败后 15、30、60 秒退避探测；每五秒检查本机网络地址变化，变化后提前探测。存在旧直连 TCP 时优先探测原 peer 的恢复，避免为换 peer 结束可用的旧 TCP。停止、退出原登录和授权失效仍撤销全部通道。

沿用 WEBRTC_ENABLED、WEBRTC_IPV6、WEBRTC_LAN_ADDRESS、WEBRTC_IPV6_ADDRESS 和 WEBRTC_STUN_URL 设置。设置 WEBRTC_ENABLED=0 时仅使用中转。只接受私有 IPv4 和普通公网 IPv6 的 UDP 候选，公共 IPv4、TURN 和 ICE-TCP 未启用。双方主动 ICE 探测允许尝试打通可出站回复的防火墙，并不保证所有网络均能直连。

服务器转发 peer 的 UDP 端口限定为 40016–40047，独立于桌面/网页终端的 40000–40015；Mac/Windows 助手使用 40048–40111。若设备或网络有出站/入站限制，需要允许相应 UDP 通信，否则自动使用中转；程序不改防火墙。助手提供给 SSH 等软件的 TCP 端口始终只监听本机的 127.0.0.1。

管理、授权与协商仍通过原网站的 WSS 连接。0.7.2 助手与新版服务端双方确认保活能力后，管理连接短暂断开时保留健康的 WSS/直连 TCP 和原 peer，暂停新建连接，并在原 30 秒授权窗口内恢复管理连接；数据通道仍独立进行心跳与授权检查。未建立完成的连接关闭，已断开的 TCP 不迁移或重放。旧版任一端未支持此能力时，继续采用关闭旧 TCP 后恢复映射的方式。详见[双栈直连](lan.md)。

## 反向连接与设备目录

服务器接收新 TCP 后只保留一个暂停的 socket 和四十秒期限，并通知助手使用一次性连接标识认领。0.6.1 助手为数据通道预留十五秒建立预算（含直连预检及 WSS 握手），就绪记录最多等待十秒；收到该连接的认证就绪记录后才访问固定目标，设备连接期限仍为五秒，发送确认最多五秒。服务端总期限覆盖这些阶段，避免旧版十秒期限提前关闭尚在握手的连接。原有 16 KiB 消息、256 KiB 缓冲与背压继续生效，监听 backlog 为八，待就绪连接仍计入八条并发上限。失败不换通道重连设备或补发旧字节；由原 SSH / Telnet 客户端明确重新连接。

双方支持管理保活时短暂断线保留健康连接，暂停新连接；旧版未支持时关闭监听、旧 TCP、旧连接标识和直连 peer。30 秒 / 八次握手的恢复预算及退避策略保持不变；恢复同时绑定原映射 ID、方向、名称、两端端口与规范化目标 IP。已确认目标在同一次助手运行中无需再次确认，恢复不访问设备、不重新配对、不重放命令。一次性模式在停止、退出原登录、授权到期或面板重启后不自动重建；常驻模式按持久规则及有效 key 重建。

设备目录为服务器 `data/panel/devices.json`：最多 16 项、文件最多 16 KiB、0600，只有一份固定临时文件原子替换；拒绝符号链接、FIFO、非普通文件或非当前用户文件。仅保存名称、协议、目标和监听端口，无账号密码、配对/恢复凭据、设备输出或日志。新建、编辑、删除沿用登录、Host、Origin 和 CSRF 检查，无操作队列。修改或删除条目不改变现有授权中的固定目标；条目已改变时，旧表单需重新选择或保存后再配对。

## 短暂断网恢复

以下描述单条运行映射的恢复；常驻管理连接及规则重建见[常驻助手协议](#常驻助手协议)。

助手声明恢复能力后，首次配对返回独立的 256 位恢复凭据，仅绑定原映射、原登录、目标 IP 和两端端口，不能用于打开数据连接。服务端只保留其摘要，助手只放在内存，不写文件、URL、命令行或日志。原一次性配对码不会再次提交。恢复通过同源 `/forward/resume` WSS 接口认证，沿用 Host、Origin 和固定子协议检查。

服务端检测到控制断开后，将映射保留在最多 30 秒的恢复窗口中，仍占原有活动名额。助手按 1、2、4、8 秒退避，在自身 30 秒预算内重试；每个服务端恢复窗口最多接受八次握手。未完成握手不延长原期限；恢复请求也可替换仍半开的旧控制连接。

双方支持 `keepStreamsProtocol=1` 时，本机/服务器回环监听和已建立的数据连接保留，监听期间的新 TCP 立即关闭，恢复握手未确认前不能新建数据通道。恢复始终核对原映射、目标 IP/端口、方向、设备/串口参数、直连协议、连接上限和原数据凭据，确认后开放新连接。数据凭据只在该映射的原授权内复用；服务端每个映射至多额外保留一个 43 字符凭据，仅内存使用，不进入列表、最近记录或日志。原 peer 的健康检查继续运行，不依赖管理 WSS 的状态推送。旧版任一端未声明该能力时仍换发数据凭据、关闭旧 TCP/peer 并重新绑定监听与探测。恢复和探测均不主动重连目标或发送先前的字节。

网页显示“正在自动恢复”、剩余时间或恢复握手状态，仍可通过原确认框停止。明确停止、退出原登录、授权过期或撤销、协议或证书错误、本机端口被其他程序占用，以及恢复预算耗尽均终止恢复。握手和网络故障的检测本身仍受既有五秒启动、十五秒 ping 和四十五秒读取期限影响；30 秒从检测到故障后计时，不保证实际断网后立即恢复。服务端授权窗口可能比助手先到期，服务端拒绝为准。

Ctrl+C 会立即停止本地恢复；通道仍可达时通知服务端关闭映射。断网期间退出或强制关闭助手无法通知服务器时，服务端在恢复窗口到期后清理。服务端不持久化运行恢复状态，重启后旧运行凭据失效；一次性模式需重新配对，常驻模式通过长期 key 和期望规则签发新映射，不复用旧运行凭据。

## 构建与原子发布

构建命令先检查固定 Go 1.26.4；版本与依赖见[构建器](../scripts/build-forward.mjs)、[go.mod](../client/forward/go.mod)和 [go.sum](../client/forward/go.sum)。公网地址支持 HTTPS 根地址与 `/node/<slug>/`，产物绑定最终入口。

产物只保存在被Git忽略的`data/forward-client`。新构建在`releases/<32位随机版本号>`中生成完整的两个Windows exe、两个Mac ZIP和至多4 KiB的v2清单，全部成功后才原子更新至多256字节的`current.json`入口；中途失败保留正在提供的版本。即使入口改名后目录同步报错，也不会删掉已经生效的版本。下载链接固定版本号，下一次构建清理更早版本后旧链接返回410，需刷新列表；已打开文件描述符的下载继续完成。

发布入口还会在文件租约内及提交前比较构建开始时保存的原始内容；构建期间入口被修改时拒绝覆盖，旧版本和人工修改保留。首次发布要求入口仍不存在，不会替换并发创建的入口。

最多保留两个版本目录，含当前版本与前一版本或正在构建的版本；下一次构建开始回收非当前目录。每版本四个产物各至多32 MiB，构建时至多一份helper.tmp、一份package.tmp及有界清单/入口暂存，产物生成后验证大小。现有根目录v1清单和四个旧产物原样保留，旧面板继续使用它们；更新面板后才识别新入口，部署应先升级后台再运行新构建。新格式最多约320 MiB已校验产物/临时数据，保留旧产物时另加至多128 MiB，不保存构建日志或任务队列。遇到非工具生成的目录、链接或额外文件时拒绝清理，不删除其他内容。

Mac包检查Mach-O架构、可执行类型、macOS 12目标及ARM64签名结构范围，固定三项ZIP内容和权限；这不代替macOS实际签名验证。下载仍要求登录，文件名和版本号固定校验，拒绝链接及特殊文件，最多同时两项下载；所有产物、清单和运行锁都不提交Git。

构建复用系统flock，`.build.lock`保留为0600的空锁inode，不再把文件存在当作永久占用。默认执行器由持锁Python助手直接管理固定的go/git/python3子进程，不经过shell，不排队；父Node被杀或取消时，先结束并回收独立编译进程组和被收养后代，再释放租约。子命令还继承锁描述符，避免监督器异常退出时编译器立即失去互斥。构建只在原生Linux运行；每租约最多32条顺序命令，每条请求128 KiB、输出16 KiB、最长180秒，Go包编译并行数2。未发布的唯一版本目录由下一次持锁构建安全回收。升级时应先结束旧版构建，不混跑旧版“仅检查文件存在”和新版内核锁协议。

## 验证

    npm run check
    npm test
    npm run test:desktop
    npm run test:forward
    npm run test:forward:agents
    npm run test:forward:package
    npm run test:forward:publication
    CHROME_PATH=/usr/bin/google-chrome npm run test:browser -- test/browser/forward.spec.mjs test/browser/web-terminal.spec.mjs

Node 单元测试使用真实 WebSocket 和隔离 TCP 服务，另有基于模拟通道的背压/重组资源上限测试；桌面与管理执行器为 fixture。浏览器测试使用真实 Chrome 和模拟 RFB，覆盖刷新和接管保留映射、不同页面管理、固定故障提示和丢失响应不重试；通道统计界面用例使用模拟诊断数据，不将其当成真实网络通道验证。

`test:forward:agents` 同时运行两个带 race 检测的 Linux Go 助手、真实 TCP、回环 WebSocket 和 Pion / werift UDP / DTLS。覆盖多规则正反向字节、网卡清单、编辑仅一条、撤销仅一个助手、管理重连保留原 TCP、无效串口规则隔离，以及面板重启后原 key 重建规则并通过中转继续工作。桌面 / 终端及管理器为 fixture，不使用真实 USB 串口或 Windows / Mac 运行环境。`test:gateway:worker` 另验证真实 workerd 内浏览器切换默认节点后，助手仍固定连接授权节点。

test:forward 使用带 race 检测的 Linux 同源助手、临时证书、真实 TLS/WSS 代理、真实 Pion/werift UDP/DTLS/SCTP 和 TCP 服务。覆盖 8 MiB 数据、双向半关闭、心跳、探测不连接目标、旧中转流保留、不同通道并存、直连失效/恢复、peer 实际关闭后的后台重建、目标就绪丢失不回退重连、明确停止撤销两种通道，以及原有端口占用、目标不可达、输出上限和证书拒绝。实际关闭管理连接并暂时返回 503 后，正反向已有中转/直连 TCP 继续传输，同一映射/监听/peer 恢复且目标未被重新连接；新连接暂停、配对码/字节不重放、恢复中明确停止和持续故障的真实 30 秒预算耗尽也在覆盖范围内。健康失效、就绪丢失和故障代理使用受控故障注入，数据仍经真实协议栈；IPv6 在主机实际分配的公网 IPv6 上验证，无地址时明确跳过。所有检查均不连接工作中的 Codex 或真实 SSH 服务。

`test:forward:package` 交叉编译两种真实 Mach-O 并核对 ZIP CRC、程序字节、固定内容、执行权限、最低系统目标、ARM64 签名结构和 Go 构建元数据；另用隔离的脚本替身验证启动器对空格、中文和字面参数的保留，不声称在 Linux 上执行了 Mac 程序。Windows PE/Mac Mach-O 结构检查不代替各平台真机验收，本机公网 IPv6 也不能代替跨运营商验收。

`test:forward:publication` 在临时部署目录运行完整构建器，使用真实Go编译器、持锁子进程监督器和Python打包器，生成两个Windows PE与两个Mac ZIP；核对嵌入的持久入口、版本/架构、ZIP结构/权限以及版本固定下载流的尺寸和SHA256。测试只使用合成配置及临时Git身份，退出后清理；不会覆盖正式下载、重启服务或在本机执行Windows/Mac程序。该检查已加入CI的native作业。

Mac/Windows 真机可依次检查：初次打开和版本正确、配对后 SSH 登录、SFTP 上传/下载同一文件并核对 SHA256、保持一条 SSH 后切换直连状态确认旧连接保留，再只中断管理链路测试已有健康通道继续工作、恢复期间新连接暂停；完整断网导致的数据连接失败仍由原客户端重连。最后明确停止并确认不再恢复。常驻模式另验收多个助手和规则隔离、网卡 / 串口清单、撤销 key、重启后自动重建规则；一次性模式面板重启后重新配对。需要实际目标服务的账号，项目不代为保存该密码。
