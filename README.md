# Codex on Cloud

在 Ubuntu 本机运行独立开发桌面，通过手机或平板浏览器操作 Codex。**无需 Docker**，复用当前用户的工具、项目和 Codex 登录。

```text
手机浏览器 → Cloudflare Access（可选）→ Cloudflare Tunnel
                                      ↓
                         本机 Web 面板 127.0.0.1:36080
                                      ↓ 已认证的 WebSocket
                              私有 Unix socket
                                      ↓
                       x11vnc → Xvfb 独立显示 :93
                                      ↓
                        XFCE + xterm + tmux + 本机 Codex
```

面板与桌面使用独立的 systemd 用户服务。关闭浏览器、切换网络或重启面板，都不会主动停止桌面任务。VNC 不监听 TCP 端口，内部输入接口只监听回环地址。

## 快速部署

先准备带 systemd 的 Linux 主机、Node.js 22+ 和本机 Codex CLI，通过普通用户登录。Ubuntu/Debian 可用下面的统一入口安装桌面依赖、初始化、安装并启动用户服务，以及启用开机自启：

```bash
git clone https://github.com/ptpt52/codex-on-cloud.git
cd codex-on-cloud
npm run deploy -- --install-deps --enable-linger
```

只需要网页终端时，新部署可选择轻量模式：

```bash
npm run deploy -- --mode terminal --install-deps --enable-linger
```

此模式不安装 Xvfb、XFCE、x11vnc、Xterm、X11 工具、桌面字体或 noVNC，只需现有 Node.js/Codex 环境及 tmux、Python。保留网页终端、多终端、历史、文件传输、直连/中转和端口映射；由独立终端后台持有任务。桌面模式仍是默认选项，已有部署不会自动转换，详见[纯网页终端部署](docs/terminal-only.md)。

已有系统依赖时运行 `npm run deploy` 即可。系统包和 linger 两步会按所选参数使用 sudo，其余步骤以当前用户运行。apt 安装使用 `--no-upgrade --no-remove`，保留列出的已安装包并拒绝移除包。安装器按锁文件安装项目依赖，保留已有密码与 `.env`，不安装或修改 Codex；服务运行时保留现有依赖，若其不完整或版本不符则停止并提示另行维护。重复运行只启动缺失的服务，不重启桌面；最后检查服务状态、面板健康与桌面就绪，失败后停止后续步骤。

在 WSL 镜像网络中，部署会自动为 Windows 本机浏览器直连补齐 `.wslconfig` 的 `hostAddressLoopback=true` 并保留原文件备份；需保存任务后重启 WSL 才生效，安装器只提示重启。`--check` 只读检测，`--skip-wsl-network` 可保留原配置。Windows 重启后的启动方式、Node 版本及直连排障经验见 [WSL 部署说明](docs/wsl.md)。

只检查环境、不执行安装：

```bash
npm run deploy -- --check
```

完成后本机访问 `http://localhost:36080`，账号密码见 `secrets/credentials.txt`。面板保持回环监听；若部署在远程服务器上，可用 SSH 本地端口转发后访问 localhost，或配置下面的公网入口。安装器不会自动打开防火墙或将面板改为公网监听。

有 Cloudflare 托管域名时，把具备所需权限的 API token 存为仅含 token 的文件，增加以下参数即可复用现有发布脚本配置域名、Tunnel 和 HTTPS 入口（[授权准备](docs/cloudflare.md)）：

```bash
npm run deploy -- --install-deps --enable-linger \
  --domain desktop.example.com --zone example.com \
  --api-token-file /path/to/cloudflare-api-token
```

公网配置会重启已运行的网页面板，已有端口映射需要重新配对，桌面与 Codex 任务保留。API token 不进入命令行内容或日志；安装器只把文件路径交给发布脚本。若已配置 HTTPS 与 Tunnel token，重复部署也会启用该 Tunnel。公网入口配置和系统软件包安装仍需主机网络可用。

需要提供端口映射助手下载时，可再加 `--build-forward`，使用已有的固定 Go 1.26.4 构建四平台助手；普通网页桌面部署不需要 Go。全部参数见 `npm run deploy -- --help`。下面保留分步安装与维护说明。

## 环境与安装

需要 Linux、可运行的 Node.js 22+、Python 3.8+ 和本机 Codex CLI。已在本机 Ubuntu 18.04、Node 24、Python 3.11 上实测。Ubuntu 18.04 的系统默认 Node/Python 版本不满足要求，不要直接用旧系统包替换已有环境。

在新主机上安装桌面依赖，只有这一步需要 sudo：

```bash
sudo apt-get update
sudo apt-get install -y --no-install-recommends \
  xvfb x11vnc xfwm4 xfdesktop4 xfce4-panel xfce4-settings \
  xterm tmux xclip xdotool xauth x11-utils dbus fontconfig fonts-noto-cjk
```

普通用户初始化、检查和安装服务：

```bash
cd codex-on-cloud
npm ci
npm run setup
npm run native:doctor
npm run native:install
npm run native:start
npm run native:status
```

本机已经有大部分组件。为完成无 sudo 的实机验证，Xvfb、xclip 和备用中文字体已从 Ubuntu 官方包解压到被 Git 忽略的 `data/host-tools/`；启动器会优先查找这个目录。这不是系统级安装，删除 `data/host-tools` 后需要用上面的 apt 命令补齐。

浏览器访问 **http://localhost:36080**。登录信息保存在 `secrets/credentials.txt`，不会打印到日志。

如需本机用户退出登录后及开机继续运行，执行一次：

```bash
sudo loginctl enable-linger "$USER"
```

这让用户服务在无人登录时也能运行；主机仍需保持供电、联网且不休眠。

## 使用 Codex

打开桌面后点击“打开终端”，在已有 tmux 会话中运行 `codex`。需要登录时运行 `codex login`。项目不会读取、改写或复制本机 `~/.codex` 配置，也不会更改审批和沙箱设置。

初始终端只打开 shell，重新连接不会自动启动 Codex、提交指令或重放按键。关闭 xterm 后点击“打开终端”会重新连接原 tmux 会话。

桌面、面板都以当前用户运行，**拥有这个用户的本机文件权限**。独立显示、Xauthority、D-Bus、XFCE 设置和 tmux socket 与物理桌面分开；文件系统和用户身份没有隔离。

## 配置

`.env` 使用 dotenv 格式解析，不作为 shell 脚本执行。初始化保留已有密码和配置。旧版 Docker 配置中的 `CODEX_VERSION`、`desktop_password` 不再使用，可自行移除。

```dotenv
PUBLIC_ORIGIN=http://localhost:36080
ALLOWED_HOSTS=127.0.0.1:36080
ADMIN_USER=admin
PANEL_PORT=36080
AGENT_PORT=36902
DISPLAY_NUMBER=93
DESKTOP_SIZE=1600x3200
WORKSPACE_DIR=./workspaces
TZ=Asia/Shanghai
```

`WORKSPACE_DIR` 可改为现有项目目录，绝对路径直接使用，相对路径以本项目根目录为基准。中转目录固定为该目录下的 `transfer`，面板会显示真实路径。每个文件最大 50 MiB，上传同名文件会原子替换。

显示号被占用时启动器会停止并提示，绝不接管已有桌面或删除其他显示的锁。可选 `RUNTIME_DIR` 指定私有运行目录，默认在 `$XDG_RUNTIME_DIR/codex-on-cloud`，无此变量时使用项目 `data/runtime/codex-on-cloud`。

修改公网域名或面板端口后，只重启面板：

```bash
systemctl --user restart codex-cloud-panel.service
```

网页保存的分辨率优先于 `.env` 中的 `DESKTOP_SIZE`；尚未保存时使用该默认值。修改显示号、工作目录，或手动调整默认尺寸后，需要先结束桌面任务，再重启桌面服务。这会终止原桌面进程及 tmux 任务：

```bash
systemctl --user restart codex-cloud-desktop.service
```

Node/Codex 安装路径发生变化时重新运行 `npm run native:install`，刷新服务捕获的 PATH。该命令不重启正在运行的服务。

## 界面主题

工作台采用 [X-Wrt 主题](https://raw.githubusercontent.com/x-wrt/luci/master/themes/luci-theme-x-wrt/htdocs/luci-static/x-wrt/cascade.css)的橙灰配色：橙色 `#f7971d`、深色导航 `#231815`、灰白内容区，并跟随系统切换深浅模式。登录、工具栏、弹窗、快捷键和端口映射使用统一配色；在线、警告与错误分别保留绿、黄、红状态。网页终端的实时显示与历史共用底色和选区颜色，ANSI 文字颜色保持原样。

## 屏幕锁与临时账号

“工具 → 访问与屏幕锁”可开启独立屏幕密码，首次进入和每次抢占接管都需输入；锁定时任务与已有映射继续运行，连接状态、反向设备映射和文件中转可用。也可配置有期限的临时账号，只允许“服务器访问本地设备”映射及共享文件上传下载，不能解锁桌面或使用终端。桌面和纯网页终端部署都支持，默认关闭。详见[访问权限说明](docs/access.md)。

锁屏后已授权的双向映射全部保留，包括原 TCP、后续新 TCP、有效配对码及原授权恢复；锁定页面仍不能新增或管理访问服务器的正向映射。来源登录失效、明确停止或面板重启仍会结束对应映射。[锁屏保留规格](docs/access.md#锁屏后全部保留)

忘记密码时，在服务器项目目录执行 `npm run reset-password`，按菜单操作；也可用 `-- --admin` 重置管理员密码、`-- --screen` 重设锁密码、`-- --unlock` 关闭锁。交互密码不回显，`-- --admin --generate` 可生成密码并保存到私有凭据文件。命令只停止并恢复原来运行的面板，映射需重新配对，桌面和 Codex 任务保留。[后台重置说明](docs/access.md#后台密码重置)

## 桌面显示

- 电脑与手机统一默认使用 1600×3200 的固定桌面，按浏览器可用宽度缩放；高度超出可用区域时上下滚动查看，不再把桌面挤到只有几百像素高。
- “适应宽度”填满可用宽度并允许纵向滚动；默认“滚动画面”让滚轮和单指/双指滑动移动本地画面，轻点仍操作远端。画面下方可直接切换为“滚动程序”，将滚轮及双指滚动发送到远程终端、编辑器等应用；也可在工具面板中选择滚动目标。轮询和显示控件刷新不会把已滚动的画面跳回顶部。
- “适应窗口”一次显示整个桌面；“原始比例”按 100% 显示，放大、缩小按钮可在 10%–200% 间调整比例。桌面设置仍可手动开启“桌面大小跟随浏览器窗口”，恢复动态分辨率；默认关闭。
- 连续放大、缩小按目标比例递增，旧画面的比例回报不会覆盖新选择；切回“适应窗口”时等到当前画面的比例确认后再启用缩放按钮。
- 开启“拖动画面”后，可以用鼠标或单指移动查看区域，也可用滚轮、方向键和 Page Up / Down 浏览。这个模式拦截画面区域的点击和键盘输入，避免误操作远程桌面；再次点击按钮恢复操作模式。
- 默认进入专注布局，标题栏保留模式、连接状态及独立的“工具”“输入”入口。显示设置、终端管理、重连与全屏集中到工具面板：电脑位于右侧，手机从底部展开。输入助手使用独立浮层，两种面板互相切换，不再占据桌面高度或裁剪画面；Esc / 关闭按钮收起面板并恢复入口焦点。
- 工具面板的“触控方式”可选择触屏或触控板。触控板模式下单指滑动移动相对指针、轻点左键、双指轻点右键，双指滑动按所选目标滚动；画面下方也有左键、右键和明确的“拖动 / 结束拖动”按钮。拖动只保持当前连接的鼠标左键，失焦、离线、隐藏页面或切换操作模式时释放；重连不会恢复拖动。电脑物理鼠标继续按实际位置操作。
- 全屏时仍可从标题栏打开工具与输入。缩放、查看拖动、工具和输入面板只改变浏览器视图，不重启桌面；自动尺寸仍由明确开启的窗口跟随选项控制。
- “保持亮屏”在支持 Screen Wake Lock 的安全上下文中防止访问设备自动息屏，默认关闭；开启后记住本浏览器的选择，显示申请中、已开启、暂停或不支持状态。切到后台、退出登录、失去桌面控制权或离开页面时释放，返回前台且仍有控制权时尝试恢复。系统省电或锁屏可释放亮屏锁；暂停后可关闭再开启以重试，不循环申请。普通局域网 HTTP 页面通常不具备所需安全上下文。[浏览器规范](https://www.w3.org/TR/screen-wake-lock/)
- “退出”“打开终端”“重新连接”和输入助手的 Ctrl C 均先显示确认框，默认聚焦“取消”；取消、默认回车或 Esc 不会执行操作。接管、断线、隐藏页面或登录变化会丢弃未确认操作。退出入口及 Ctrl C 与其他按钮分隔，触控区域增大；终端内直接按键和独立的粘贴/Enter 保持原有行为。
- 网页终端字号、宽度和历史行数，以及显示比例、自动尺寸与亮屏开关、查看拖动、触控方式、滚动目标和面板收起状态属于当前浏览器，主/辅助终端共用，不向其他设备同步。一个固定偏好条目最多 512 字符，逐项验证，不保存终端输出；禁止存储时仍可操作并提示刷新后可能恢复默认。范围、迁移和共享设置边界见[浏览器偏好规格](docs/browser-preferences.md)。

## 手机输入与剪贴板

点击“输入”直接打开助手并聚焦文字区，也可点击“键盘”再次唤起系统键盘。助手按浏览器 visualViewport 的可见区域定位，键盘出现时压缩次要提示，保持粘贴和 Enter 可达；不会因此更改默认固定桌面分辨率。中文候选词组合期间暂停发送，完成组合后仍需手动点击“粘贴文字”；文字中的 Enter 只编辑草稿，远程 Enter 使用独立按钮。

“发送到远程”与“取回文字”提供明确的两个方向。发送前可核对输入目标及终端/其他应用粘贴方式；取回文字仍需主动读取、预览后复制，切回发送会清空远程预览并保留草稿，不自动同步两端剪贴板。草稿按终端 ID 与进程身份隔离，当前窗口另有一份草稿；只保存在当前标签页的固定 sessionStorage 条目，最多 9 份、每份 32768 字符，序列化总量不超过 2 MiB（含 JSON 转义）。达到容量时保留当前文字并提示清理，存储不可用时提示刷新前复制；发送仍遵守 32 KiB UTF-8 上限。终端粘贴使用 Ctrl+Shift+V，粘贴不附带 Enter。

`npm run test:pointer` 在独立、临时的 Xvfb 显示上，以真实 x11vnc / noVNC 和 UDP/DTLS 验证触控板移动、左右键、失焦释放，以及中转→直连→回退期间保持同一 VNC 连接和画面对象、释放按住的键与拖动；管理接口使用测试夹具，不连接生产桌面或输入 Codex 任务。手机系统键盘仍需真机验收，浏览器测试中的 visualViewport 模拟只检查布局与发送边界。

## 更多快捷键

输入助手新增“更多按键 ▾”，按 Codex 常用、输入编辑、光标导航、远程剪贴板和会话控制分组，提供 39 项固定按键。点击条目发送一次；Ctrl+C、Ctrl+D、Ctrl+Z 和双 Esc 需明确确认。列表支持触屏、方向键和 Esc 关闭，打开或关闭不会发送按键；断线与接管清除未确认操作，不重发输入。换行提供已验证的 Ctrl+J，网页粘贴与 Enter 提交继续分开。用途、兼容性和来源见[快捷键清单](docs/shortcuts.md)。

## 网页终端模式

标题栏的“桌面 / 网页终端”可切换两种操作模式。网页终端直接显示文字，支持原生键盘、中文输入、鼠标选择复制、滚动历史、行列适配和 10–28 号字体；顶部可切换主终端及辅助终端，并进入终端管理。它连接现有私有 tmux 会话，保留同一个 shell / Codex 进程，不会另起 Codex 对话、重启桌面或补发旧输入。

存在多个终端时，宽屏在原标题栏内显示紧凑标签，手机和较窄窗口在同一位置显示当前终端按钮并打开会话列表；不额外占用一行高度，只有一个终端时隐藏切换入口。手机的连接状态缩为指示点，完整文字仍提供给屏幕阅读器，也可打开“连接状态”查看详情。查看对象、输入助手和工具面板中的选择保持同步，输入发送中或中文组合期间暂缓切换，后台终端不额外附加 PTY 或订阅输出。每个终端有独立草稿，切换和刷新均不自动发送；首次从未指定目标的桌面输入切入网页主终端时，未分配草稿可迁移到尚无草稿的主终端。

刷新后先读取终端目录、校验保存的进程身份，再连接原目标。目标结束、进程变化或目录读取失败时保留草稿，暂停输入并提示手动选择，不自动回退到另一终端。终端管理可以在确认后清理已失效且当前未编辑的旧草稿。切换目标仍清空当前历史视图；原任务继续由 tmux 保留。

点击另一种模式会先显示确认，默认聚焦“取消”；只有明确确认才重建连接。取消、Esc 或默认 Enter 保持原模式与连接，重复点击当前模式不会重连；输入和维护进行中暂停切换。未确认的选择不会保存，断线、页面隐藏或接管会清除旧确认。刷新页面继续使用上次已确认的模式。

网页终端默认“界面适应宽度”：保持字号，按浏览器空间重新计算行列，宽屏展示更多文字。tmux 2.6 会受最窄桌面查看器限制；网页模式将对应虚拟 Xterm 查看器临时切到等待画面，原 shell / Codex 保留在原 pane 中，网页终端接管尺寸。最后一个网页连接离开后，独立于面板的等待助手在约 0.5 秒内恢复原桌面查看器，即使网页 PTY 被强制终止也能恢复；不结束或挂起桌面窗口进程。最多八个固定等待会话，恢复后清理空等待会话；私有运行目录最多八个 0600 空锁文件，串行处理新连接与清理，不保存输入或终端文字。

也可选择“内容放大适宽”，按共享终端的可用列数放大等宽字体（基础字号为下限，最多 4 倍），或使用“手动字号”。适配方式保存在现有浏览器显示偏好内；只读列数上限每 2 秒检查，仅变化时发送少量元数据，不同步终端历史。

网页终端默认收起输入助手，需要粘贴长文字时点击“展开输入”；两种模式分别记住收起状态，草稿保留。输入助手和快捷键通过当前终端连接发送，不操作 X 窗口，粘贴与 Enter 继续分开；当前程序未开启多行粘贴保护时拒绝助手的多行粘贴，提示分行处理。Ctrl+Shift+V 明确读取远程剪贴板后粘贴，选择文字后 Ctrl+Shift+C 可复制到本机，浏览器允许时生效。应用输出不能通过 OSC 52 静默改写本机剪贴板。

终端上方提供“上翻 / 下翻 / 回到实时”。普通回看时按钮每次最多移动 3 行，短窗口自动缩小步长；首次读取快照从最近内容开始，不再直接回退两屏。回看时键盘 PageUp / PageDown 仍按整页移动，滚轮和触摸按实际滑动距离滚动。普通文本输出最多保留 2000 行本地历史；tmux 的备用屏幕保留正常语义，上翻按需读取历史快照，不把光标定位、清屏和重绘帧拼成历史。快照沿用实时终端的等宽字体、字号、行高和颜色表，保留颜色、背景色、加粗、斜体、下划线等样式及原始空格与行界，超宽行可横向查看，避免代码、表格再次折行错位。样式通过独立的只读文字视图显示，仅解析 SGR；光标、剪贴板、链接和其他控制序列不执行，文字始终按文本创建。最多 4096 个彩色样式片段，超出时用一个纯文本尾段保留剩余文字并提示简化；64 KiB 快照上限包含样式序列，旧页面继续读取纯文本。

回看时暂停编辑和输入助手，新的输出继续接收并出现“有新输出 · 回到实时”提示，不抢回阅读位置或刷新快照；点击提示或“回到实时”恢复输入，只改变本地显示，不发送按键。提示只保留一个状态，不累计消息队列；重连和浏览器缓存恢复保留阅读位置与提示，切换终端目标后清除。连接重建、WSS/直连换流及浏览器缓存恢复保留已读快照；刷新、切换模式或终端目标时清空，不把输出存进浏览器存储或日志。

“查找/复制”按钮与上翻、下翻、回到实时保持同一行，不再单独占用按钮行；宽屏的状态文字也放在同栏，手机保留一行紧凑提示，按钮仍至少 44×44 像素。电脑、平板和手机的查找面板统一浮在外层页面顶部，覆盖 Logo、连接状态和模式栏；翻页按钮始终露出，历史文本区域的尺寸和位置保持不变。宽屏将搜索和复制控件横向排列，窄屏分为两行，不改变实时终端行列。浮层不设模态遮罩，可继续选择文字及翻页；打开时聚焦面板而不自动聚焦搜索框，点击搜索框才唤起键盘。全屏或可用顶部空间较小时，面板内容可滚动，“收起”固定在可见位置。旋转或调整窗口大小时使用同一面板与搜索状态；关闭、换终端、退出或失去控制权会移回或清理面板。

查找在浏览器内对已加载内容做不区分大小写的字面匹配，保留原有颜色、加粗和排版；支持上一个/下一个匹配、Enter / Shift+Enter，Esc 只收起工具。关键词最多 128 字符、最多定位前 1000 处匹配，超过时显示“1000+”；查找使用一个 150 毫秒计时器，不请求远端历史或发送按键。若尚未打开历史，会冻结当前已接收的本地缓冲，最多 64 KiB，并优先保留正在阅读的区域；全屏程序可能只有当前已显示画面。需要更早内容时仍需明确上翻读取。新输出和重连保留快照、关键词与定位结果。顶部布局仅在同源页面内移动现有 DOM 节点，最多保留一个浮层、一个占位节点和一个布局回调，不通过消息复制终端文本，也不新增持久存储。

“复制选区 / 复制当前快照”只在明确点击时向当前设备剪贴板写入纯文本，保留空格和换行，不包含颜色控制码；一次最多 64 KiB，最多一个待完成的复制请求。“复制当前快照”按钮至少 128×44 像素。浏览器未提供或拒绝自动复制时打开独立的大型只读复制窗口，不受顶部工具栏高度限制。窗口内有“复制到本机”和“全选文字”按钮，也可按 Ctrl/Cmd+C 或长按复制。“复制到本机”在明确点击时尝试对当前只读文字执行浏览器复制命令，必要时尝试 Clipboard API；使用文字所属的同源文档，兼容浮层移到外层页面的情况。窗口内显示复制成功或失败，失败保留已选中文字，复制期间阻止重复点击；不会绕过浏览器剪贴板限制。关闭和 Esc 仅收起复制窗口并清空文字，保留历史查找。复制窗口适配可视区域和全屏，覆盖界面但不改变终端尺寸或历史位置。收起工具、回到实时、失去控制权或离开页面会关闭并清空复制窗口，迟到的复制结果不会重新打开窗口或抢焦点。搜索词和复制内容不写入浏览器存储，也不发送给服务端。

tmux 会合并快速输出，滚到本地顶部后继续上翻会通过当前加密连接按需补取历史快照，最多 64 KiB、每块 8 KiB；平时不持续同步，取消读取或断线后不自动重试。快照包含 tmux 当前保留的普通历史与可见文字，阅读时保持静止。全屏程序使用备用屏幕时可能只有当前画面，界面明确标为“当前画面快照”，其顶部不代表程序会话历史的开头。全屏程序的完整历史由程序自身维护，可明确开启“程序翻页”，让上翻/下翻、滚轮及滑动发送固定 PageUp/PageDown，每 160 毫秒最多一次，不附加 Enter；关闭或“回到实时”只改变本地显示。具体翻页效果取决于当前程序及其[快捷键配置](https://learn.chatgpt.com/docs/config-file/config-reference)。不修改 Codex 配置或重启任务。

新版页面在登录并取得控制权、画面页面初始化后，并发建立 WSS 中转连接和探测局域网 IPv4 / 公网 IPv6 的 WebRTC 加密直连，首屏无需等待完整直连协商。候选经过至少 1.5 秒稳定检查，切换后或直连失效后至少冷却 30 秒再升级，输入、中文组合及确认操作仍会推迟切换。前后端对 WebRTC 的暂时 disconnected 状态保留 1.5 秒宽限，明确失败和通道关闭仍立即处理。桌面重连期间保留一张当前可见区域的图片，最多 4096×4096 像素、8 秒，等新画面绘制后释放；不保存历史画面。

网页和协商仍通过 HTTPS。文字终端复用桌面模式的 ICE、DTLS、候选过滤和固定 UDP 端口范围，使用独立通道。登录、Host、Origin、CSRF、控制权和终端目标校验都通过后才连接终端。新版页面把查看会话与传输路径分离：同一前台会话最多保留一条 WSS 和一条 WebRTC 路径，共用一个 VNC 上游或终端 PTY；切换时不新建查看器、不重新附加 PTY，保留画面、终端解析器、选区及本地历史。待命中转只做认证和心跳，不重复采集画面、订阅终端或传输输出。

输出使用连续字节位置和确认，换路时只补齐尚未收到的输出，重复片段会被丢弃。服务端用单调递增的代次限制输入只能来自当前路径，输入与审批从不自动重发。旧路径失效时，只有服务端确认已接收全部已发送输入才继续同一个会话；输入完整性无法确认时终止该次查看连接、提示结果未知并按原任务重新附加，不补发提示词或 Enter。桌面恢复后仅释放可能卡住的键和鼠标按下状态，不重放按下或剪贴板操作。

会话只放在内存，每个控制者最多一个前台会话、两条已准备路径，另各允许一个 WSS 认证候选和 WebRTC 协商候选；输出最多 1 MiB / 1024 片段，256 KiB 未确认时暂停读取 VNC 上游。终端仍受原有 64 KiB 输出确认窗口约束。单次输入最多组装 128 KiB / 16 片段，3 秒不完整则关闭；浏览器最多保留 64 项输入确认元数据 / 128 KiB，切换期间暂存的输出最多 1.4 MiB / 1024 片段。计划换路前短暂停发上游输出，等解析与输入确认完成再提交，暂停最长 2.5 秒并可自动取消。所有路径消失后，上游最多保留 15 秒；退出、接管、维护、授权失效或面板停止会释放会话与路径。超出恢复窗口时重新附加原任务，独立桌面和 tmux 中的任务继续运行。没有新增持久文件、终端录制或输入重放队列。

网页终端在前台每 3 秒发送独立的只读心跳，2 秒未收到回复便开始重连，不必等待浏览器报告断线。切网或从后台返回时约 250 毫秒后提前检查，离线时等待网络恢复；隐藏页面暂停检查，页面从浏览器缓存恢复时重新附加原终端。连续网络通知不会反复打断新连接，旧回复不能确认新连接有效；草稿、字体及所选终端保留，已发送输入和审批不会补发。

直连失效后立即尝试 WSS，并在中转期间持续探测，按 15、30、60 秒退避；网络变化或返回前台时约 1 秒后提前探测。探测不附加 PTY，通过两次加密往返后等待输入、中文组合输入、按住的键/指针和确认操作结束，再启用直连、附加原任务。服务端也拒绝在旧终端输入尚未完成时启用候选。点击“连接状态”可查看文字终端当前通道、实际 IPv4/IPv6 路径、往返延迟及回退原因。

新建辅助终端在文字模式下只创建独立 shell，不打开 X 窗口。模式选择、字号和折叠偏好保存在原有固定浏览器设置条目中，不保存终端输出。缺失或结束的目标需手动刷新终端列表重新选择。tmux 2.6 的同一窗格会按多个客户端共同约束行列，网页尺寸变化可能同时改变桌面中终端的排版，不改变 Xvfb 分辨率或任务进程。

前端固定为 `@xterm/xterm@6.0.0` 和 `@xterm/addon-fit@0.11.0`，后端使用现有 Python 标准库 PTY；不要求额外 ttyd 服务或公开端口。首次部署新版本先执行 `npm ci`，再更新管理服务和网页面板，保持桌面运行。

## TCP 端口映射

标题栏的“端口映射”可下载 Mac 或 Windows 免安装助手，将电脑的本机回环端口经服务器映射到指定 IP 和 TCP 端口，用原有 SSH、数据库等客户端连接。目标 IP 支持服务器可达的局域网或公网 IPv4 / IPv6，默认 127.0.0.1 表示服务器自身；每次配对固定目标，编辑表单不会修改已有映射。默认 TCP_FORWARD_PORTS=* 允许自定义端口，也可显式配置最多 16 个端口或留空禁用，管理端口始终排除。0.5.0 助手会显示实际目标并校验恢复后的目标 IP。网页生成两分钟有效、仅可使用一次的配对码，助手新建连接优先局域网或公网 IPv6 的 WebRTC 加密直连，失败回退 WSS 并持续探测；已有 TCP 连接保持原通道，网页显示新连接偏好、往返延迟及直连/中转连接数。刷新、关闭网页或其他页面接管均保留映射。助手在检测到短暂断网后可于 30 秒内恢复原映射和本地监听，已有 TCP 关闭后由原客户端重新连接，不重放数据或配对码。有效登录可明确停止映射，停止、退出原登录、授权失效或恢复超时均结束恢复；面板重启后需重新配对。助手和网页提供固定故障原因，最近结束的八条映射仅在内存保留十分钟。

服务器用 Go 1.26.4 运行 npm run build:forward，生成 Mac Apple Silicon/Intel ZIP 和 Windows x64/ARM64 exe。网页在浏览器能确认芯片时推荐对应下载，始终支持手动选择；Mac 需要 macOS 12 或更新版本，解压后运行 Start.command，无需安装运行环境。0.4.0 包含 Mac 支持和既有配对、直连及断网恢复。构建产物保存在被 Git 忽略的 data/forward-client，下载需登录并显示 SHA256。首次打开、使用、边界和验收见 [端口映射助手](docs/forward.md)。

新增“服务器 / Codex 访问本地设备”反向模式：在网页填写设备名称、助手电脑可达的目标 IP/端口及服务器回环端口，生成配对码后，0.6.1 助手会显示目标并要求本地输入 YES。确认后，Codex 可通过服务器的 127.0.0.1 访问该设备的 SSH、Telnet 或其他 TCP 服务；同样支持直连、中转及有限恢复。映射行提供“复制给 Codex”，仅复制入口、固定目标和连接示例，不包含密码，也不执行设备命令。

“本地设备目录”最多保存 16 份名称、协议、地址和监听端口预设；选择后仍需单独配对和本地确认。目录显示助手状态及最近一次实际目标连接结果，未访问过的目标标为尚未验证；修改或删除目录资料不改变已有授权。串口接入不在本版范围内，完整操作与授权边界见[反向设备接入](docs/forward.md#反向设备接入)。

## 多终端

输入助手中的“终端管理”可新建、命名和打开终端。主终端继续使用现有 Codex 进程，默认最多另建 3 个辅助终端；可在 `.env` 设置 `MAX_TERMINALS=8`，支持最多 7 个辅助终端，用来运行测试、开发服务器或查看日志。部署项、默认值和重启范围见[部署配置清单](docs/deployment-config.md)。每个辅助终端是独立 shell，使用同一主机用户和工作目录。新建与打开/切换均先确认；新建不会自动运行 Codex 或提交提示词。

主终端和辅助终端统一通过 `desktop/codex-session` 初始化交互式 Bash，加载 `~/.bashrc` 中的 PS1、别名、函数及环境变量，并保留服务选定的 Node/Codex PATH 优先级、启用多行粘贴保护。两者都不加载登录 shell 的 profile 文件。各终端中临时执行的 `export`、目录切换等仍属于自己的 shell；新终端重新读取共同配置。更新仅影响之后新建的 shell，已运行的终端与任务保持原状，重新打开窗口也不会重载配置；需要更新已有终端时，可在任务结束后退出 shell，再从管理界面新建。

“输入目标”默认跟随桌面当前焦点；选择某个终端后，按键与粘贴会先切换到该终端。服务端检查终端进程标识、窗口焦点及窗口实际连接的 tmux 会话；终端已结束、重建、窗口关闭或布局改变时拒绝旧目标，不自动改发到其他窗口。终端粘贴仍为 Ctrl+Shift+V，Enter 继续单独发送。打开/切换完成会选中该终端；名称可直接保存。

关闭 xterm 窗口只关闭显示，任务留在私有 tmux 中，可从列表重新打开。真正结束辅助终端可在其 shell 中执行 `exit`；终端结束后手动刷新列表，对应名额可重新使用。刷新网页默认恢复为“当前窗口”，不会重建终端、恢复旧输入目标或重发输入。结果未知时先手动刷新列表确认，不自动重试新建。

终端名称保存在私有 tmux 会话的一个固定选项中，最多 24 个字符 / 96 字节，只随当前桌面存活；重启管理服务后可重新读取。独立桌面执行服务持有管理器新开的终端窗口及剪贴板，管理服务重启保留这些进程，详见[生命周期与恢复](docs/reliability.md)。存在辅助终端或其他窗格时，网页禁止通过重启桌面恢复单个会话；显示上限内的分辨率立即应用仍可使用。最大化和恢复窗口针对服务器上的主终端；网页字号属于当前浏览器。

## 桌面设置

新启动的 Xvfb 至少预留 1600×3200 的显示上限，再按已保存配置设置初始尺寸；每轴仍最多 4096。已运行的旧显示如上限为 1600×1600，需要显式重启一次才能启用 3200 高度。上限不足时保留当前实际桌面并提示，不会偷偷缩成 800×1600 或自动重启。固定与动态尺寸切换都不改写已保存的启动配置。

独立虚拟桌面关闭桌面图标，以兼容旧版 XFCE 的短屏布局；应用菜单和任务栏保留。壁纸或任务栏组件退出不会连带结束显示与终端任务。

新建或重新打开的主/辅助图形终端窗口默认最大化，占满虚拟桌面的可用工作区。已有窗口只激活，保留用户手动恢复或调整的布局；浏览器刷新、重连和端口映射不强制更改窗口状态，也不重建 tmux 任务。

画面工具栏的“服务器桌面设置”提供 `1280 × 1280`、`1600 × 1600`、`1600 × 3200`、`1920 × 1600` 预设，也可输入 320–4096 的自定义宽高。这里修改共享服务器；桌面阅读大小用本浏览器缩放，网页终端字号在工具中调整。

- “保存设置”只保存配置，窗口分别显示实际分辨率与待应用值；不会立即调整当前画面或重启桌面。
- 保存后，尺寸在当前显示上限内时显示“立即应用分辨率”。点击后精确应用所填宽高，更新固定桌面目标，保留显示、终端、任务和观看连接，无需识别 Codex 会话或勾选重启确认；不自动应用字号。
- “最大化终端”和“恢复窗口”只调整服务器上本项目的终端窗口。普通浏览器偏好不再提供重新打开全局 xterm 的字号操作。
- 超过显示上限或不支持动态调整时，才显示重启说明和确认框。需明确勾选后再点击重启按钮；直接应用失败不会自动转为重启。重启会终止原有进程及其他桌面应用。只有一个窗格且能准确识别 Codex `resume` 会话 ID 时，才按该 ID 和项目目录重新打开对话；不会自动继续旧任务或重发提示词。空闲 shell 则打开新的 shell。无法识别的前台任务或多个窗格会阻止重启。
- 应用时若网络中断或结果未确认，先刷新设置检查实际尺寸，不会自动重试应用或重启。

设置保存在被 Git 忽略的 `data/desktop-settings.json`（0600，最多 1 KiB，固定临时文件原子替换）。管理服务独立于面板和桌面，使用私有 Unix socket，仅提供固定动作。操作状态只保留一项，不排队、不自动重试；请求结果不明确时先手动刷新查看。

升级已有部署时运行 `npm run native:install`，再启动管理服务并只重启面板，当前桌面可继续运行：

```bash
systemctl --user start codex-cloud-manager.service
systemctl --user restart codex-cloud-panel.service
```

## 连接状态

顶部“连接状态”分别显示网页服务、桌面服务与画面连接情况，并显示实际分辨率、直连实际选中的 IPv4/IPv6 与 UDP 路径、两端地址及往返延迟，以及 Tunnel 活动连接数。浏览器隐藏的本地地址明确标为隐藏，不从候选列表猜测实际路径。Tunnel 统计在窗口打开时每 5 秒更新，可手动刷新；无法读取诊断时显示未知，不把它当作桌面停止。

画面断开后会显示“画面重连中”，健康轮询不会将它覆盖为在线。网络不可用、画面未连接或等待接管时，输入按键暂时禁用；草稿保留，恢复后不自动提交。工作台登录过期需要重新登录，外层 Access 验证过期则显示手动刷新入口。

cloudflared 的诊断接口固定监听 `127.0.0.1:36903`，可用 `TUNNEL_METRICS_PORT` 调整。只读汇总经工作台登录保护提供，不公开原始诊断接口；升级到此版本或修改该端口时，需重启面板和 Tunnel，桌面服务独立运行。

## 手机输入

- 先点击桌面里要输入的位置，再使用输入助手粘贴中文或多行文字。
- “终端”模式使用 Ctrl+Shift+V，“其他应用”模式使用 Ctrl+V。
- 粘贴不附带 Enter，确认后单独提交。网络故障后不会自动重试写操作。
- 新标签页会接管桌面，旧页等待手动接管；不会互相不断重连。
- 手机端缩放固定尺寸的桌面，横屏或全屏可以获得更大的操作区域。
- 输入助手保留“正在发送、成功、未发送、结果未知”的状态。结果未知时先查看桌面确认，避免重复执行；网络恢复、刷新或重新接管不会重发输入。
- 一次只执行一项输入或桌面操作，繁忙时直接拒绝新输入。接管、退出或登录过期后，尚未转发的旧页面请求会被拒绝，即使随后又在原页面接管也不会补发。
- 重启桌面和更新字号期间暂停输入并关闭旧画面连接，完成后自动恢复画面；这不会自动提交指令。关闭设置窗口也不会解除操作期间的暂停。

## 取回远程文字

输入助手里的“取回文字”支持从远程桌面复制文字到手机或本机浏览器：

1. 在远程应用执行复制，或在终端用鼠标选中文字。
2. 点击“取回文字”，选择“远程剪贴板”或“选中文字”，再点击“读取远程文字”。两个来源分别读取，不自动互相替代。
3. 确认预览后点击“复制到本机”。浏览器未允许剪贴板写入时，可点击“选择文字”，再长按或使用系统复制操作。

每次最多读取 32 KiB UTF-8 纯文本，保留中文、换行和空白；不支持的内容、超限或超时会提示手动重试。读取不发送按键，不把内容粘贴到输入助手或终端。内容只在当前预览窗口暂存，不进入浏览器存储或服务日志；关闭、切换来源、失去控制权、断网或画面重连会清空预览。重新连接和刷新不会自动读取。

## 统一门户与多服务器

可将 `codex.x-wrt.dev` 部署为独立 Cloudflare Workers 门户，home、work 和后续节点分别使用自己的域名与 Tunnel。门户动态管理节点、生成长期复用授权码；在节点的“工具 → 门户接入”粘贴授权码即可注册。删除授权码只禁止新注册，已接入节点保留身份。节点不依赖门户在线，切换保留任务、登录和端口映射。

当前入口：[统一门户](https://codex.x-wrt.dev)、[home 工作台](https://home-codex.x-wrt.dev)。work 保留待部署入口。门户密码保存在部署主机的 `secrets/portal_password`；home 使用原工作台账号和密码。

门户目录保存在 SQLite Durable Object，各节点的桌面、文件和映射仍留在各自机器。初始化、发布、界面接入、资源边界与验证说明见[统一门户](docs/portal.md)。

## Cloudflare 外网访问

画面、原生键鼠及输入助手优先尝试 IPv4 局域网或公网 IPv6 的 WebRTC 加密直连，双方主动 ICE 探测可尝试穿过允许出站回复的防火墙。浏览器默认使用 Cloudflare STUN 发现地址，最多等待 1.5 秒，不经 STUN 转发桌面；可配置或关闭。前台直连每 3 秒进行独立心跳，2 秒无回复就开始连接中转；网络变化后约 250 毫秒提前检查。中转期间持续探测，确认直连可用并等待输入空闲后自动切换，保留草稿、显示设置与当前滚动位置；无需另备本地证书或修改 DNS。网页、协商、桌面管理和文件仍使用 HTTPS，当前未部署 TURN 或 ICE-TCP；配置、UDP 端口范围与限制见[双栈直连](docs/lan.md)。

统一会话模式下，直连切换由候选通道与服务器交接，不等待旧中转确认。已建立直连的状态查询、终端目录和网页终端标签切换可继续通过该直连完成；中转模式的终端标签切换也复用现有 WSS，无需重新加载页面或建立连接。切换重新核对目标身份，原任务和分终端草稿保留。首次页面、登录、无现成直连时的信令，以及文件和管理操作仍需 HTTPS，详见[直连状态与切换](docs/lan.md#已直连时的状态与终端切换)和[中转终端切换](docs/lan.md#中转模式下的终端切换)。

详见 [Cloudflare 配置](docs/cloudflare.md)。安装固定版本的用户级 cloudflared：

```bash
npm run native:cloudflared
```

它下载官方 `2026.10.0` 程序并校验 SHA-256，保存到 `data/host-tools/usr/bin`。有 API Token 时可直接创建专用 Tunnel 和域名：

```bash
npm run native:publish -- --domain home-codex.x-wrt.dev --zone x-wrt.dev --api-token-file /tmp/cf_token
```

脚本需要账户 Tunnel 编辑、目标区域 Zone 读取和 DNS 编辑权限，不覆盖无关记录。也可手动配置 Tunnel、HTTPS 域名并把 Tunnel 运行 token 写入 `secrets/tunnel_token`。随后启动：

```bash
systemctl --user restart codex-cloud-panel.service
npm run native:tunnel
```

Tunnel 的上游是 **`http://127.0.0.1:36080`**。不需要开放路由器端口，也不把 VNC 或内部接口直接发布出去。

本机系统 DNS 无法解析 Tunnel 的 SRV 记录时，可只给 Tunnel 配置独立 DNS，配置及 IPv4/IPv6 选项见 [连接排查](docs/cloudflare.md#dns-与-ipv4ipv6)。Tunnel 异常退出后每 10 秒自动重试；桌面不会因此重启。

本机 Tunnel 使用 `TUNNEL_EDGE_IP_VERSION=auto`，已验证解析结果中 IPv6 排在前面，四条边缘连接均通过 IPv6 建立，并保留 IPv4 故障回退。`auto` 随主机解析顺序选择主地址族，部署到其他主机时需核对实际连接；`6` 则表示仅使用 IPv6，详见 [地址族配置](docs/cloudflare.md#dns-与-ipv4ipv6)。

公网入口使用工作台自身的账号密码登录，HTTPS Cookie 带 Secure。Cloudflare Access 是可选的额外身份验证层，配置方式见部署文档。

后续设计见 [TURN 中继与自有 VPS 公网入口规划](docs/turn-selfhost-plan.md)：先为现有部署增加 TURN，再支持 Caddy/frp/coturn 自建入口。该文档为待实施方案，当前部署参数与功能不变。

## 生命周期与运维

| 操作 | 桌面与 tmux 进程 | 文件与 Codex 登录 |
| --- | --- | --- |
| 浏览器关闭、断网或面板重启 | 继续 | 保留 |
| 关闭 xterm 窗口 | tmux 内任务继续 | 保留 |
| 重启/停止桌面服务、主机重启 | 终止；不会自动重放任务 | 本机文件保留 |

```bash
npm run native:status
journalctl --user -u codex-cloud-desktop -u codex-cloud-panel -n 100 --no-pager
# 查看设置操作服务
journalctl --user -u codex-cloud-manager -n 100 --no-pager
# 查看 Tunnel
systemctl --user status codex-cloud-tunnel.service
# 停止全部服务，会终止桌面任务
npm run native:stop
```

桌面服务遇到关键进程退出会整体停止并报告错误，不自动反复重建桌面。恢复前先检查日志，再运行 `npm run native:start`。

```bash
npm run check
npm test
npm run test:desktop
CHROME_PATH=/usr/bin/google-chrome npm run test:browser
# Chromium / Firefox / WebKit 的电脑、手机和平板兼容性流程
npm run test:compat
# 单独的真实 X11 控件验证：使用临时显示、HOME、tmux，不启动 Codex
npm run test:display
# 独立 Xvfb/x11vnc/完整 XFCE/xterm 的无重启尺寸适配验收
npm run test:viewport
# 管理器重启后保留真实隔离窗口、tmux 和剪贴板
npm run test:lifecycle
# 可用的 systemd 用户管理器中验证临时面板的有限恢复
CHROME_PATH=/usr/bin/google-chrome npm run test:recovery
```

前端自动化测试连接模拟 RFB 上游，但实际运行 noVNC 客户端与 Unix socket 网关；重启与恢复命令也使用模拟执行器。`test:display` 使用真实 Xvfb、xfwm4、xterm 和 tmux 验证窗口动作与字号替换，不重启正在使用的桌面。`npm run demo` 在 `127.0.0.1:36081` 提供明确标注的模拟桌面，不连接 Codex。

多引擎环境准备、覆盖范围和真机状态见[兼容性验收](docs/compatibility.md)，本轮问题、修复及待跟进项见[代码审核记录](docs/code-review.md)。

GitHub Actions 自动检查后端、三种浏览器引擎及真实隔离桌面；完整浏览器回归支持两个独立 worker。版本、触发方式、产物保留和本地命令见[自动检查](docs/ci.md)。

桌面执行服务持有终端窗口和剪贴板，管理器更新保留原任务。面板异常退出后有限重启，并在无人占用时恢复原页面；输入结果未知时仍不重发。服务归属、恢复上限和更新步骤见[生命周期与恢复](docs/reliability.md)。

真实桌面已经启动且 tmux 中为**空闲 bash**时，可运行：

```bash
CHROME_PATH=/usr/bin/google-chrome npm run test:native
```

实现边界见 [架构说明](docs/architecture.md)。参考 WechatOnCloud 的浏览器常驻桌面与手机输入设计，以及 agent-relay 的跨设备、断线不重发需求。浏览器客户端使用 [noVNC](https://github.com/novnc/noVNC)，本项目新增代码采用 MIT 许可，依赖分别遵循自身许可。
